# 框架开发遵循准则（xadmin）

> 用途：服务端 / 前端开发新模块、新页面、新接口时的统一约定与检查清单。
> 开发时先读本节；拿不准的写法参照参照页实现：
> - 前端参照页：`views/demo/book`（官方 demo）与 `views/system` 下既有页面（role / dept / notice / online / config-user）
> - 服务端参照页：`system/views/task.py`、`system/views/admin/dept.py`
>
> 本准则与项目记忆 `project_memory.md` 互为补充；准则记"怎么写"，记忆记"踩过的坑"。

---

## 0. 技术栈总览

| 端 | 技术栈 | 入口 |
|---|---|---|
| 服务端 `xadmin-server` | Django + DRF + django_filters + django_celery_beat + drf-spectacular（Python 3.13） | `sh xadmin.sh start`（docker 一键启动） |
| 客户端 `xadmin-client` | Vue3 + TS + Vite + Element Plus + plus-pro-components + pure-admin(RePlusPage) + vue-i18n + Tailwind | `pnpm dev` |

- 通用框架代码在 `common/core`（modelset / serializers / fields / filter / permission / response / routers / pagination）与 `common/drf`（metadata）。
- 业务 app：`system`（views/admin、views/auth、serializers、models、services、urls）。

## 1. 服务端开发准则

### 1.1 响应约定（不要破坏）

所有接口统一经 `common/core/response.py::ApiResponse` 返回，结构固定：

```json
{ "code": 1000, "detail": "...", "requestId": "...", "timestamp": "...", "data": {...} }
```

- `code == 1000` 为成功；失败时 `detail` 给出原因。
- 列表接口 data 为 `{ "results": [...], "total": n }`（分页）；元数据接口 data 为数组。
- 校验失败的错误经 `common.core.exception.common_exception_handler` 统一封装，前端表单内联展示。

### 1.2 Model 层

- 主键统一用 `common.core.models.DbUuidModel`（UUID pk）或 `DbCharModel`。
- 需要文件清理（自身 File/ImageField 或关联 system.UploadFile）混入 `AutoCleanFileMixin`。
- 审计字段（creator / dept_belong / created_time / updated_time 等）由基类提供，业务模型直接继承。
- 字段 `verbose_name`、`help_text` 必须走 `gettext_lazy`（`_()`），这是绝大多数服务端文案的唯一定义处。

### 1.3 Serializer 层（`common/core/serializers.BaseModelSerializer`）

- 继承 `BaseModelSerializer`；`Meta.fields = "__all__"` + `table_fields`（控制前端表格列与顺序，index+1 即 `table_show`）。
- `id` 自动转 `pk`，无需手动声明。
- 关联字段展示增强：用 `DisplayRelatedField`（`common/core/fields.BasePrimaryKeyRelatedField` 子类）输出 `{pk, label}`，避免前端显示裸主键；自定义 label 用 `label_builder`。
- 选择型字段：优先 `LabeledChoiceField`（序列化 `{value,label}`，前端 `labeled_choice` 下拉）；纯值下拉用 `serializers.ChoiceField`（前端 `choice` 下拉）。
- **下拉数据源 = 后端 choices**：前端表单/列表的下拉选项全部由 backsearch-columns 下发的 `choices` 驱动，不要在前端硬编码选项；选项有动态来源时（如 celery 队列、枚举）在序列化器层面从配置推导。
- 字段权限：序列化器按当前请求用户的字段权限自动裁剪字段；敏感字段注意 `write_only` / `read_only`。
- 表单联动/自定义渲染：`Meta.tabs`（TabsColumn）分栏；规则校验在 `validate()`；JSON 字符串校验用项目既有 `_validate_json_string` 模式。

### 1.4 ViewSet 层（`common.core.modelset`）

- 视图继承预组合 ViewSet：`BaseModelSet`（完整 CRUD）、`ListDeleteModelSet`、`OnlyListModelSet`、`DetailUpdateModelSet`、`NoDetailModelSet`。
- Filter：继承 `django_filters.rest_framework.FilterSet`，**声明的过滤器必须同步列入 `Meta.fields`**，否则 search-fields 元数据不产出、前端搜不到。
- 定制 action：`@action(methods=[...], detail=True/False, url_path='xxx')` + `@extend_schema`（drf-spectacular）；返回统一 `ApiResponse(data=...)`。
- 批量删除/排序/导出/回收站等能力已由组合 action 提供，无需重写。
- 数据权限：非超管默认按 `DataPermission` 规则过滤（未配置规则默认拒绝），新模型上数据权限前无需额外处理。
- 类 docstring 首行会成为操作日志 `module`（varchar(64) 截断），写简洁一句话即可。

### 1.5 路由（`system/urls.py`）

- `SimpleRouter` 注册普通资源；`NoDetailRouter` 注册用户中心等无 detail 的资源；无鉴权/会话类走 `no_auth_url` / `auth_url`。
- basename 与前端组件 name、权限码关联，保持稳定。URL 前缀用 `tasks/xxx` 这类 kebab 形式。

### 1.6 权限

- 接口鉴权由 `permission_classes`（默认 IsAuthenticated）与菜单-URL 匹配共同完成。
- 前端按钮/操作权限码形如 `run:SystemTask`（action:组件名），**必须在 `loadjson/menu.json` 中登记同名的 permission 类型菜单**，且后端 action 存在，前端 `getDefaultAuths(..., ['run'])` 才会下发。
- 新增菜单/权限后需重新导入 loadjson（`load_init_json`）才生效。
- **新增/修改 API 端点后跑一次体检**：`python manage.py sync_menu_permissions --dry-run`（只报告）→
  去掉 `--dry-run` 执行修复（幂等：补齐缺失权限点 + 校正模型绑定 + 重建字段树）；
  与种子保持一致时加 `--update-seed`（回写 `loadjson/{menu,menumeta,modellabelfield}.json`）。
  设计说明见 [architecture/菜单权限与字段同步补全方案-2026.09.md](architecture/菜单权限与字段同步补全方案-2026.09.md)。
- 绑定口径：CRUD（list/create/retrieve/partialUpdate）需绑定关联模型（否则角色页无法配置字段白名单）；
  导入导出链（含 `-async/-validate/-headers`）**必须为空绑定**（字段权限按运行时规则回退到 list/create 菜单）。

### 1.7 国际化（服务端）

- 文案一律 `gettext_lazy`；新增可翻译字符串后，需在 `locale/zh/LC_MESSAGES/django.po` 补条目并用 `msgfmt`/`compilemessages` 编译 `.mo`。
- 常见坑：po 中 msgid 含引号/折行易写坏（报 "end-of-line within string"）；无需运行时 churn 时不要跑 `makemessages`（会重排 location 注释）。

### 1.8 Celery 定时任务

- 任务注册走 `@task` / `common/celery` 自动发现；创建 `PeriodicTask` 记录后由 beat 调度。
- 队列来源以 `settings.CELERY_TASK_ROUTES` + `CELERY_TASK_DEFAULT_QUEUE` 为单一事实源，新队列只需改 settings，下拉自动跟随。
- 立即执行/批量执行已实现（periodic `run` / `batch-run` action），执行历史经 `TaskExecution` + WebSocket 增量推送日志（`/ws/tasks/log/<pk>`）。

### 1.9 数据字典（枚举选项可运营化）

状态/类型等枚举的文案与颜色需要管理员在线维护（不发版改文案）时，接入数据字典；纯代码内部流转、从不展示的枚举仍用 TextChoices。

**服务端接入**

- 序列化器字段：`DictChoiceField(dict_code="xxx", fallback_choices=Model.Choices.choices, value_cast=int, merge_fallback=True)`（`system/serializers/fields.py`）。
  - `fallback_choices` 必传：字典未配置/项被清空时回退模型枚举，业务不中断；
  - 整型枚举字段配 `value_cast=int`；
  - 状态等展示型字段用 `merge_fallback=True`（字典项优先、枚举补缺，管理员只配部分项时其余枚举标签不缺）；写入路径受字典约束时用默认 False（字典项完全替换）。
- 被代码按 code 引用的字典类型必须在 `loadjson/datadict.json` 登记（类型行 `is_locked=true`，接口层禁删、锁 code/parent），默认字典项随种子下发（文案/颜色与前端 i18n、Element 色板对齐）。
- 消费端读项：`system.utils.dict.get_dict_items(code)`（300s 缓存 + 信号失效）；`items` 接口在 `PERMISSION_WHITE_URL` 白名单（GET），登录用户可直接消费，无需数据字典页权限。
- 直连改库/批量 `update()` 绕过信号的场景，须显式 `invalid_dict_cache(code)`（参照 `move` action 与 `load_init_json` 尾部）。

**前端接入**

- RePlusPage 页面零成本：choices 由后端元数据下发，行数据为 `{value,label,color?}`，带 color 自动渲染彩色 tag（labeled_choice 渲染器），表单/搜索下拉自动跟随字典。
- 自定义页面/非元数据场景：`src/utils/dict.ts` 的 `useDict(code)`（进程内 TTL 缓存 + 并发去重 + loading/refresh）/ `getDictItems(code)`。
- 状态列渲染约定：`h(ElTag, statusTagProps(row.status), () => row.status?.label ?? t("页面命名空间.status" + value))`——字典色优先彩色 tag，无色回退 `STATUS_TAG_TYPE` 映射，文案字典 label 优先回退页面 i18n key（下载中心导出/导入、定时任务执行历史三处已按此接入，新增状态列照抄）。

## 2. 前端开发准则

### 2.1 页面结构（RePlusPage 模式）

```
views/system/xxx/
├── index.vue          # 薄壳：defineOptions({name}) + hook 展开 + <RePlusPage/>
└── utils/
    └── hook.ts(x)     # 页面逻辑：api/auth/列格式/按钮/弹窗全部收敛于此
```

- `index.vue` 只做三件事：`defineOptions({ name: "XxxYyy" })`（**name 必须定义**，用于菜单匹配与权限码后缀）、解构 hook 返回值、渲染 `<RePlusPage>`。
- **API 模块放 `src/api/system/*.ts`，不要写在页面目录里**（demo 的 `utils/api.ts` 仅为教学示例，不照抄该点）。
- 自定义弹窗（非 CRUD 弹层）在 hook 内用 `addDialog`（`@/components/ReDialog`）定义调用，不在模板挂组件。内容组件通过 `props`（addDialog 的 `props` v-bind）收参数，自己发起副作用（如 WebSocket），关闭用 `emit('close')`（ReDialog 已内建接线）。

```ts
// hook.ts 标准骨架
export function useXxx(tableRef: Ref) {
  const api = reactive(xxxApi);                                   // 1. api
  const auth = reactive({ ...getDefaultAuths(getCurrentInstance(), ["custom"]) }); // 2. 权限
  const { t } = useI18n();                                        // 3. i18n
  // 4. operationButtonsProps / tableBarButtonsProps / addOrEditOptions / *ColumnsFormat
  // 5. 返回
}
```

### 2.2 RePlusPage 关键 props（`src/components/RePlusPage`）

| prop | 作用 |
|---|---|
| `api` / `auth` | 页面数据接口与权限集，由 hook 提供 |
| `locale-name` | 国际化命名空间（对应 locales 的 key 前缀） |
| `listColumnsFormat` | 列表列自定义（`forEach + switch (column._column?.key)`） |
| `searchColumnsFormat` / `baseColumnsFormat` / `detailColumnsFormat` | 搜索 / 新增编辑 / 详情列自定义 |
| `addOrEditOptions` | 表单整体定制（columns 函数、tabsProps、dialogDrawerOptions） |
| `operationButtonsProps` | 行内按钮组 |
| `tableBarButtonsProps` | 工具栏按钮组 |
| `recycleBin` | 软删除模型回收站入口 |

### 2.3 按钮与交互约定

- 行内/工具栏按钮统一 `shallowRef<OperationProps>`，`buttons: [{ text, code, confirm, props, onClick, show }]`。
- **显隐 = 索引位**：`show: auth.xxx && N`（N 为排序索引；默认按钮占 -30/-20/-10，自定义按钮用正数），自定义按钮要平铺显示时调大 `showNumber`。
- `confirm.title` 支持函数：`title: row => t('xxx.confirm', { name: row.name })`（行内动态文案）。
- 请求封装统一 `handleOperation({ t, apiReq, success, requestEnd })`（自动分发成功/失败消息）；loading 用回调参数 `loading.value`。
- 图标用 `useRenderIcon(Icon)` + `~icons/ep/*` / `~icons/ri/*`（自动按需引入）。

### 2.4 API 模块写法（`src/api/system/*.ts`）

```ts
import { BaseApi } from "@/api/base";
import type { BaseResult, DetailResult, ListResult, DataListResult } from "@/api/types";

class XxxApi extends BaseApi {
  customAction = (pk: number | string) => {
    return this.request<BaseResult>("post", {}, {}, `${this.baseApi}/${pk}/custom`);
  };
}
export const xxxApi = new XxxApi("/api/system/xxx");
```

- 返回类型按语义选择：写操作 `BaseResult`，带 data 的 `DetailResult`，分页列表 `ListResult<T>`，裸数组 `DataListResult<T>`。
- 简单无定制 CRUD 直接用 `new BaseApi(url)` 即可。

### 2.5 国际化（前端）

- 唯一文件：`locales/zh-CN.yaml` + `locales/en.yaml`（**必须成对补 key**，缺 key 会回退英文）。
- 页面/字段文案命名空间对应 `locale-name`：如 `systemTask.name`、`systemTask.runConfirm`。
- 列 label 解析链路（`formatPublicLabels`）：前端 `{localeName}.{key}` 优先 → 通用白名单（`commonLabels.*`）→ 回退后端 gettext label。因此**后端字段名在前端补 key 即可覆盖服务端文案**。
- 菜单标题用 `menus.xxx` key（meta.title 存 key 而非硬编码中文）。
- **yaml 不允许重复 key**（vite i18n 报 "Map keys must be unique" 白屏），新增时先查重。
- 弹窗标题/按钮/空态等所有可见文案必须走 `t()`。

### 2.6 新增页面完整清单（前端 + 后端联动）

1. 后端：Model → Serializer（含 `table_fields`、下拉字段 choices）→ FilterSet（声明式+Meta.fields）→ ViewSet → `system/urls.py` 注册。
2. 后端：Service 端 i18n po 补条目并编译；loadjson 菜单（menu.json 页面/权限码 + menumeta.json 标题 key）登记。
3. 前端：`src/api/system/xxx.ts` → `views/system/xxx/index.vue` + `utils/hook.ts(x)`。
4. 前端：locales 两文件补 `xxx.*` 与 `menus.xxx` key。
5. 验证：后端 `manage.py check`、相关单测；前端 `pnpm typecheck` + `eslint` + `prettier` + `build`。
6. 回归：`sh xadmin.sh start` 后走一遍页面（列表 / 新增 / 编辑 / 删除 / 自定义按钮 / 弹窗）。

## 3. 常见坑（速查）

- 前端 locales yaml 重复 key / po 引号折行写坏 → 编译期报错即白屏，先自查再提交。
- 同一文件多处编辑必须串行（last-write-wins 覆盖）。
- 恢复被删代码前先确认引用仍在（曾因删 computed 被引用导致整站挂）。
- 数据权限未配置时非超管默认拒绝（`Q(id=0)`），联调注意用超管。
- OperationLog.module 为 varchar(64)，docstring 首行即可。
- E2E 断言不要依赖「目标行恰好在列表第一页」：RePlusPage 默认 `ordering=-created_time` + `pageSize=15`，全量跑时早期种子账号会被后建数据挤出首页（只在后半程浏览器暴露，易被误判为 flaky）。要定位具体行先用 `helpers.openList(page, path, { placeholder, value })` 在搜索区过滤（`?query=` 预置只回填搜索框、首屏请求不带条件，不可用）；只验证「列表能加载」就断言「已渲染出数据行 + 分页可见」。
- 新增 list ViewSet 必须给默认 `ordering`（否则分页抛 `UnorderedObjectListWarning`，且列表顺序不稳定）。
