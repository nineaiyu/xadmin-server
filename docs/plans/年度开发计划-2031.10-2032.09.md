## 一、年度定位

第五年度完成「两修三交付一恢复」（DB connect_timeout / venv 修复；SLO 工具 / 升级指南 / 演练规范 ×2；
DNS 事故恢复）。本年度延续**持续运营**，三个抓手延续：

1. **清账**（T3/T5）：推送合 main 后执行 CSP 页面层切强制与视觉基线/Renovate 验收；
2. **SLO 校准执行**（T6）：数据积累成熟即按工具化流程落地并回填 metrics；
3. **演练新场景轮换**（累计 6 轮）：继续覆盖未触达面（iptables 丢包 / 磁盘压力等）。

## 六、验证方式（门禁矩阵）

| 层级 | 每窗口出口门禁 |
|------|---------------|
| 后端 | `ruff check/format` + `pytest -n auto` 全量 + 覆盖率 ≥78% + 新增守护测试 |
| 前端 | typecheck + typecheck:strict + eslint + prettier + stylelint + vitest + check:contract + **check:bundle-size（基线 522 KB）** |
| E2E | 新功能主链路双浏览器 + `test:e2e:fresh`（改后端必跑）+ 视觉回归（基线入库后常态） |
| 数据/部署 | 新权限点重灌幂等；迁移全新库重建（测试库持续覆盖）；升级路径按 installer 预检/回滚口径 |
| 性能/稳定 | k6 场景集基线对比；SLO 看板（校准后按新阈值） |
| 治理 | 新功能 100% 带测试；先 ADR 后动手；候选池先对账再排期 |

## 七、风险与对策

| # | 风险 | 对策 |
|---|------|------|
| R1 | 单人维护总线因子 | 按需插槽制；文档即产品 |
| R2 | 依赖断代（Django 线 / TS7 / 前端 major） | ADR-004 / ADR-014 触发条件 + 回滚预案 |
| R3 | 运营节奏滑坡 | 演练/审计/依赖窗口进年度台账，季度检查 |
| R4 | 挂起项长期悬空 | 清账抓手（T3/T5）+ SLO 校准（T6）显式化，季度核对 |
| R5 | 环境变化引入新缺陷 | 演练新场景轮换（累计 6 轮；继续覆盖丢包/磁盘压力等） |
| R6 | 演练侧环境事故（如 DNS 损坏） | 规范前置：网络层操作仅限可重建环境 + 恢复预案（第五年度教训） |

## 附录 A：明确不做（红线延续）

- 多租户（[ADR-031](../adr/ADR-031-multi-tenant-evaluation.md) 重开条件未命中）；
- 业务模块军备（商城 / CRM / WMS 等）；
- 重依赖（类 Excel 报表设计器、vxe-table、schema-form 等）；
- 适老主题、全面移动端适配（维持既有结论）。

## 附录 B：本计划与第五年度的衔接

- T10 承接第五年度演练登记（`connect_timeout` TCP 场景未覆盖边界）；
- T6 承接第五年度工具化交付（`scripts/slo_snapshot.py`）；
- T3/T5 承接 release-checklist 挂起项（待推送解锁）；
- 演练累计 6 轮（beat / worker / Redis / 归档 / DB / 备份 / 网络分区），本年度继续轮换。
