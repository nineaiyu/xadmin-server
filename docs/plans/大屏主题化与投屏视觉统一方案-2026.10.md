# 大屏主题化与投屏视觉统一方案（2026.10）

> 状态：待评审　|　影响面：`xadmin-server`（dataset 模型 / 序列化器 / 迁移 / i18n）+ `xadmin-client`（大屏设计器 / 投屏页 / ChartCard / 主题令牌 / 词条 / E2E 基线）
> 目标：大屏支持「深色（缺省）/ 浅色 / 跟随站点」三种主题与独立主题色，消除投屏页「深色画布里嵌白色图表」的割裂
> 预估：后端 1~1.5 人日 + 前端 2.5~3.5 人日（含测试与基线重录）
>
> 关联：本轮已先行落地「恒深色投屏下的图表深色渲染」修复（`ChartCard` 新增 `forceDark` 配色方案
> `chartColorScheme`），本方案在其上把「恒深色」升级为「可配置主题」，`forceDark` 语义从默认行为
> 收敛为深色主题的实现手段之一。

## 1. 背景

### 1.1 用户可见的问题

1. **主题不统一**：投屏页（`/analysis/screen/display`）与画布设计器（`/analysis/screen/designer`）
   是「刻意恒深色」设计（`--screen-*` 令牌固定深色值，不随站点主题），站点为白色主题时投屏仍是黑底；
2. **不能配置**：大屏（`Screen`）没有任何主题字段，设计器也没有主题入口——每块大屏无法按挂屏环境
   （会议室大屏 / 明亮车间 / 夜间值班室）选择外观；
3. **图表割裂（已修复）**：投屏复用 `ChartCard` 按**站点主题**渲染图表且内层铺 `--el-bg-color-overlay`
   底色，亮色站点下投屏页出现「深色卡片里嵌白底黑字图表」。2026-10-20 已修：投屏场景全部传
   `force-dark`，图表与内层底色强制深色。

### 1.2 现状设计基线（为什么当初是恒深色）

- `src/style/tokens/semantic.scss` 的 `--screen-*` 令牌块注释明确「恒深色，不随站点主题」，
  设计器与投屏共用同一套深色视觉保证「所见即所得」；
- 《体验升级与工程优化计划-2026.09》（archive）V4 批次按「恒深色投屏」重构了投屏视觉
  （氛围底 + 玻璃卡片），同批把图表内层做成了「站点主题底色画框」——这个画框是本轮割裂的直接来源。

### 1.3 另一个已证实的真实缺陷（顺带修复，纳入本方案）

主题初始化 `dataThemeChange()` 写在管理布局 `src/layout/index.vue` 的 `onBeforeMount`。
大屏投屏 / 设计器是 `showLink: false` 的**菜单外全屏路由**（`src/views/analysis/screen/routes.ts`，
无 Layout），直接刷新或新标签页打开时布局不挂载，`data-theme` / `html.dark` / `--primary` 都不会应用：

- `data-theme` 属性缺失 → 菜单调色板类 `data-theme` 皮肤全回退缺省；
- 站点暗色模式失效（`html.dark` 不加）；
- 自定义主色 `--primary` 缺失 → 图表主色回退内置蓝。

从列表页点「投屏」按钮是 `router.push`（布局已挂载），变量已在，因此缺陷只在「直开全屏页」时出现，
且表现为「投屏页自己正常（恒深色写死）、但返回管理页后主题错乱」或「直开时取色器色板错」。
方案 C（恒深色）场景下它影响有限；主题化后（跟随站点）投屏页**自己就要读主题**，此缺陷必须先修。

## 2. 目标与非目标

### 2.1 目标

1. `Screen` 新增 `theme`（dark / light / auto，缺省 `dark` 保持存量观感）与 `theme_color`
   （可空，覆盖该大屏的主色，空 = 跟随站点主色）两个字段，随大屏 CRUD 全链路可编辑；
2. 设计器工具条新增主题选择（深色 / 浅色 / 跟随站点）与主题色（预设色卡 + 清除），所见即所得；
3. 投屏页按 `theme` 渲染：深色 = 现状恒深色；浅色 = 浅色画布 + 深色前景；auto = 跟随站点明暗；
4. 投屏 / 设计器直开（无 Layout）时主题正确初始化（修 §1.3 缺陷）；
5. 图表随大屏主题渲染：深色走 `chartColorScheme(true)`（现状 `forceDark` 链路），浅色走
   `chartColorScheme(false)` 并去掉 `force-dark`；
6. 存量行为零变化：不设置主题的大屏（缺省 `dark`）投屏观感与修复前一致。

### 2.2 非目标

- 不改站点级主题体系（设置面板的明暗 / 主题色 / 预设仍是站点维度）；
- 不做自由画布窗格级主题（窗格没有独立配色，主题是大屏整体属性）；
- 不支持自定义渐变 / 背景图片等复杂画布皮肤（只做「明暗 + 主色」两维）；
- 大屏模板 / 剪贴板 / 团队模板的载荷结构不动（主题在 `Screen` 上，不在画布载荷里）；
- 不改 WS 协议帧结构（`ws-frame.schema.json` 的 screen 帧）——主题是静态属性随详情下发，
  远程控制不推主题变更。

## 4. 方案选型

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 投屏跟随站点明暗 | `--screen-*` 改读 EP 变量，无字段 | 零后端改动 | 挂屏环境与操作者主题强耦合（操作者切浅色，墙上大屏跟着变白）；设计器与投屏观感随人而变 | 不采用 |
| B. 大屏级主题字段 | `Screen.theme` + `theme_color`，设计器配置、投屏按配置渲染 | 每块屏按环境定外观；存量缺省 dark 零影响；与可见性一样是「大屏自身的属性」 | 后端字段 + 迁移 + 两端表单 | **采用** |
| C. 维持恒深色 | 只修图表配色与全屏路由主题初始化 | 最小改动 | 不满足「可配置」诉求 | 已部分落地，作为 B 的深色分支 |

方案 B 内的「主题色」维度：**大屏独立主题色**允许同一块深色屏按企业 VI 换强调色（标题色条 /
图表主色 / 光晕色随动），存 `null` 时读站点 `--primary`，实现上是「把 `--primary` 在投屏根节点
内联覆写」——与站点设置面板 `setEpThemeColor` 同一机制（`hexToHslTriplet`），零新协议。

## 5. 总体设计

### 5.1 数据模型（后端）

`Screen` 新增两个字段（置于 `visibility` 之后）：

```python
class ScreenTheme(models.TextChoices):
    DARK = "dark", _("Dark")
    LIGHT = "light", _("Light")
    AUTO = "auto", _("Follow site")


theme = models.CharField(
    _("Theme"),
    max_length=8,
    choices=ScreenTheme.choices,
    default=ScreenTheme.DARK,
    help_text=_("Display theme: dark / light / follow site"),
)
#: 大屏主题色（hex，如 #006be6）：空 = 跟随站点主色
theme_color = models.CharField(
    _("Theme color"),
    max_length=9,
    blank=True,
    default="",
    help_text=_("Screen accent color (hex); empty = follow site primary"),
)
```

要点：

- 缺省 `dark` = 存量大屏与示例种子零迁移观感（迁移只加列带默认值，不回填）；
- `theme_color` 存 hex 字符串（`#rgb` / `#rrggbb`），`blank` 允许空串语义「跟随站点」；
  不用 null 是为了避免 JSONField/CharField 空值双态（与项目「空串即未配置」口径一致）；
- choices 的 label 进 i18n（`_("Dark")` / `_("Light")` / `_("Follow site")`），zh 译文
  「深色 / 浅色 / 跟随站点」补进 `locale/zh/.../django.po`。

### 5.2 归一化与校验（`screen_layout.py`）

主题字段不是画布载荷，**不进** `normalize_*` 窗格链路；校验收敛在序列化器：

```python
#: 大屏主题取值（与 Screen.ScreenTheme 同值；本模块不依赖模型）
SCREEN_THEMES = ("dark", "light", "auto")


def normalize_screen_theme(raw: Any) -> str: ...
def normalize_screen_theme_color(raw: Any) -> str: ...
```

- `normalize_screen_theme`：`None/""` → `"dark"`；非白名单值抛 `ScreenLayoutError`
  （消息可读，与窗格错误同通道）；接受标量（LabeledChoice 兼容由前端 `choiceValue` 归一）；
- `normalize_screen_theme_color`：`None/""` → `""`；`#rgb` / `#rrggbb` 之外的值抛错；
  统一输出小写 `#rrggbb` 形态（`#abc` 展开）。

`ScreenSerializer`：

1. `Meta.fields` 追加 `theme`、`theme_color`；`read_only_fields` 不含（创建/编辑均可写）；
2. `validate_theme` / `validate_theme_color` 调用上述归一化函数；
3. `table_fields` 追加 `theme`（列表可见；`theme_color` 不进列表列，避免色彩单元格无意义）；
4. 新建/编辑弹窗字段由前端元数据表单接管（见 §5.5），后端不做 choices → labeled 的特殊处理
   （沿用 `visibility` 的既有模式，读取为 `{value,label}`、写入收标量）。

### 5.6 前端：大屏主题解析与令牌（核心）

新增 `src/views/analysis/screen/utils/screenTheme.ts`（单一事实源，设计器与投屏共用）：

```ts
export type ScreenTheme = "dark" | "light" | "auto";

/** 大屏主题 → 实际明暗：auto 跟随站点 isDark */
export function resolveScreenTheme(theme: ScreenTheme | undefined, isDark: boolean): boolean;

/** 把大屏主题应用到根元素：data-screen-theme + 深浅态 + 可选主色覆写 */
export function applyScreenTheme(root: HTMLElement, dark: boolean, themeColor: string): void;
```

`applyScreenTheme` 实现（对齐站点 `setEpThemeColor` 机制）：

1. `root.classList.toggle("screen-root--light", !dark)`（深色为缺省态，不加类）；
2. 主色覆写仅 `themeColor` 非空时：`root.style.setProperty("--primary", hexToHslTriplet(color))`
   ——`--screen-*` 的光晕、标题色条与 `epColor("primary")` 图表取色全部随动；
   空串时 `removeProperty` 恢复站点主色。卸载（`onBeforeUnmount`）对称清理；
3. 不动 `data-theme` / `html.dark`（站点主题体系不被投屏页污染）。

CSS（`semantic.scss` 扩展）：`--screen-*` 令牌改为「深色缺省 + `.screen-root--light` 成对覆写」：


消费面审查结论（改造时逐条核对）：

- `display.vue` / `designer.vue` / `ScreenPane.vue` / 各画布组件（`GridCanvasBoard` /
  `FreeCanvasBoard` / `ScreenFreeStage` / `PaneMediaView`）全部只消费 `--screen-*` 与
  `--el-color-primary`（标题色条）——挂 `--screen-*` 覆写到投屏根节点即可整体换肤，
  但组件在**投屏根之外**渲染的部分（设计器的检查器面板 / 工具条 / 模板对话框）要用
  `:deep` 或提到根节点的类作用域核对一遍；
- 设计器根节点同样挂 `screenTheme`（编辑中即所见即所得），工具条 / 检查器保持现状深色玻璃
  视觉（它们是「设计器 chrome」，不是「画布内容」）；浅色画布 + 深色 chrome 的层次由
  `--screen-surface` 反转自然达成，若对比不足再单独微调 chrome 令牌（登记到执行时验证项）；
- 空态组件（`ReEmpty` 的 `:deep` 覆写）两档各验一次。

### 5.7 前端：投屏与设计器接线

`display.vue`：

```ts
const { isDark } = useDark();
const screenDark = computed(() =>
  resolveScreenTheme(choiceValue<ScreenTheme>(screen.value?.theme) ?? "dark", isDark.value)
);
const rootEl = ref<HTMLElement>();
onMounted(() => {
  if (rootEl.value) {
    applyScreenTheme(rootEl.value, screenDark.value, screen.value?.theme_color ?? "");
  }
});
watch([screenDark, () => screen.value?.theme_color], () => { /* 重新 apply */ });
onBeforeUnmount(() => { /* removeProperty 恢复 */ });
```

- 根元素 `:class="{ 'screen-root--light': !screenDark }"`；`--primary` 覆写由
  `applyScreenTheme` 写在根节点 style 上（模板 :style 绑定亦可，取其一实现，避免双写）；
- `auto` 模式下 `isDark` 变化（站点切深浅）实时跟随；
- `ScreenPane.vue`：`force-dark` 改为 `:force-dark="!screenDark"`（即深色主题才强制深色图表）；
  浅色主题下图表走 `chartColorScheme(false)` + `--el-bg-color-overlay` 内层底（浅色站点下

  读到暗色 tooltip。处理：`ChartCard` 的 `forceDark` prop 语义保持「强制深色」，另加
  `forceLight?: boolean`（优先级：forceDark > forceLight > 跟随 isDark）；投屏浅色主题传
  `force-light`，保证「大屏主题决定图表配色」而不受站点污染。

`designer.vue`：

| 风险 | 影响 | 缓解 |
|------|------|------|
| 浅色档令牌对比度不足（浅底浅字 / 深底深字） | 可读性 | 浅色值按深色档同构反转（同透明度、色相反转），交付前双主题截图人工验收 + 浅色基线入库 |

### 11.2 与方案的偏差（执行时定夺，均为等价或更优实现）

1. **表单主题控件改为页面自绘 renderer**：元数据 `labeled_choice` 的读值是
   `{value,label}` 对象，直接换 `valueType: "radio"` 匹配不到选项；改为在
   `screenThemeForm.ts` 里用 `ElRadioGroup` / `ElColorPicker` 自绘并绑定标量
   （写入仍是标量，服务端契约不变）。
2. **装配期主题独立成轻量模块**：方案建议 `main.ts` 直接调 `useDataThemeChange()`，
   实测会拖入 `useLayout` / `appReset`（首屏闭包 **+8.2 KB gzip**）。改为
   `src/utils/bootTheme.ts`（仅依赖 config / preferences / 主色纯函数，**+2.5 KB**），
   并把 `setLayoutThemeColor` 的主色判定抽为 `resolveThemePrimaryHex` 纯函数，
   装配期与布局期共用同一优先级（避免两套判定漂移）；装配期只做视觉落点、不写存储。
3. **设计器 chrome 随浅色档转浅**：方案预留「chrome 保持深色玻璃」为验证项；实测
   浅色画布 + 浅色 chrome 层次更清晰（`--screen-surface*` 成对反转已足够），故不额外
   引入中性令牌；深色主题完全不变。
4. **图表取色需作用域**：`--el-color-primary` 在 `:root` 已完成 `var()` 代换后向下
   继承，只覆写根节点 `--primary` 影响不到后代读到的 EP 主色；因此
   `applyScreenTheme` 同时覆写 `--el-color-primary: hsl(var(--primary))`，
   `chartTheme` 的 `cssVarColor` / `epColor` / `chartColorScheme` 增可选 `scope`
   （`ChartCard` 传自身根节点）——大屏主题色才能驱动图表系列色。
5. **`theme_color` 不进列表列**：色彩单元格无信息量，列表只加 `theme`（LabeledChoice → tag）。

### 11.4 投屏页体验补充（同日，方案外三项）

实测投屏后提出三点：无法返回、投屏页没有主题入口、站点公告浮层会盖住画面。补充如下：

1. **返回入口**：投屏页头部左侧加「返回」按钮（`data-testid="screen-back"`）——有站内历史走
   `router.back()`，直达打开（无历史）兜底跳大屏列表 `/analysis/screen/index`。
2. **投屏页主题面板**：头部加「主题」popover（`DisplayThemePanel.vue` + `useDisplayTheme.ts`），
   三选一 + 主题色取色。**切换默认只在本机生效**（投屏端多为共享展示账号，现场切深浅不应改
   别人的配置）：`useScreenTheme` 增加 `override` 入参，优先级 = 本机覆盖 > 大屏配置；
   面板内「恢复配置」清覆盖，「保存为默认」仅创建者且有 `partialUpdate:DataScreen` 时可见，
   一次 `partialUpdate` 固化后撤覆盖并回读。
3. **展板静默**：大屏投屏路由加 `meta.kiosk`（`types/router.d.ts` 补类型），通知 store 在
   `push_message` 分派处按 `isKioskMeta(router.currentRoute.value.meta)` 判定——应用内
   `ElNotification` 与桌面通知全部不弹（公告/聊天类同口径），**未读计数照常累加、登出指令照常执行**。
   判定抽为纯函数 `utils/kiosk.ts`（便于单测），守护用例覆盖「展板态不弹浮层」与「登出仍执行」。

副作用与连带动作：投屏页头部新增两个按钮 → 深/浅两档视觉基线重录（chromium + webkit）；
