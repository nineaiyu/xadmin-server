# 验证码上线前安全硬化实施细则（2026-10）

> 状态：**S1~S5 代码与烟雾验证已实施（2026-10-27）；shadow 基线/k6/回滚演练留发布日** ｜ 姊妹篇：[验证码统一题型与题库资产化方案-2026.10.md](验证码统一题型与题库资产化方案-2026.10.md)
> 前提：**项目尚未真正上线**——不保留旧图片码兼容层，不做存量迁移表演；直接用 clean cut 把攻击面砍到最小。
> 本篇承接主方案 §六/§七/§八，写威胁模型、强绑定、删除清单、上线门禁与红队验收；主方案保留架构与资产设计。

## 〇、一句话结论

上线前做三件事：**删掉旧图片码链路**（它答案明文入库、无票据、无风控，是最大攻击面）、
**把票据绑死到浏览器会话与动作**（sid + fp + scene + action + audience）、
**默认 `enforce` 并让所有失败同形**。不做「更难但更脆」的题，做「能证明、能观测、能回退」的安全。

> 安全声明：不承诺「不可破解」。承诺的是——答案永不出服务端、票据不可转移/重放、
> 客户端不能降级题型、批量行为必然留痕、异常可一键回退。任何声称验证码绝对安全的设计都不可信。

## 一、安全不变量（所有代码路径必须满足）

| # | 不变量 | 守护方式 |
|---|--------|----------|
| 1 | 答案只存在于服务端挑战密文，**不出现在** response / ticket / 日志 / 预览 | 响应字段断言 + 日志脱敏测试 |
| 2 | 风险分、决策、难度档**不回显客户端** | 契约测试：response 无 `risk/decision/difficulty` |
| 3 | 票据一次性、短 TTL、绑定 `scene + action + sid + fp + aud` | 重放 / 跨场景 / 跨动作 / 跨会话用例 |
| 4 | 客户端不能通过 `type`、`difficulty`、`action` 降级 | 决策优先级用例（hard 下请求 slide/image） |
| 5 | 所有失败路径响应体**字节级同形**（含耗尽、deny、签名错、跨域） | 字节比对用例 |
| 6 | 挑战 / 校验 / 消费在缓存不可用时 **fail-closed**；遥测故障不影响结果 | 缓存故障注入 + 遥测故障注入 |
| 7 | 匿名写端点必须 `require_human`，否则 CI 红 | `check_captcha_coverage.py` |
| 8 | 旧图片码路由/字段/模型**不存在**，误恢复即 CI 红 | `check_captcha_legacy.py` |
| 9 | 生产环境密钥必须显式配置，缺失即拒绝启动 | `doctor` + `manage.py check` |
| 10 | 资产必须有许可、来源、哈希、版本；禁止用户上传 | `check_captcha_assets.py` |
| 11 | 生产不存在 E2E inspect / 调试端点 | 路由 404 守护 + 配置门禁 |
| 12 | 日志不含答案、票据、ck/sign、原始 env/track、明文 IP | 日志字段白名单 + 脱敏测试 |

**信任边界**

```
不可信：浏览器/客户端、env/track/answer、type/action 参数、所有请求头、Origin/Referer
可信：服务端密钥、Redis（内网）、DB（内网）、经哈希校验的资产清单
规则：客户端只提供「观察值」，不参与决策；服务端永远用存储态（挑战密文 + 风险结果）判题与发票
```

## 二、威胁模型（上线前必须逐条有测试）

| 威胁 | 攻击路径 | 现有缺口 | 加固 | 验证 |
|------|----------|----------|------|------|
| 答案提取 | OCR 图片码、CV 模板匹配滑块、多模态读点选 | 图片码可 OCR；底图纹理熵低 | 图片题权重 0；资产轮换；低风险兜底；图片回退强制 PoW | 红队 OCR/模板匹配成功率记录 |
| 票据重放 | 拦截 ticket 重复提交 | 已有 nonce 一次性 | 保留 + 消费即删 + 统一失败 | 二次消费必败 |
| 票据转移 | A 浏览器产票，B 浏览器消费 | **`services.consume_ticket` 接收 `fp` 但未传给 `consume_ticket_payload`**（[services.py:415](../../captcha/services.py#L415)） | sid cookie + fp 强绑定 + aud；缺失/不一致即拒 | 跨浏览器/跨指纹消费必败 |
| 题型降级 | 客户端请求 `type=slide` 规避 hard | **`flow.pick_type` 先返回 requested，后判断 hard**（[flow.py:150](../../captcha/flow.py#L150)） | 服务端决策优先：hard 忽略 requested；image/icon 不进 hard | hard 下请求 slide 仍出难题型 |
| 环境伪造 | 伪造 `env` 拿 `allow` 免费票 | `allow` 无题直接发票 | **allow 也发低难度 PoW**（静默计算），通过后才发票 | 无 PoW 的 allow 请求必败 |
| 挑战枚举 / 资产枚举 | 高频拉题、按资产训练 | 无资产 id 但可高频 | 题型/资产轮换；挑战-校验比规则；子网限流 | 高频拉题触发冷却/告警 |
| 僵尸网络 | 大量 IP 轮换 | 仅按单 IP 限流 | `/24`、`/64`、ASN/CIDR、IP-指纹扩散规则 | 子网轮换仍被限 |
| 生成型 DoS | 刷 challenge 让 Pillow/TTS 打满 CPU | 仅 30/min 单 IP | 边缘 nginx 限流 + 应用并发上限 + 生成超时 + 503 | 压测下 P95 与错误率达标 |
| PoW 放大器 | 让服务端发大量 PoW 消耗 | bits 封顶、IP 预算已有 | 保持封顶 + 预算 + 频率限制 | 超预算拒绝 |
| 缓存投毒 | 写 Redis 伪造挑战/票据 | 票据签名自证 | 挑战密文只服务端写；票据 HMAC；不信任客户端状态 | 篡改挑战/票据必败 |
| 配置篡改 / 内鬼 | 改白名单、关风险、换密钥 | 设置页权限 + 审计 | RBAC + 配置审计 + 密钥轮换 + doctor | 非授权改配置被拒且留痕 |
| 供应链 | 替换字体/图库/图标字体 | 无 manifest | 许可白名单 + sha256 + 可选 HMAC + 只读挂载 | 篡改资产启动失败 |
| 日志注入 / PII | 答案、token、原始 env 入日志 | 现有日志已收敛 | 字段白名单 + 脱敏 + 保留期 + 访问权限 | 日志扫描无敏感值 |
| 无障碍拒绝 | 高风险只出难题型 | allow/light 可读屏 | 图片回退 + 音频 + 键盘；回退带 PoW | a11y E2E + 真机 |
| 旧链路复活 | 旧路由/字段/模型被误用 | 仍存在 | clean cut 删除 + CI 门禁 | 旧路由 404 + grep 门禁 |
| E2E 后门 | inspect 端点误挂生产 | 条件挂载 | 彻底删除，测试直读 Redis | 路由 404 守护 |
| CSRF / 跨站 | 第三方站点代发 challenge/verify | 无 Origin 校验 | `Origin`/`Sec-Fetch-*` + SameSite cookie + 无 CORS 通配 | 跨站请求拒绝 |
| 探测决策 | 通过响应差异判断 allow/hard | `decision/difficulty/attempts_left` 回显 | 删除这三个字段；统一失败 | 字节级同形断言 |

## 四、强绑定：票据不能离开这台浏览器

### 4.1 会话 sid（新增）

1. `challenge` 成功生成挑战时，服务端创建 32 字节随机 `sid`，计算 `sid_hash = HMAC(salt, sid)`，
   写入挑战密文；响应设置 cookie `captcha_sid`：
   `HttpOnly; Secure; SameSite=Lax; Path=/api/identity; Max-Age=挑战 TTL`。
2. `verify` 必须携带同一 cookie，服务端比对 `sid_hash`；缺失/不一致 → 统一失败。
3. 票据 payload 增加 `sid`（哈希）、`aud`（部署 audience）；消费时要求 cookie 一致。
4. `sid` 不落日志；轮换：每次 challenge 重新生成，旧 sid 随挑战过期。

### 4.2 指纹 fp（修复现有断线）

- 前端已在所有请求带 `X-Captcha-Fp`（[http/index.ts:322](../../../xadmin-client/src/utils/http/index.ts#L322)），
  但 `InteractiveCaptcha.consume_ticket` 只传了 IP，**把 `fp` 丢了**。
- 修复：`consume_ticket_payload(..., fp_hash=sig.hash_value(fp))`；`CAPTCHA_STRICT_BINDING=True`（默认）
  时缺失或不一致一律拒绝；不再「弱绑定只记录」。
- `fp` 是环境摘要的加盐哈希，不含原始 Canvas/WebGL 像素；盐可轮换。

### 4.3 audience 与密钥

- 票据 payload 增加 `aud`，默认取 `CAPTCHA_TICKET_AUDIENCE`（默认站点 URL/部署 id）；
  消费端必须匹配，防止 A 部署票据在 B 部署使用。
- `CAPTCHA_TICKET_SECRET`：**生产必须显式配置**；`DEBUG=False` 且缺失 → 启动失败，
  不再由 `SECRET_KEY` 派生。`CAPTCHA_TICKET_SECRET_PREVIOUS` 支持双密钥轮换。
- `CAPTCHA_FP_SALT`：生产建议显式配置；未配置时由 `SECRET_KEY` 派生并告警，轮换即切断历史关联。

### 4.4 verify 加签与时间窗

- `CAPTCHA_VERIFY_SIGN_REQUIRED` 默认 True，且**不再依赖风险档**；`off` 档也强制签名。
- `ck` 每次 challenge 下发；`gen_time` ±300s；`nonce` 一次性（`captcha_seen_`）；
  canonical 串与前端 `buildVerifySign` 严格同口径，专项向量测试交叉校验。
- `verify` 请求的 `type` 只用于匹配存储态；不匹配 → 统一失败。

### 4.5 Origin / CSRF

- challenge/verify 校验 `Origin` 是否在允许列表（`CSRF_TRUSTED_ORIGINS` / 站点 URL）；
  跨站或缺失（浏览器 UA）→ 统一失败。
- 校验 `Sec-Fetch-Site` / `Sec-Fetch-Mode` 与 Origin 自洽；异常 +10 分（不硬拒）。
- `SameSite=Lax` cookie + 无 CORS 通配；不使用 `*`。
- 生产强制 HTTPS/HSTS；`SECURE_PROXY_SSL_HEADER` 配好，否则 cookie `Secure` 不生效。

### 4.6 票据使用约束

- 只放 POST body，禁止 URL/query；日志与操作审计对 `captcha_ticket` / `ck` / `sign` 脱敏。
- TTL：allow 60s / light 90s / challenge 90s / hard 60s；一次性消费即删 nonce。
- 同 IP 未消费票据 ≤3 保留；新增同 sid/同指纹未消费票据 ≤1。

## 五、决策优先级：客户端只能「请求」，不能「决定」

`challenge` 的 type 处理必须改成：

| 服务端决策 | 客户端请求 type | 服务端行为 |
|------------|-----------------|-----------|
| `deny` | 任意 | 统一失败，不出题 |
| `allow` | 任意 | 发低难度 PoW（静默），忽略请求 type |
| `light` | 任意 | 发 PoW，忽略请求 type |
| `challenge` | 在启用池内 | 尊重请求；否则服务端加权选 |
| `challenge` | `image` | 仅当图片回退开启且风险未达 hard；强制 PoW |
| `hard` | 任意简单题 | **忽略**，强制 wordorder/click/icon + hard 难度 |
| `hard` | `image` | 拒绝，要求重验；图片题永不用于 hard |

- `flow.pick_type` 改为「先算决策，再过滤候选池，最后才考虑 requested」；
- `image` / `icon` 默认权重 0；`image` 不在 hard 候选；
- `verify` 以存储的 type 为准，客户端 type 不匹配 → 统一失败；
- 新增用例：hard 下请求 slide / image / pow 均不能降级；allow 下请求 image 仍走 PoW。

## 六、失败同形与反探测

- 删除响应中的 `decision`、`difficulty`、`attempts_left`；客户端不需要知道风险档。
- 所有失败（答案错、耗尽、过期、重放、跨场景/动作、sid/fp/origin 不符、deny、服务不可用）
  统一：HTTP 400 + `{code: 400, detail: <同一文案>, error: "captcha_invalid"}`。
- 不再返回 `captcha_exhausted` / `attempts_left`；尝试次数只进服务端日志。
- 失败文案双语一致（zh/en），i18n 门禁守护；字节级比对用例覆盖全部失败分支。
- 429 限流可区分（标准语义），但不得携带剩余次数/风险信息。
- 成功响应也不含风险分；`type`/`ttl`/题目数据是唯一必要字段。

## 七、密钥、配置与生产 fail-fast

| 检查 | 规则 |
|------|------|
| `CAPTCHA_TICKET_SECRET` | `DEBUG=False` 必须配置；缺失 → `ImproperlyConfigured`，不派生 |
| `CAPTCHA_TICKET_AUDIENCE` | 非空；默认站点 URL；票据必须匹配 |
| `CAPTCHA_FP_SALT` | 生产建议显式；空则派生 + 告警；轮换盐 = 切断历史 |
| `CAPTCHA_VERIFY_SIGN_REQUIRED` | 默认 True，且与风险档解耦 |
| `CAPTCHA_STRICT_BINDING` | 默认 True；缺 sid/fp → 拒绝 |
| `CAPTCHA_RISK_MODE` | 默认 `enforce`；上线前必须完成影子/合成流量基线 |
| `CAPTCHA_RISK_TRUST_PRIVATE_NETWORKS` | 默认 True；白名单为空 + enforce → doctor 告警 |
| `CAPTCHA_IMAGE_FALLBACK_ENABLED` | 默认 True（无障碍）；`CAPTCHA_POW_FOR_IMAGE_FALLBACK` 默认 True |
| `CAPTCHA_HONEYPOT_ENABLED` / `CAPTCHA_ACTION_BIND` / `CAPTCHA_POW_ENABLED` | 默认 True |
| `CAPTCHA_LOG_ENABLED` | 默认 True；保留期 30 天；成功采样可配 |
| HTTPS | 生产强制；cookie Secure；HSTS；反代 `SECURE_PROXY_SSL_HEADER` |
| 配置审计 | 设置页变更写操作日志；密钥字段只写不读；仅授权角色可改 |

**`manage.py doctor` 新增/强化检查**：密钥缺失、audience 空、strict binding 关闭、
enforce + 白名单空、图片回退开启但 PoW 关闭、资产 manifest 哈希不符、字体缺失、
旧路由仍挂载、inspect 路由存在、Redis/缓存不可用。

## 八、限流、DoS 与容量

- **边缘 + 应用双层**：nginx `limit_req`（challenge/verify/login 分开）+ DRF throttle
  （challenge 30/m、verify 60/m 起步，按压测调整）；登录失败与验证码失败分开计数。
- **多粒度**：单 IP、`/24`（IPv4）、`/64`（IPv6）、可选 ASN/CIDR、sid、指纹；
  同一指纹跨多 IP / 同一 IP 跨多指纹走风险规则与冷却。
- **生成并发上限**：Pillow 出图与 TTS 子进程各设并发信号量（建议 8/worker）；
  超时 2s；队列满返回 429/503 + `Retry-After`，**不得绕过验证**。
- **payload 上限**：图片 WebP、尺寸上限、base64 体积上限；拒绝超大 JSON / 深嵌套。
- **PoW**：bits 服务端封顶 20；verify O(1)；IP 预算；allow 静默 PoW 建议 16 bits。
- **Redis**：maxmemory 策略、键 TTL、挑战 payload 大小上限；缓存故障 fail-closed。
- **压测目标**：生成 P95 <150ms、verify P95 <300ms、错误率 <1%；
  100/500/1000 RPS 三档记录；bot 洪峰下不拖垮登录主链路。
- **紧急开关**：`CAPTCHA_ENABLED=False`（全站跳过，仅管理员、写审计日志）；
  按场景开关仍保留；不得作为常规降级。

## 九、资产与供应链安全

- `manifest.json`：`id/file/license/source/sha256/category/orientation/version`；
  启动与 `doctor` 校验哈希；可选 `CAPTCHA_ASSET_SIGNING_KEY` 做 manifest HMAC。
- 许可白名单：CC0 / OFL / Apache-2.0 / MIT / 自绘；无来源或许可不符 → 启动失败。
- 图片：WebP、剥离 EXIF/GPS、无人脸；Pillow `MAX_IMAGE_PIXELS` 防解压炸弹；
  禁止 symlink / 路径穿越；只读挂载，属主为应用用户。
- 字体：OFL/Apache；子集化；启动检查字符集覆盖；缺失 fail-fast。
- 图标字体：codepoint manifest；不运行时下载；不接收用户字体/图库。
- 依赖：不新增运行时第三方验证码/云服务；`pip-audit` + Trivy；
  Pillow/fontTools 版本跟安全通告。
- 资产轮换：版本化 pack；按资产看通过率；异常资产下线可回滚；
  客户端永远拿不到 `asset_id`。

## 十、日志、隐私与审计

- `CaptchaLog` 只存派生信号：`phase/scene/action/type/difficulty/decision/would_decision/
  risk_score/risk_reasons/passed/attempts/latency_ms/ip_hash/fp_hash/ua_class/browser/
  env_version/pow_bits/key_id/asset_id/input_mode`；不存答案/ticket/ck/sign/原始 env/track。
- IP 只存加盐哈希（网段前缀），UA 只存类别；fp 只存哈希；保留期默认 30 天。
- 请求日志/操作审计对 `captcha_ticket`、`captcha_code`、`ck`、`sign`、`password` 脱敏；
  验证码高 QPS 路由加入审计忽略面。
- 配置变更（阈值/白名单/密钥 id/资产开关）写审计日志；密钥值掩码。
- 访问日志/大盘需权限；导出审计；可选每日哈希链/导出 SIEM（企业部署）。
- 合规告知：采集什么、不采集什么、保留多久、零第三方外发；放置于登录页/设置页。

## 十一、安全测试与红队

**必测负向用例**

1. 纯 `curl`：无 env / 无 track / 无 sign / 无 sid / 无 fp → 全部统一失败；
2. 票据跨浏览器、跨指纹、跨 scene、跨 action、跨 audience → 全部失败；
3. 同一票据/同一 verify nonce 重放 → 第二次失败；
4. hard 决策下请求 slide/image/pow → 不能降级；
5. 客户端篡改 PoW bits / answer 类型 / track 形状 / NaN/Infinity / 超大 JSON → 失败但不 500；
6. 旧路由、inspect 路由 → 404；旧字段不在 OpenAPI；
7. 缓存/Redis 故障 → challenge/verify/consume fail-closed；
8. 遥测/Celery 故障 → 验证结果不受影响；
9. 资产 manifest 篡改、字体缺失、许可缺失 → 启动/doctor 失败；
10. 跨站 Origin / 缺 Sec-Fetch → 拒绝；Cookie 不带 → 拒绝；
11. 失败响应字节级同形（含耗尽/deny/签名错/跨域/缺 sid）；
12. 日志中不出现答案/票据/ck/sign/原始 env。

**红队脚本（发布前人工跑，不入 CI 阻断）**

- `loadtest/captcha_attack.py`（可选依赖）：OpenCV 模板匹配滑块、Tesseract/PaddleOCR 图片码、
  Playwright 模拟点选；记录每种题型的成功率与耗时；
- 结果写入 `docs/security/captcha-redteam-YYYYMMDD.md`，低于/高于阈值都复盘；
- 同一份脚本在调参前后各跑一次，证明「变贵」而不是「自我感觉」。

**其他**

- 浏览器矩阵：Chromium / WebKit / Firefox / 移动端；读屏；键盘；`prefers-reduced-motion`；
  无 `crypto.subtle` 的降级路径；
- 压测：k6；生成/校验 P95、错误率、Redis 命中、CPU/内存；
- 模糊测试：type 混淆、超长字段、非法 base64、负数坐标、超大 track；
- 依赖扫描：pip-audit、Trivy。

## 十四、残余风险（必须写进发布说明）

1. 客户端信号（env、track、fp）**必然可伪造**；我们靠多信号 + 会话绑定 + 算力 + 频率，
   不承诺识别所有自动化。
2. PoW 不是 GPU 抗性方案；它抬的是「每次尝试」的成本，不是「绝对不可能」。
3. 图片/点选/图标题都能被 CV/多模态模型攻击；题型轮换与资产热更是延缓，不是终结。
4. 无障碍与安全存在张力：图片回退 + PoW 是折中；极端攻击下可能临时收紧，
   必须保留人工/替代通道与合规说明。
5. 自托管没有云厂商的全局 IP 情报；ASN/代理清单需客户或运营维护，默认不完整。
6. 资产可被攻击者下载后离线训练；`asset_id` 隐藏与轮换只能提高成本。
7. `enforce` 默认值依赖合成/影子基线；没有真实流量时阈值仍是估计，上线首周必须盯盘。
8. 任何「超级安全」都应理解为**纵深防御 + 可观测 + 可回退**，不是零风险。
