## 工作纪律红线（长期有效，原散落于各规划文档，集中于此）

1. 新功能 100% 携带测试（单测或 E2E），CI 阻断；
2. 改动后端后跑 `pnpm test:e2e:fresh`（防旧进程假失败）；webkit 偶发 flaky 隔离重跑确认；
3. 业务功能先 ADR 后动手；
4. 升级走独立分支 + 全量门禁；Django 6.2 严格按 ADR-004 触发条件重开；
5. 任务原子拆分、conventional commits（中文 subject）；**只有用户明确说提交才 commit**；
6. 候选池启动前需产品优先级确认，窗口内不并行多项业务功能（单人维护）；
7. 先复核再动手：新任务先与既有计划/候选池对账，再全仓 grep 复核（「借鉴清单」必须先对账再排期）；
8. 契约改动先行：涉及元数据先改 server schema 再生成前端类型；
9. 教程 ↔ 代码镜像：xadmin-docs example 教程与 demo app 是镜像关系，改 demo 能力时同步教程或在 PR 中标记文档影响面。

技术观察项：TS 7.1（vue-tsc 兼容后按 [ADR-014](../adr/ADR-014-typescript-7-evaluation.md) 试点）、vite/rolldown 生态、
Django 6.2（严格按 [ADR-004](../adr/ADR-004-django-60-upgrade.md) 触发条件复核）——随依赖窗口滚动检查。
