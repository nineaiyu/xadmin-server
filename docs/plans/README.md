## 工作纪律红线（长期有效）

1. 新功能 100% 携带测试（单测或 E2E），CI 阻断；
2. 改动后端后跑 `pnpm test:e2e:fresh`（防旧进程假失败）；webkit 偶发 flaky 隔离重跑确认；
3. 业务功能先评审记录后动手（ADR 机制）；
4. 升级走独立分支 + 全量门禁；Django 6.2 严格按触发条件重开；
5. 任务原子拆分、conventional commits（中文 subject）；**只有用户明确说提交才 commit**；
6. 候选池启动前需产品优先级确认，窗口内不并行多项业务功能（单人维护）；
7. 先复核再动手：新任务先与既有计划/候选池对账，再全仓 grep 复核；
8. 契约改动先行：涉及元数据先改 server schema 再生成前端类型；
9. 教程 ↔ 代码镜像：xadmin-docs example 教程与 demo app 是镜像关系，改 demo 能力时同步教程或标记文档影响面；
10. 跨仓依赖的测试必须带单仓检出守卫：断言依赖兄弟仓（`../xadmin-client` / `../xadmin-web`）文件树的用例，
    必须先判目录存在、缺失即 `pytest.skip`——CI 只检出单仓（CSP 三处同源守护、`module remove` 前端扫描各踩过一次）；
    生产代码一侧同口径降级（缺目录返回空清单、不抛错）。

技术观察项：TS 7.1（vue-tsc 兼容后试点）、vite/rolldown 生态、Django 6.2（严格按触发条件复核）——随依赖窗口滚动检查。
