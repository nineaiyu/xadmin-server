## 二、年度主线：持续运营下的「两修三交付一恢复」

第五年度延续稳定运营，**无功能军备**；价值集中在真实缺陷与交付补缺：

| 类别 | 项 | 说明 |
|------|----|------|
| **缺陷修复** | DB `connect_timeout` | 演练暴露：PG 断网时 health **20s+ 完全无响应**（TCP 默认超时）→ `connect_timeout=3` 快速失败 |
| | venv 脚本 shebang | 重建 venv 后 pip/pytest 等指向旧路径 `.venv314` → 批量校正 + 补装 pip-audit |
| **交付** | SLO 快照工具 | `scripts/slo_snapshot.py`（四项 SLO 当前值：可用性 / P95 桶级近似 / 任务成功率 / 队列积压标注），校准与日常观测两用 |
| | docs 升级指南 | `guide/upgrade.md`（预检/执行/验证/回滚），补齐文档站缺口 |
| | 演练规范 ×2 | 网络层操作仅限可重建环境（DNS 事故教训）；`db_backup.sh` 手动执行须 `BACKUP_ONCE=1` |
| **事故与恢复** | Docker DNS 记录损坏 | `network disconnect/connect` 后全网络解析失效 → **重建 PG 容器恢复**（数据无损），恢复动作与规范入 [observability](../ops/observability.md) §六 |

## 三、演练（第五年度 2 轮，累计 6 轮）

| 轮次 | 场景 | 关键结论 |
|------|------|----------|
| 第五轮 | 网络分区（PG 断网） | 修复 `connect_timeout`；事故恢复流程验证（重建容器）；DNS 快速失败行为观察 |
| 第六轮 | 备份失败（单次模式） | `EXIT=1` + WARN 可判；临时文件不落正式名；恢复后 `EXIT=0` |

未覆盖边界（已登记）：`connect_timeout` 在 **TCP 挂起**（非 DNS 失败）场景的验证——可用 iptables 丢包模拟。
