**本年度输入（缺口与余量）**：

1. **可观测性缺「追踪 + SLO 运营」**：指标（prometheus）与错误收集（sentry）已就位，但无请求级追踪、
   无 SLO/告警分级运营、压测未常态化、故障演练未制度化——问题定位仍靠日志人肉串联；
2. **依赖线需窗口化**：Django 6.0.8 为非 LTS（6.2 LTS 预期已于第二年度依赖窗口完成升级，本年度复核落地状态）；
   Python 3.13 / Node 22+ / Vue·EP·Vite 大版本按依赖窗口滚动（[ADR-004](../adr/ADR-004-django-60-upgrade.md) / [ADR-014](../adr/ADR-014-typescript-7-evaluation.md) 触发条件口径）；
3. **交付工程未体系化**：升级路径（installer）、开放平台接入体验（SDK/示例）、发布工程（版本化/变更日志）；
4. **遗留外部条件项**（视觉基线 / Renovate / SCIM / 异地副本 / 页面 CSP 强制）：依赖推送与部署节奏，逐窗口检查。

## 二、年度定位与方向

**定位：平台成熟期。** 第一年度补功能缺口（G1–G12），第二年度做平台化深化（AI 执行 / 开放平台 / 体验债）；
本年度起功能面**按门控冻结**（仅真实诉求触发），资源向「稳定性、可观测性、交付工程」倾斜——
对单人维护而言，**降低故障排查与发布成本的投资回报高于继续加功能**。

### 方向 A（推荐主攻）稳定性与可观测性工程

| 子项 | 动作 | 验收 |
|------|------|------|
| A1 追踪 | 基于已引入的 sentry-sdk 启用 performance（请求级 trace + DB/缓存 span）；OTel 按评估出口决定是否再引入 | 核心链路（登录 / 列表 / 导出 / 审批 / 任务）可看耗时瀑布；无新增服务面 |
| A2 SLO 与告警治理 | 基于 prometheus 指标定义 SLO（可用性 / P95 延迟 / 任务成功率 / 队列积压）；告警分级与收敛（现有渠道） | SLO 看板 + 分级告警清单；误报率可统计 |
| A3 压测常态化 | k6 基线扩为核心 API 场景集 + 阈值化回归（CI 可选门槛，复用既有基线脚本范式） | 场景集入仓库；基线可对比；回归口径文档化 |
| A4 故障演练制度化 | 演练清单（DB 不可用 / Redis 断开 / worker 堆积 / beat 停摆 / 归档失败）按季度执行 | 每季一次演练记录（沿用 ops 记录口径） |

### 方向 B（门控）AI 观测与动作扩展

- B1 **用量/成本/失败率看板**（多档案 × 模型 × 调用方维度，复用多档案与 OperationLog）——直接做，低成本；
- B2 **受限动作扩展**（动作注册表按真实诉求增项；越权矩阵随项交付）——仅在出现真实业务动作诉求时启动；
- 检索向量化：按 [ADR-037](../adr/ADR-037-ai-retrieval-evaluation.md) 重开条件（评测驱动）。

### 方向 C（条件）交付与二开工程

- C1 **升级路径**：安装器（xadmin-installer）增强——版本迁移脚本、升级前检查、回滚口径与演练；
- C2 **开放平台接入体验**：示例客户端 / SDK 完善、事件契约文档体验（文档已自动生成）——**门控=出现真实接入方**；
- C3 **二开脚手架复评**（复评条件：教程再增 / 多人协作；未命中则维持关闭）。

### 方向 D（硬约束）依赖现代化

- Django：复核 6.2 LTS 落地状态；7.x 评估（触发条件 = celery 全链路声明支持 + 依赖窗口）；
- 运行时：Python 3.14/3.15、Node 24/26 LTS 评估与提线；
- 前端链：Vue / Element Plus / Vite / TS 按 ADR-014 触发条件复核（TS 7 依赖 vue-tsc 支持）；
- 安全依赖：pip-audit / pnpm audit 零高危（已常态化，按季度窗口）。

### 明确不做（红线延续）

- 多租户（[ADR-031](../adr/ADR-031-multi-tenant-evaluation.md) 三条重开条件未命中）；
- 业务模块军备（商城 / CRM / WMS 等）；
- 重依赖（类 Excel 报表设计器、vxe-table、schema-form 等）；
- 适老主题（已否决，仅保留「浏览器缩放引导」类轻方案的说法，需求触发再评估）；
- 全面移动端适配（仅核心页平板宽度抽查修补）。

## 三、年度排期总览

```
2028-10    11      12  | 2029-01    02      03  | 04      05      06  | 07      08      09
|--依赖窗口--|--追踪--|--SLO/告警--|--压测/演练--|--AI观测--|--交付一--|--交付二--|--前端窗口--|--数据触发--|--滚动债--|--缓冲/核对--|--回顾+规划--|
```

排期逻辑：**先立可观测性底座（追踪 → SLO → 压测/演练）→ 再做低成本治理项（AI 观测、交付工程）→
中段处理前端依赖窗口与触发式数据项 → 后段滚动债与年度收口**。每窗口独立可交付、先 ADR 后动手。
