# 二开体验与模块化管理评估与改进（2026.09）

> 依据 2026-09-28 的全仓走查（后端模块化机制 / 前端模块消费 / 生成器与文档 / 开发态工具链四路）+
> 与既有台账（[OPTIMIZATION-PLAN](../../../../OPTIMIZATION-PLAN.md)、plans/archive 二开两篇、
> [ADR-045](../adr/ADR-045-modular-trimmable-architecture.md)）对账后的结论。
> 定位：**评估报告 + 改进台账**。P1 四项与 P2 五项已全部收口（见 §四；P2-5 为评估结论、维持触发制）。

## 一、总体结论

项目在「二开友好」上的建设已远超同类开源 RBAC 项目（对标口径见
[全面架构盘点](全面架构盘点与重构方案-2026.09.md) §对标）：**「禁用自带模块」「快速新增业务模块」都已是现成能力**，
且各有文档与守护测试。当前提升空间不在补功能，而在少数**日常摩擦点**：

1. 开发态后端代码不热加载（改代码 → 手动 restart 四容器，二开者第一小时最大挫败感来源）；
2. 新 app 注册要动两套机制（`XADMIN_APPS` + `modules.py`），且 config.yml 手工编辑；
3. 模块停用对前端无感知（网关 404 无模块标识，前端按普通 404 报错）；
4. 后台覆盖行会静默屏蔽 config.yml 变更，`modules --config` 输出不提示，易踩坑。

## 二、现状盘点（已有能力，速查）

| 能力 | 用法 | 实现 |
|------|------|------|
| 禁用自带模块（软裁剪） | `config.yml` 的 `MODULE_PRESET`（core/standard/full）+ `MODULE_ENABLE/DISABLE`；或管理页「模块管理」 | 六层生效：路由 404 / WS 拒连 / 菜单权限点隐藏 / 周期任务不注册 / 种子裁剪 / 缓存清理（`common/core/modules/`）；`manage.py modules` 清单/预演/`--impact` 体检 |
| 物理移除模块 | `manage.py module remove <id> [--apply]` | 种子清理 + 归档回滚（`system/management/commands/module.py`），代码删除按清单人工 |
| 新增业务模块 | `manage.py generate_crud <app>.<Model> [--bootstrap --grant-to]` | 后端四件套 + 前端页面（RePlusPage）+ 菜单种子一条龙；教程 `docs/guide/first-module-30min.md` |
| 第三方 app 扩展点 | `XADMIN_APPS` 注册 → `config.py::URLPATTERNS`（路由）/ `TASK_ROUTES`（队列）/ `routing.py`（WS）/ `modules.py`（模块声明，`generate_module` 生成） | 全部自动发现，无需改框架源码 |
| 前端零样板 CRUD | `RePlusPage` + 元数据契约（choices/search-fields/search-columns） | 新页面约 30 行；渲染器注册表可扩展 |
| 二开文档体系 | 30min 教程 / recipes 23 条 / cookbook / component-handbook / dev-pitfalls | 四道 doc 门禁（facts/paths/index/tutorial-mirror）防腐 |

**语义红线**（勿破坏）：关闭模块只隐藏与拦截、不删业务数据，重启后全进程原子生效；
`XADMIN_APPS` 决定「是否安装」（迁移/路由），`MODULE_*` 决定「是否可用」（裁剪），两者正交。

## 三、已知边界（评估确认，维持现状）

- 自带 9 个 app 硬编码在 `server/settings/base.py` 的 `INSTALLED_APPS`：软裁剪后代码仍安装、表仍迁移。
  硬移除走 `module remove` + 按清单删代码（人工）；不提供运行期「卸载 app」配置（迁移与依赖校验的复杂度 > 收益）。
- 前端构建产物含全部页面（P2b 已评估不立项，页面懒加载下收益仅 dist 体积）；
- 模块开关 ≠ 功能开关（`LDAP_AUTH_ENABLED` / `SCIM_ENABLED` / `AI_ASSISTANT_ENABLED` 等保持独立）；
- 后台覆盖行存在时 config.yml / 环境变量不生效（§四 P1-3 已补提示；恢复通道 `modules --clear-override`）。

## 五、给二开者的三句话

1. 只想裁掉自带功能：改 `config.yml` 的 `MODULE_PRESET / MODULE_DISABLE`（或管理页「模块管理」）→ 重启；
   上线前先跑 `manage.py modules --preset standard --impact` 体检；
2. 要加自己的业务：`generate_crud <app>.<Model> --bootstrap --register-app --with-module --grant-to <角色>`
   一条命令出全栈骨架并注册可裁剪模块，全程见 `docs/guide/first-module-30min.md`；
3. 开发自查三件套：`manage.py doctor`（权限点/依赖/契约）、`manage.py modules`（模块清单）、
   `python scripts/check_tutorial_mirror.py` 教程镜像门禁随 CI 常驻。
