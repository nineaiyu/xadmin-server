# 聊天室重构计划（微信式 IM + AI 助手）

> 状态：**已交付**（2026-09-14，决策记录见 [ADR-034](../adr/ADR-034-chat-room-rebuild.md)；ADR-032 已被审批业务集成占用，本文所涉决策顺延为 ADR-034）。
>
> 范围已与用户确认：**一期即含私聊**（ChatRoom 会话模型 + 未读红点）；**AI 双形态**（通用多轮对话 + `/kb` 前缀触发知识库问答）。
>
> §9 待确认事项的落地口径：①私聊对可进聊天室的用户全量开放（未加额外开关，权限由
> `list:ChatRoom` 等 6 个权限点控制）；②一期不做自动清理（`CHAT_HISTORY_DAYS` 登记二期候选）；
> ③AI 人设内置默认值写死（配置化留后续）；④菜单路径保持 `/default/chat/index` 不变。

## 1. 背景与现状诊断

| 层 | 现状 | 问题 |
|---|---|---|
| 前端 `views/chat/index.vue`（172 行） | 单列窄卡片，消息纯文本一行行 | 无头像/气泡/时间分组；`search`/`filteredItems` 为未接线死代码；刷新消息全丢 |
| 后端 `message` app | 无 `models.py`、无 REST，纯 WS 广播到硬编码组 `message_system_default_0` | 消息零落库，无历史/撤回/分页；全站单一房间；无私聊概念 |
| @提及 | 只认行首 `@` 后第一个词 | 位置受限、无多目标、无成员联想 |
| 在线用户 | 已有完整基建：`UserSession` + `/api/system/online`（WS+HTTP 会话统一） | 聊天室未使用 |
| AI | 已有基建：`ChatCompletionsClient`（原生多轮 `messages`）、`AI_ASSISTANT_ENABLED` 配置、`ask:AiAssistant` 权限点、知识库 RAG（`system/utils/ai.py`） | 聊天室未接入 |
| 协议 | ADR-003 已 Schema 化（`message/protocol.py` ↔ `websocket/protocol.ts` ↔ `test_protocol.py` 三处契约） | 新增 action 必须三处同步 |

**两个必须处理的隐藏坑：**

1. 聊天页现用 `new PureWebSocket("system_default_websocket", "xadmin")`——构造签名实为 `(username, group)`，URL 拼成 `/ws/message/xadmin/system_default_websocket`，后端靠 `URL 第二段 username != 登录用户名` 这条**隐式规则**判定进聊天室组。重构改用显式路由后此规则即废弃。
2. E2E `notice-push.e2e.ts` 依赖旧聊天页的输入占位符（`输入消息并回车发送`）与 `chat_message` → `push_message` 帧链路，页面重构后必须同步改写。

## 2. 目标形态

微信式两栏布局（窄屏左侧折叠为抽屉）：

```
┌──────────────┬──────────────────────────────────────┐
│ 🔍 搜索       │  会话标题 + 副标题（在线人数/模型名）   │
├──────────────┼──────────────────────────────────────┤
│ AI 助手  ②   │  ── 昨天 ──────────────              │
│ 公共聊天室 ●  │  [头像] 张三  你好                    │
│ ── 最近在线 ──│             我也好 [头像]（自己靠右）  │
│ 张三 ● 在线   │  ── 14:02 ──                         │
│ 李四 ○ 2h前  │  [头像] AI助手 ▌正在思考…             │
└──────────────┴──────────────────────────────────────┘
```

- 左列表三段：固定会话（AI 助手按开关显隐、公共聊天室）+ 最近在线联系人（在线优先、按最后活跃排序）
- 未读红点：私聊与 AI 会话在左列表显示角标；公共聊天室一期不做未读（进入即浏览）
- 右侧：消息气泡（自己右对齐）、时间分组（今天/昨天/日期）、历史向上滚动加载、离底时“N 条新消息”悬浮条

## 3. 总体设计

### 3.1 数据模型（`message/models.py`，message app 新增 models）

**ChatRoom（会话）** — BigAuto 主键

| 字段 | 说明 |
|---|---|
| `room_type` | `public`（公共聊天室，全站单例）/ `private`（一对一私聊）/ `ai`（AI 助手，每用户一间） |
| `room_key` | 规范化唯一键：`public` / `dm:{min_pk}:{max_pk}` / `ai:{owner_pk}`，`UniqueConstraint` 保证幂等 |
| `name` | 显示名兜底（private 留空，前端显示对方昵称） |
| `owner` | ai 会话归属用户；其余为空 |
| `last_message` / `last_message_time` | 冗余最后消息，会话列表排序零成本 |
| `is_active` | 软关停位 |

**ChatRoomMember（成员 + 未读游标）** — 仅 `private`/`ai` 会话维护行（公共聊天室全员可见，不建行）

| 字段 | 说明 |
|---|---|
| `room` / `user` | `UniqueConstraint(room, user)` |
| `last_read_id` | 已读游标（消息 BigInt id） |
| `unread_count` | 冗余计数（新消息 +1、已读清零），避免每次 count |

**ChatMessage（消息）** — BigAuto 主键（自增即游标）

| 字段 | 说明 |
|---|---|
| `room` / `sender` | sender 可空（AI/系统消息）；`sender_name` 存快照防改名漂移 |
| `message_type` | `text` / `ai` / `system` |
| `content` | TextField，发送端限长 2000 |
| `client_msg_id` | 客户端幂等键（断线重发去重），`(sender, client_msg_id)` 唯一 |
| `is_recalled` / `recalled_time` | 撤回标记（本人 2 分钟内） |
| 索引 | `(room, id)` 游标分页 |

### 3.2 WS 协议扩展（ADR-003 契约三处同步）

**新增专用路由** `ws/chat/` → 新 consumer `ChatNotify`（纯聊天通道，**不登记 UserSession**，避免在线列表重复计数）：

- connect 后加入两个组：`chat_room_public`（公共广播）+ `chat_user_group_{pk}`（私聊/AI/未读推送）
- 旧路由 `/ws/message/<group>/<username>` 与 `MessageNotify` **完全不动**（user store 全局通知连接 + 登录日志链路零风险）

| action | 方向 | 载荷 |
|---|---|---|
| `chat_message` | ↑ 发送 | `{room_id, content, client_msg_id}` |
| `chat_message` | ↓ 广播 | `{id, room_id, room_type, sender_pk, sender_name, message_type, content, created_time, client_msg_id}` |
| `chat_recall` | ↑/↓ | `{message_id}` → 双方/全员广播撤回事件 |
| `chat_read` | ↑ | `{room_id}` → 服务端清零未读并回执最新游标 |
| `chat_unread` | ↓ | `{room_id, unread_count}` → 左列表红点实时更新 |

**消息分发拓扑：**

- 公共消息 → 落库 → `chat_room_public` 组一次广播
- 私聊消息 → 落库 → 双方 `chat_user_group_{pk}`（多端同步）+ 接收者通知组 `websocket_group_{pk}` 推 `push_message` 帧（`message_type=chat_private`，复用现有站内信弹窗管道）
- @提及：保留 `notify_at_user_msg` 管道，增强为**全位置匹配 + 多目标**（不限于行首）

### 3.3 REST 接口（`/api/chat/`，message app 新增 urls/views）

| 接口 | 说明 |
|---|---|
| `GET /api/chat/room/` | 我的会话列表：固定公共聊天室 + 私聊 + AI，含最后消息摘要与未读数 |
| `POST /api/chat/room/open-private/` | `{user_pk}` → `get_or_create` 私聊房间（`room_key` 幂等） |
| `GET /api/chat/message/?room=&before_id=&limit=` | 历史游标分页（倒序拉取、前端反转），默认 20 条 |
| `POST /api/chat/message/{id}/recall/` | 撤回：仅本人、2 分钟内 |
| `GET /api/chat/contacts/` | 在线联系人：复用 `get_online_info` 去重用户 + 在线态/最后活跃 |
| `POST /api/chat/ai/message/` | AI 发问 `{room_id, content}`；`/kb ` 前缀走知识库 RAG，否则多轮对话（见 §4） |

权限：页面沿用聊天室菜单授权；私聊默认对可进聊天室的用户开放；AI 相关接口复用 `ask:AiAssistant` 权限点 + `AI_ASSISTANT_ENABLED` 门禁。消息内容前端一律文本插值渲染（不 `v-html`），长度服务端限 2000。

### 3.4 前端架构

```
src/views/chat/
  index.vue              # 左右分栏骨架 + 响应式（<768px 折叠抽屉）
  components/
    ChatSidebar.vue      # 搜索 + 固定会话 + 在线联系人（在线点/最后活跃）
    ChatWindow.vue       # 头部 + 消息区 + 输入区
    MessageBubble.vue    # 气泡（头像/昵称/时间/撤回/系统消息）
  hooks/
    useChat.ts           # 聊天 WS 连接订阅、消息状态、游标分页、发送幂等
    useRooms.ts          # 会话列表、未读红点、open-private
src/api/chat/index.ts    # REST 封装
src/utils/websocket/     # protocol.ts 协议类型扩展（与服务端同步）
```

- 聊天页自建 `ws/chat/` 连接（`PureWebSocket` 增加子类），不与 user store 全局连接争抢 `onmessage`
- user store 增补 `chat_private` 提醒分派：弹通知（点击跳聊天室）+ 未读角标
- 交互细节：Enter 发送 / Shift+Enter 换行；`@` 弹在线成员联想插入 `@username `；发送中/失败重试（client_msg_id 幂等）；AI 会话“正在思考”指示器 + `/kb` 命令提示；深色模式；i18n 中英词条齐全；清理 `search/filteredItems` 死代码

## 4. AI 集成（双形态）

- **通用多轮**（默认）：读 `room=ai:{owner_pk}` 最近 20 条裁剪上下文 + 系统提示词（内置通用助手人设）→ `ChatCompletionsClient.chat(messages)`；user/assistant 双条落库，刷新可续聊
- **`/kb` 知识库问答**：前缀命令识别后复用 `system/utils/ai.py` RAG `ask()` 链路，回复附引用来源（折叠展示）
- **门禁**：`AI_ASSISTANT_ENABLED` 且凭据已配置才可用——关闭时前端隐藏 AI 入口、接口 400；LLM 异常降级为“AI 服务暂时不可用”系统消息（不静默）
- AI 走 REST 同步（LLM 5~60s，不用 WS 长占）；流式 SSE 留二期

## 5. 兼容性与风险

| # | 风险 | 处置 |
|---|---|---|
| 1 | E2E `notice-push.e2e.ts` 依赖旧页面占位符与旧连接 | 同步改写：走新聊天页发 `@xadmin` 消息，`push_message` 帧断言链路不变 |
| 2 | 旧聊天连接（`system_default_websocket`）废弃 | 后端旧分支保留兼容无害；页面切新路由 |
| 3 | 在线列表重复计数 | `ChatNotify` 不登记 UserSession（会话登记仍由全局连接唯一负责） |
| 4 | 迁移与部署 | message app 首版迁移，纯新增表零数据风险；正式库按纪律 `docker restart xadmin-server xadmin-celery-worker xadmin-celery-heavy` |
| 5 | XSS / 内容安全 | 前端文本插值渲染禁 `v-html`；服务端限长 2000 |
| 6 | N+1 / 性能 | 会话列表 `select_related`；历史 `(room, id)` 索引游标分页；联系人接口复用 5s 在线快照缓存 |
| 7 | i18n 词条 | 全部新增文案同步 zh-CN/en（含 po 词条的历史教训：占位符形如 `<xxx>` 会触发 i18n 报错，文案规避） |

## 8. 一期不做（登记二期候选）

图片/文件消息、群聊（多人会话）、已读回执展示（“对方已读”）、全局消息搜索、表情包、AI 流式输出（SSE）、历史自动清理任务（可预留 `CHAT_HISTORY_DAYS` 配置位）、桌面 Notification API 通知。

## 9. 待确认事项

1. **私聊权限**：默认对能进聊天室的用户全量开放，是否需要额外权限点/开关（如 `CHAT_PRIVATE_ENABLED`）？
2. **消息保留**：一期不自动清理，是否接受（或需要一期就加保留天数清理任务）？
3. **AI 人设**：内置通用助手提示词（写死默认值），后续再开配置项，是否可？
4. **菜单路径**：聊天室保持现有 `/default/chat/index` 不变（E2E 与用户习惯零影响），确认？
