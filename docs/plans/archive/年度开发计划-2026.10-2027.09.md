## 一、现状结论（对标不落下风的部分）

三层权限（16 种规则编译器 + 权限预览试算）、认证安全全家桶（MFA / PAT / OAuth2·OIDC 联邦 / SCIM 2.0 / 密码历史·过期·泄露库 / CSP / 限流）、审批流一二期（网关 / 版本回滚 / 比例会签 / 画布）、导入导出与下载中心、文件中心 + Office 预览、监控面板与任务健康度、通知渠道抽象、审计与脱敏、元数据驱动 CRUD + 契约 Schema 冻结、i18n 硬门禁、a11y 门禁、E2E 双浏览器入 CI——
以上能力**多数对标项目要么没有、要么深度不及**（jumpserver 对标过的安全项全部闭环）。缺口集中在「平台化/生态」侧，而非框架质量侧。

## 二、缺口清单（按对标项目差距排序）

### P0 — 国内企业环境的事实标配，缺失即劝退

| # | 缺口 | 对标现状 | 说明 |
|---|------|----------|------|
| G1 | **LDAP/AD 目录同步** | jumpserver / RuoYi 系标配 | xadmin 有 SCIM（云 IdP）但无 LDAP（本地 AD/OpenLDAP，政企刚需）：LDAP bind 登录 + 定时同步用户/部门 + 字段映射 + 冲突策略 |
| G2 | **企业 IM 深度集成** | jeecg / 芋道标配 | ① 钉钉/企微/飞书扫码登录（复用既有 OAuth 联邦扩 provider，成本低）；② 三家消息渠道（候选池已有项，模板就绪） |
| G3 | **可视化：自定义仪表盘 / 大屏** | jeecg 大屏 + 仪表盘设计器、积木报表 | xadmin 仅固定监控面板。做「数据集（绑定现有 API/模型，天然过数据权限）+ 拖拽卡片仪表盘 + 投屏模板」，**不做**类 Excel 报表设计器（重依赖红线） |
| G4 | **AI 能力** | jeecg AI 低代码 2.0（NL 生成系统/表单/流程）、芋道 AI 模块 | xadmin 完全空白。差异化打法=「受权限约束的 AI」：NL 查数（编译为数据权限过滤的受控查询，fail-closed，复用权限试算链路）+ 基于本仓 docs/ 的使用/二开问答（RAG）。元数据 + 权限体系是做「可信 AI 查数」的天然地基 |

### P1 — 平台化与二开体验

| # | 缺口 | 说明 |
|---|------|------|
| G5 | 动态表单（无模型采集表单） | jeecg 在线表单设计器的收敛版：JSON Schema 表单 + 通用 JSON 存储 + 审批/通知挂接；补「采集登记类」需求，与元数据理念兼容 |
| G6 | 出站 Webhook 事件订阅 | 事件目录 + 签名 + 重试 + 审计；对外系统集成的标准能力（现通知渠道只面向人） |
| G7 | 代码生成器 | Model → 后端四件套 + 前端页面 + 菜单种子 JSON。与 D5「脚手架不立项」不冲突：生成器输出的是仓库既有范式代码，无模板维护面 |
| G8 | 报表中心轻量版 | 数据集 + 筛选聚合 + 导出 + 定时报表邮件（复用异步导出与通知渠道） |
| G9 | 全局实体搜索 | Postgres 全文检索跨常用实体（用户/部门/文件/审批单/日志），顶栏统一入口 |

### P2 — 小件

| # | 缺口 | 说明 |
|---|------|------|
| G10 | 页面水印 | 敏感页面动态水印（用户名/时间），防截图溯源 |
| G11 | 开放平台雏形 | API 应用管理（client-credentials 应用、回调注册、按应用限流），基于 PAT 体系扩展 |
| G12 | SysConfig 值级加密 | 代码优化清单 T13 登记的既定方向 |

### 明确不做 / 需推翻既有决策才做

| 项 | 处置 |
|----|------|
| SaaS 多租户 | RuoYi-Vue-Plus / 芋道的核心卖点，但既有决策为「除非立项 SaaS 多租户」——**仅做 ADR 评估（go/no-go），不默认承诺**（2027-09 窗口） |
| 商城 / CRM / ERP / 支付 | 芋道路线，超出「权限管理框架」定位，单人维护不可持续，不做 |
| uni-app 多端 / 小程序 | 不做 |
| 类 Excel 报表设计器、vxe-table、schema-form 等重依赖 | 维持「重依赖不引入」红线 |

## 三、年度排期总览

```
2026-10  11    12 | 2027-01  02    03 | 04    05    06 | 07    08    09
|--LDAP--|--IM登录-|--IM渠道--|--仪表盘--|--仪表盘/报表-|--Webhook-|--AI一期--|--AI二期--|--动态表单一--|--表单二/生成器-|--开放平台+小件-|--租户ADR+回顾-|
            └─ 运营贯穿：季度备份演练(12/03/06/09-08) · audit 周检 · 依赖窗口(12/03/06/09) · E2E 绿 · 新功能 100% 带测试
```

排期逻辑：**先补企业接入标配（LDAP/IM，最广诉求、复用度高）→ 再补可视化与集成（仪表盘/Webhook）→ 再做差异化（AI 受权限约束查数）→ 最后平台化收尾（动态表单/开放平台）**。每个主项独立可交付、先 ADR 后动手。

## 五、风险与对策

| 风险 | 对策 |
|------|------|
| 单人维护，AI/仪表盘/动态表单三个大件体量高 | 每窗口仅 1 主项；每个大件先 ADR 并设「评估出口」（可降级/可砍）；一律走独立分支 + 全量门禁 |
| AI 查数的安全边界 | 禁原生 SQL、白名单字段、数据权限编译器强制过滤、试算预览、默认关闭灰度、越权专项用例——四层防线缺一不可 |
| 重依赖诱惑（报表设计器/画布类） | 维持红线：优先复用 ECharts/@vue-flow 既有资产；新依赖需 ADR 说明体积与维护面 |
| LDAP/IM 涉及外部凭据 | 凭据全部走 SysConfig 值级加密（G12 提前到 AI 一期前落地）；连接测试 + 失败降级不阻断本地登录 |
| 计划与现实偏差 | 双周回顾，超期按「安全 > 测试 > 文档」砍范围；候选池/新需求先登记本表再排期 |
