## 二、演练体系（累计 12 轮，全域覆盖）

| 域 | 轮次（场景） |
|----|-------------|
| 调度 / 执行 / 缓存 | beat 停摆 · worker 停摆 · Redis 冻结 |
| 备份 | 归档失败 · 备份恢复 · 备份目录不可写（单次模式） |
| 数据库 | PG 重启 · **PG 只读** · **TCP 挂起（connect_timeout）** |
| 网络 | 网络分区（含 DNS 事故恢复） |
| 配置 / 安全 | **坏配置 fail-fast** · **SECRET_KEY 轮换** · **敏感泄漏扫描** · **敏感权限审计** |

完整记录（方式 / 结论 / 规范沉淀）见 observability §六；由演练驱动的修复：
`connect_timeout=3`、探针并行化 + 2s 预算、`BACKUP_ONCE` 单次模式规范、`ALTER SYSTEM` 单语句规范。

## 三、能力矩阵（现行）

- **平台**：六容器（server / worker / heavy / beat / PostgreSQL / Redis）+ 备份容器 + Prometheus 指标端点（token 保护）+ health 四指标（探针并行化，2s 共享预算）
- **安全**：CSP（Django 侧 enforce / 页面 Report-Only 待部署形态）、AES v2 加密传输、JWT + PAT + SCIM + LDAP、AI 审计全链路、config 600 加固
- **数据**：PITR 回放（WAL 归档）、备份（KEEP_DAYS + 单次模式 + 预检/回滚）、异地副本机制就绪（未启用）、审计保留
- **运营**：SLO 快照工具、12 轮演练与规范、发布 checklist、依赖审计（双 0）、季度节奏
- **AI**：观测看板（用量 / 成功率 / token 成本）、知识库问答、NL 查数、受限动作（门控）、多档案
- **工程**：安装器（升级预检 + 回滚指引）、文档站（安装 / 升级指南）、门禁全链（pytest / ruff / 前端 typecheck·lint·stylelint·vitest·contract·bundle-size / E2E 双浏览器 / visual baseline 机制）
