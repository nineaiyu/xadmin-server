## 一、C-22 生产量级执行计划（`UserLoginLog` / 公告 `icontains`）

方法：开发库灌 **100 万行** `audit_userloginlog`（16 列真实分布）+ **20 万行**
`notifications_messagecontent`，用 ORM 真实 SQL 跑 `QuerySet.explain(analyze=True, buffers=True)`。

| 查询（100 万行登录日志） | 无索引 | 加 trgm 表达式索引 |
|---|---|---|
| `ipaddress__icontains='192.168'` 首页 20 条 | **232.5ms**（`Index Scan Backward(idx_loginlog_created)` + Filter，凑够 20 条扫掉约 100 万行） | **2.5ms**（Bitmap Index Scan，≈93×） |
| 同上 `count()` | 93.2ms（Parallel Seq Scan） | 2.3ms（≈40×） |
| `city__icontains` 首页 20 条 | 0.05ms（命中 12.5%，倒序扫 140 行即凑够） | 0.05ms（planner 不选索引） |
| `city__icontains count()` | 56.7ms | 110ms（**负收益**，命中率高时 seq 更快） |
| 公告 `title__icontains`（20 万行） | 15.4ms | **1.5ms**（≈10×） |
| 公告 `message__icontains`（命中 100%） | 39.5ms | —（不可能走索引） |

结论与决策：

- `ipaddress` 走 `UPPER(HOST(ipaddress)) LIKE`（Django 对 `GenericIPAddressField` 的 icontains 形态），
  **低命中率 + 小 LIMIT** 是 planner 最坏组合：只能沿 `created_time` 索引倒扫逐行过滤。
- 只有**低命中率模糊检索**（ip、公告 title）值得 trgm；city/browser 属高频命中，加索引为负收益。
- **本批不提交索引迁移**：生产行数未知，100 万行 232ms 属可接受单次开销，且 GIN 有写放大。
  **触发条件**：`UserLoginLog` > 200 万行且登录日志检索 P95 > 300ms，或公告 title 检索 P95 > 50ms。

## 三、C-32 worker 停机重复派发（已复现 → 已修 → 已回归）

**机理**：`last_run_at` 只在任务完成后推进，而 beat 每分钟扫描。worker 停机/积压后恢复瞬间，
多条积压的 `dispatch_scheduled_reports` 被并发消费，全部判定「到期」→ 同一期次重复派发。

**复现（真实开发栈）**：暂停默认队列 worker → 向 broker 注入 3 条积压 dispatch → 恢复。
`task_exportrecord` 出现 **3 条同一报表记录**，创建时间 13:53:51.362 / .372 / .372（**同一毫秒内**，
证明是并发扫描而非串行补跑）。

**修复**（`dataset/analysis_tasks.py`）：

- 派发前 `cache.add` 原子占位 `report_schedule_dispatch_claim_<pk>`（TTL = 30min + 120s，
  覆盖 `CELERY_TASK_TIME_LIMIT`）；落选扫描直接跳过本轮。
- 任务 `finally` 释放占位（成功 / 失败 / 取消同口径）；broker 拒收时回滚占位并把预创建记录
  标 `FAILURE`，避免留下永久 PENDING 的孤儿行。
- 手动运行（`schedule_report_run`）不占位、不受占位影响。

**回归**：同一注入（3 条积压）→ 只新增 **1 条**记录（13:56:09.570）。

**测试**：`TestDispatchClaim` 5 例——并发只派发一次、释放后可再派发、broker 失败回滚与恢复、
任务完成释放、手动运行不受占位影响。

**边界**：worker 崩溃导致消息从未执行时，占位靠 TTL 30 分钟自愈（该报表最多延迟一期）。

**附带修复**：`test_dform_history_api.py` 两例仍按旧导出接口读 `resp.content`（四轮流式化后
CSV 走 `FileResponse`）→ 改为拼 `streaming_content`（此前全量未跑，属遗留红）。

## 四、#15 WS 半开 / 4401（真实代理实测）

环境：临时 nginx 容器使用生产同款 `http_server.conf`（`proxy_http_version 1.1` + Upgrade 头 +
`proxy_read_timeout 600`）反代 `server:8896`（:8900）。

- **4401 实测为 HTTP 403**：未认证握手被拒在升级阶段（服务端在 `accept()` 之前 `close(4401)`，
  Daphne 只能回 403），浏览器侧 `onclose` 拿到 1006，前端 `code === 4401/4403` 分支不可达。
  影响有界：重连前的 `reconnectTokenProvider` 刷新失败会中断重连，不会无限循环；但与注释
  声明的语义不符。**建议**（未改代码）：鉴权分支改 `accept()` 后再 `close(4401)`，或前端按
  「1006 + 刷新失败」判终态。
- **半开实测**：合法 Cookie 建连 `/ws/chat/` 后暂停 nginx，每 10s 发心跳——
  **+10s / +20s `readyState` 仍为 OPEN 且无 pong**（TCP 未断，浏览器不触发 onclose）；
  +30s 起进入 CLOSING。即前端 30s（3×10s）看门狗是唯一发现手段，与 `websocket.ts` 实现一致。
- nginx `proxy_read_timeout 600s` 远大于心跳 10s → 正常空闲不会被代理断链；页面隐藏导致
  定时器节流的长尾由 600s 上限兜底（超时后走正常 onclose 重连）。

## 五、SameSite=Lax 第三方 iframe（跨站对照实测）

Playwright chromium 对照实验（两个 host 各持同值 Cookie，把「域不匹配」从 SameSite 判断中排除）：

| 宿主站点 | iframe 目标 | 结果 |
|---|---|---|
| `127.0.0.1`（跨站） | `localhost:8900/api/identity/user` | **401，Cookie 未发送** |
| `localhost`（同站） | `localhost:8900/api/identity/user` | **200，Cookie 已发送** |

- Lax 阻断的是**跨站 iframe 嵌套导航**。xadmin 是 SPA：iframe 内的 HTML 是静态资源、
  不需要 Cookie；页面内的 API 请求由 iframe 文档自身站点发起（同站）→ 会带 Cookie。
  **故「第三方 iframe 大屏」的登录态不因 SameSite 丢失。**
- 真正的闸门是 **CSP `frame-ancestors 'self'`**（默认 report-only；强制模式直接不渲染）。
  要对外嵌入必须同时：CSP 放行来源 + 需要跨站 Cookie 时改 `SameSite=None; Secure`（+ CHIPS）。
- 遗留：本机账号 UI 登录需验证码、接口登录需防重放临时 token，未能以「真实登录态」跑完
  iframe 内页面全链路；Cookie 链路已由同站 200 证明，登录态本身由既有 E2E 覆盖。

### 10.1 WS 4401 语义修正（代码）

- **问题**：`accept()` 之前 `close(4401)` 会被 ASGI 服务器降级为握手阶段 HTTP 403，浏览器只
  拿到 1006，前端 `4401/4403` 终态分支永远不可达；且 `if not self.user` 对 `AnonymousUser`
  （truthy）永不命中，匿名连接实际落到权限检查的 4403。
- **修正**：`AsyncJsonWebsocket` 新增 `is_authenticated()`（按 `is_authenticated` 判，不看真值）
  与 `reject(code)`（先 `accept()` 再 `close`）；`task/ws.py`、`message/ws/{notify,consumers}.py`、
  `system/ws_monitor.py`、`dataset/ws_{screen,dashboard}.py` 六个 consumer 统一改用。
- **真实环境验证**（重启容器后直连 8896，无 Cookie）：`/ws/chat/` 与
  `/ws/message/default/admin` 均为 **OPEN(101) → close 4401**；修复前为握手 403。
- **测试**：`test_ws_consumers.py` 29 例，替身补 `is_authenticated`/`reject` 绑定，并新增
  `accepted is True` 断言（锁住「先 accept 再 close」）。插件示例注释同步二开口径。

### 10.4 FE-UI-P2-39（隐藏字段清空）

- **问题**：`hideInForm` 只控制渲染与布局，模型里旧值仍会被提交；后端 PATCH 语义是「未提交键

- **修正**：新增 `stripHiddenFormFields()`（`unref` 兼容 `true`/`computed`、支持嵌套 prop、

- **测试**：`hiddenFormFields.spec.ts` 6 例。
- **全量 E2E 打回并修正**：初版对静态 `hideInForm: true` 也删键，导致 `smoke 角色权限：编辑弹层回显授权树勾选` 超时失败——角色表单的 `fields` 列是**静态隐藏**，
  其提交值由页面 `beforeSubmit` 从授权树重建，被误删后授权丢失。修正为**只处理 `computed`
  （联动隐藏）形态**，静态隐藏仍由页面 `beforeSubmit` 决定；复跑 chromium/webkit 均通过。
