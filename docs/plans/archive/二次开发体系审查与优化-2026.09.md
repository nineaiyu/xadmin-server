## 二、体系现状盘点

### 2.1 架构与模块（已成型，无需改造）

- **三层职责**：业务 app → 工程层 `server/` → 内核 `common/`（依赖方向由 CI 门禁强制）；
- **模块划分**：内核（模型基类 / ViewSet 体系 / 元数据 / 权限 / 缓存 / 任务 / 配置 / 模块裁剪 / SDK）+ 业务 app（system / settings / message / notifications / mfa / captcha / demo）；
- **六层模块裁剪**（路由 / WS / 菜单 / 周期任务 / 种子 / 缓存）+ 三级分层（core/standard/optional）；
- **前后端咬合**：元数据协议 + 权限码 + 契约镜像（详见 [component-handbook.md](../../architecture/component-handbook.md) §4.3）。

结论：**架构层面本轮零发现**——分层、模块化、扩展点在既有方案（ADR-045/046、common/README）中已收敛。
