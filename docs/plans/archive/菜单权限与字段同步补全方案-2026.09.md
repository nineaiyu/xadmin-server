# 菜单权限与字段同步补全方案（2026.09）

| 项目 | 内容 |
|------|------|
| 文档性质 | 调研报告 + 整改方案（**建议稿**，改动前建议先评审口径） |
| 调研日期 | 2026-09-14 |
| 触发 | 用户反馈：①「有些菜单权限不够」②「字段权限没有同步」 |
| 调研范围 | 菜单侧「批量生成权限」（`MenuViewSet.permissions`）、字段管理侧「生成数据 / 重新生成字段」（`ModelLabelFieldViewSet.sync`）、两链路的运行时权限判定 |
| 方法 | 源码通读 + 容器内权威扫描（路由 × 权限点方法级比对）+ 非超管探针用户运行时复现（事务回滚，无残留） |
| 结论 | **两条链路都存在系统性缺口**：菜单权限点靠"手工登记/手工生成"，缺 91 个端点覆盖（其中 44 条非异步链、47 条异步导入导出链）；字段同步靠"手工点按钮"，当前生产库缺 `system.aiprofile`（AI 多档案）全量字段。二者都会导致非超管用户 403 或字段树不可见，且**现状不会被超管与 E2E 发现**（正式库仅 1 个超管账号）。 |

## 一、结论先行

1. **菜单权限缺口是真实的、可复现的**：以「拥有全部权限点的非超管用户」实测（2026-09-14，容器内）：
   - `POST /api/system/user/export-async` → **403**（导出弹窗勾选「异步」即失败）
   - `POST /api/system/user/import-headers` → **403**（导入弹窗第一步即失败，**全模块导入不可用**）
   - `GET /api/system/monitor/task-health` → **403**（监控页任务健康卡片）
   - `GET /api/system/dynamic-form-submissions` → **403**（我的填报整页）
   - 对照：`GET /api/system/user/export-data` → 200（同步导出有权限点）、`GET /api/system/menu/recycle` → 200。
2. **字段同步缺口是真实的**：`sync_model_field()` 只在**手工**点击「生成数据」（或管理命令）时执行，无 `post_migrate` 钩子；生产库 ROLE/DATA 字段树缺 `system.aiprofile`（今日新增的 AI 多档案模型，ROLE 根数 45 vs 有序列化器模型 46）。
3. **根因是机制性的**（不是漏了某几行配置）：
   - 权限点来源只有两条路——`loadjson` 种子（手工维护）与菜单页「批量生成权限」（**逐个菜单手工点**）；**没有任何自动同步/漂移守护**，新端点（尤其纯后端新增的异步链）天然漏登记；
   - 字段同步与之同构：**手工按钮制**，新模型/新字段在有人点击前一直缺席；且 `sync` 的陈旧清理依赖 `updated_time`，而 1298 行中 647 行为 NULL（种子导入不经 `save()`），清理逻辑实际失效。
4. **补全分两层**：数据层（一次性补齐 91 处覆盖 + 同步字段）+ 机制层（归一映射 / 漂移守护 / 自动同步），机制层才是防复发的关键。

## 二、机制现状（源码口径）

### 2.1 权限点与判定链

```
请求 → IsAuthenticated（common/core/permission.py:175）
  ├─ 超管 / PERMISSION_WHITE_URL 命中 → 放行（ignore_field_permission=True）
  ├─ get_user_permission(user, method)            # 按「角色 → 菜单(type=PERMISSION)」取 (path, method) 表，缓存 24h
  ├─ get_menu_pk(permission_data, url)            # ① 精确匹配 "{path}$"；② 退化为 re.match("/"+path, url)
  ├─ 未命中 → PermissionDenied（fail-closed）
  └─ _load_field_permission（PERMISSION_FIELD_ENABLED）→ FieldPermission(role, menu) → request.fields
      → BaseModelSerializer 初始化时按 request.fields 裁剪字段（默认拒绝）
```

要点：
- 权限点是**数据行**（`Menu.menu_type=PERMISSION`，含 `path`（正则）+ `method` + `model`（字段权限用）），不是代码声明；
- `get_menu_pk` 的**正则回退是顺序相关的**，会产生"意外放行"：实测 `GET /api/system/menu/recycle` 被 `api/system/menu/(?P<pk>[^/.]+)$` 形态之外的既有规则命中而 200，而同族的 `recycle/purge|restore`（多段路径）因 `[^/.]+` 不匹配而 403——**同一功能三个端点三种结果**。

### 2.2 菜单侧「绑定权限」（批量生成）

- 前端入口：菜单行 →「批量生成权限」抽屉（`useMenuPermissions.tsx`）→ 勾选视图 → `POST /api/system/menu/{pk}/permissions`。
- 后端：`MenuViewSet.permissions`（`system/views/admin/menu.py:142`）→ `get_view_permissions(view)`（`system/utils/menu.py:45`）逐个视图推导 `(method, url, code, description, models)` → `_save_permissions` 落库。
- **五处行为缺陷**（本次调研确认）：
  1. **逐菜单手工触发**，无「全量扫描」模式——新增 ViewSet/action 不会被发现；
  2. `models`（字段权限的模型绑定）**只给标准 CRUD 动作**（list/create/retrieve/update/partial_update），自定义 action 一律空；
  3. 已存在判定按 **name 全局查找**（`filter(menu_type=PERMISSION, name=...)`），不同父菜单下同名 code 会**跨菜单改写/搬移**；
  4. UI 默认 `skip_existing=true`，命中已存在即静默跳过——用户看到"生成成功"但实际可能一个都没加；
  5. 设计上**跳过 PUT**（`menu.py:93`），ViewSet 的 PUT 请求永久 403（前端只用 PATCH，属可接受设计，但需在文档中明示）。

### 2.3 字段侧「生成数据 / 重新生成字段」

- 前端：字段管理页「生成数据」按钮（`views/system/field/utils/hook.tsx:22`，code=`sync`）→ `GET /api/system/field/sync`。
- 后端：`ModelLabelFieldViewSet.sync`（`system/views/admin/modelfield.py:120`）→ `sync_model_field()`（`system/utils/modelfield.py:118`，事务包裹）：
  - `get_app_model_fields()`：遍历 `PERMISSION_DATA_AUTH_APPS`（当前 = `system/settings/notifications`）的模型 → 建 **DATA** 型「模型/字段」树（数据权限规则选择器用）；
  - `get_sub_serializer_fields()`：递归 `BaseModelSerializer` 全部子类 → 按序列化器 `fields` 建 **ROLE** 型字段树（角色页字段权限勾选用）；
  - 两者末尾都做「陈旧行清理」：`filter(field_type=..., updated_time__lt=now).delete()`。
- **四处缺陷**：
  1. **无自动触发**：无 `post_migrate`/启动钩子，新增模型与序列化器在人工点击前一直缺席（本次 `system.aiprofile` 即此情况）；
  2. **陈旧清理失效**：种子导入（`loadjson/modellabelfield.json`）的行 `updated_time` 为 NULL（`loaddata` 不走 `save()`），`NULL < now` 恒不成立——实测 647/1298 行为 NULL，被删字段/模型会长期残留；
  3. **无异常隔离**：`get_sub_serializer_fields` 对每个序列化器直接 `cls(ignore_field_permission=True)`，任一序列化器实例化异常将中断整个同步（事务回滚 → 页面只报错，无细节）；
  4. **无差异可见性**：页面没有任何「有 N 个模型/字段未同步」的提示，漏同步只能靠人发现。

### 2.4 字段权限消费链（供对照）

`FieldPermission(role, menu, field[])` → `get_user_field_queryset`（缓存 10s）→ `request.fields` → `BaseModelSerializer` 按 menu 绑定的模型裁字段。
**语义是 fail-closed**：新字段默认不可见是"设计内"，但"新字段未同步进字段树（连授权入口都没有）"是缺陷——两者用户感受相同，极易混淆。

## 三、实测证据（2026-09-14，容器内权威口径）

### 3.1 覆盖扫描

- 全量路由 **365** 条（`get_all_url_dict`，仅 `api/` 前缀）；权限点 **387** 条。
- 方法级覆盖扫描（Django resolver + 视图 `permission_classes` + 白名单 + PUT 口径）结果：**缺口 91 条**：
  - **异步导入导出链 47 条**（12 个模块：user/role/dept/menu/dict/mask-rules/permission/config-system/config-user/setting/field/online/logs）；
  - **非异步缺口 44 条**（明细见附录 A）。

### 3.2 运行时复现（临时"全权限非超管"探针，事务回滚无残留）

| 端点 | 结果 | 判定 |
|---|---|---|
| `POST /api/system/user/export-async` | 403 | ❌ 缺口（异步导出全模块不可用） |
| `POST /api/system/user/import-headers` | 403 | ❌ 缺口（导入全流程第一步即断） |
| `GET /api/system/user/export-data` | 200 | ✅ 同步导出正常（对照） |
| `GET /api/system/monitor/task-health` | 403 | ❌ 缺口 |
| `GET /api/system/menu/recycle` | 200 | ⚠️ 意外放行（正则回退顺序命中） |
| `GET /api/system/dynamic-form-submissions` | 403 | ❌ 缺口（我的填报） |
| `POST /api/system/webhooks/deliveries/batch-destroy` | 403 | ❌ 缺口 |
| `GET /api/system/approval-flows/{pk}/versions` | 403 | ❌ 缺口（流程版本历史） |
| `PATCH /api/system/user/1` | 400 | ✅ 权限通过（仅数据不合法） |
| `PUT /api/system/user/1` | 403 | 设计内（生成器跳过 PUT） |

### 3.3 字段同步现状

| 检查项 | 结果 |
|---|---|
| 有序列化器的模型 vs ROLE 根 | 46 vs 45 → **缺 `system.aiprofile`**（序列化器 `AiProfileSerializer` 已在） |
| DATA 根 vs 期望模型 | 48 vs 48，但**缺 `system.aiprofile`**（多出 `*` 为设计内"全部表"根） |
| 序列化器字段漂移（已注册模型） | 0（最近一次同步于 2026-09-14 00:45，之后新增的 AiProfile 未覆盖） |
| `updated_time` 为 NULL 的行 | **647 / 1298**（陈旧清理逻辑对这批行失效） |
| FieldPermission 现状 | 171 行 / 4 角色 / 87 菜单，无孤儿菜单、无未绑定模型行（数据面健康） |

### 3.4 为什么长期未被发现

- 正式库**只有 1 个用户（超管 xadmin）**——超管绕过权限链，所有 403 都不可见；
- E2E 亦以超管身份运行，覆盖不到受限视角；
- 缺口集中在"后加功能"（异步导入导出、监控卡片、版本回滚、投递审计、我的填报），非首批核心 CRUD。

## 四、补全方案

### 4.1 数据层：一次性补齐（1 天内）

| # | 项 | 动作 | 验收 |
|---|---|---|---|
| D1 | 字段树补齐 | 执行 `sync_model_field`（管理命令或「生成数据」）→ 补 `system.aiprofile` 等 | ROLE/DATA 根与序列化器/模型集合零差集 |
| D2 | 点状权限缺口（附录 A 44 条） | 分类处置：**补权限点**（约 20 条）/ **删除端点**（interval_schedule 3 条）/ **登记豁免**（前端不调用项，见 4.2 M2 清单） | 覆盖扫描非异步缺口清零（豁免项在清单内） |
| D3 | 异步链（47 条） | 走 4.2 M1 的归一方案（不逐条建种子）；若评审选择保守方案，则按模块补 4 条/模块 | 探针矩阵中导出（异步）/导入全链路 200 |
| D4 | 种子同步 | 全部改动先改 `loadjson/menu.json` + `menumeta.json`，再重灌（保证新库/正式库一致） | `load_init_json` 幂等；新库全覆盖 |

> 补齐缺口必须带**模型绑定**（`model` 字段），否则该权限点在角色字段树中无法配置字段白名单。

### 4.2 机制层：防复发（3 项，可独立交付）

#### M1（推荐）导入导出异步链权限归一

**问题本质**：一次导出/导入动作在前端被拆成多个端点（导出：`export-data` / `export-async`；导入：`import-headers` → `import-validate` → `import-async`），但权限点只登记了 `export-data` / `import-data`。为同一动作维护 4 套权限点（备选方案）会让角色授权树膨胀且新增模块再漂移。

**方案**：在权限解析链引入**同源动作归一映射**（新增显式映射表，失败时按映射回退，不改变 fail-closed 语义）：

| 请求端点 | 归一为 |
|---|---|
| `POST .../export-async` | `GET .../export-data` 权限 |
| `POST .../import-headers` / `import-validate` / `import-async` | `POST .../import-data` 权限 |

- 落点：`common/core/permission.py` 的 `_resolve_menu_pk`（归一候选 → 依次精确/正则匹配）；映射表常量集中定义、可守护测试枚举；
- 安全等价性：归一后的权限面与同步通道**完全一致**（能导出的才能异步导出，能导入的才能走导入链），无提权；
- 必须随附：越权矩阵新增 4 例（无 `exportData` 权限的用户调 `export-async` 仍 403 等）+ 守护测试（映射表完整性）；
- 备选方案 M1'（保守）：按模块生成 4 条/模块（约 47 条），显式可审计但维护面更大——**若评审倾向显式权限点，选 M1'**。

#### M2 权限点漂移守护（管理命令 + CI）

- 新增管理命令 `check_permission_seeds`：复用本方案的扫描逻辑（Django resolver 方法级 + 白名单 + 视图权限类 + PUT 口径），输出三类报告：
  1. **未覆盖端点**（需补权限点或登记豁免）；
  2. **冗余权限点**（未匹配任何路由，可能是改名/删除残留）；
  3. **CRUD 权限点未绑定模型**（字段权限无法配置的隐患）。
- CI 落地：新增 pytest 守护测试读取**显式豁免清单**（版本化在 `tests/` 或 `docs/`），清单外缺口即红；豁免清单初始口径：
  - AllowAny / 白名单族（登录、MFA、OAuth、PAT、api-docs）；
  - `PUT` 方法（生成器设计：ViewSet 用 PATCH）；
  - 前端不调用的端点（如 `notifications/*-subscription` 详情 GET/PUT、`settings/setting` POST、`field` POST 等——逐条登记理由）。

#### M3 字段同步自动化 + 缺陷修复

| 子项 | 内容 |
|---|---|
| 自动触发 | `system` app 注册 `post_migrate` 接收器调用 `sync_model_field`（幂等；开关 `SYNC_MODEL_FIELD_ON_MIGRATE` 默认开；异常只告警不阻断迁移；表不存在时跳过——首次 migrate 顺序安全） |
| 差异可见 | 字段管理页「生成数据」旁显示差异徽标（比对"代码侧模型/序列化器字段"与 DB，差异 >0 时提示"存在 N 项待同步"）；接口返回同步摘要（新增/更新/删除计数） |
| 缺陷修复 | ① 陈旧清理改"集合差删除"（以本次扫描到的 `(name,parent,field_type)` 全集反向删除，**不依赖 `updated_time`**，NULL 安全）；② 序列化器逐个 try/except 隔离，坏类记录日志并继续；③ `sync` 响应返回摘要供前端展示 |
| 单测 | 清理逻辑（含 NULL 行）、坏序列化器隔离、post_migrate 幂等、差异检测 |

### 4.3 明确不做（防误改）

- ❌ 不做"运行时自动放行未登记路由"——违背 fail-closed 红线；
- ❌ 不修改 `PUT` 403 语义（仅文档明示）；
- ❌ 不改变字段权限"新字段默认拒绝"的语义（改的是"新字段缺失授权入口"，不是默认值）；
- ❌ ~~不把 `interval_schedule` 补成权限点（无消费方，删端点）~~ → **2026-09-14 晚已反转**：改为补齐「间隔调度」管理页（端点恢复 + 页面 + 6 权限点 + 唯一性校验），见 §七·补记。

## 附录 B：体检脚本（每批次收口必跑）

```bash
docker exec -i xadmin-server sh -c "cd /data/xadmin-server && python manage.py shell" <<'PY'
import server.urls
import re
from django.conf import settings
from django.urls import resolve
from django.urls.exceptions import Resolver404
from common.core.utils import get_all_url_dict
from system.models import Menu

routes = [u for u in get_all_url_dict("") if str(u.get("url", "")).startswith("api")]
perms = list(Menu.objects.filter(menu_type=Menu.MenuChoices.PERMISSION, is_active=True,
                                 deleted_at__isnull=True).values_list("path", "method", "name"))

def sample(path):
    s = path.replace("[^/.]+", "1").replace("[^/]+", "1").replace("\\d+", "1").replace(".*", "x")
    s = re.sub(r"\(\?P<[^>]+>", "", s)
    return s.replace("(?:", "").replace(")", "").replace("?", "")

def white_ok(sp, method):
    return any(re.match(w, sp) and ("*" in ms or method in ms)
               for w, ms in settings.PERMISSION_WHITE_URL.items())

def covered(sp, method, url):
    exact = f"{url.rstrip('$')}$"
    for p, m, n in perms:
        if m != method:
            continue
        if p == exact:
            return n
        try:
            if re.match("/" + p, sp):
                return n
        except re.error:
            continue
    return None

for u in routes:
    url, name = u.get("url"), u.get("name")
    sp = sample("/" + url.rstrip("$"))
    r = cand = None
    for c in (sp, sp + "/"):
        try:
            r = resolve(c); cand = c; break
        except Resolver404:
            continue
    if r is None:
        continue
    cls = getattr(r.func, "cls", None)
    pcs = getattr(cls, "permission_classes", None)
    if pcs is not None:
        names = [getattr(c, "__name__", "") for c in pcs]
        if not pcs or any(n in ("AllowAny",) for n in names) or "IsAuthenticated" not in names:
            continue
    for method in (getattr(r.func, "actions", {}) or {}):
        m = method.upper()
        if m == "PUT" or white_ok(cand, m):
            continue
        if not covered(cand, m, url):
            print("GAP", m, "|", name, "|", url)
PY
```
