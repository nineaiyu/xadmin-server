## 一、背景

数据权限配置页重构（ADR-056）沉淀出一套可复用的页面规范：列表页一律 `RePlusPage`、新增/编辑走抽屉或统一弹层、
规则类复杂配置用「行内编辑卡片 + 可读摘要」、表单值以中文标签而非法名呈现。

随后对全站页面做了一次一致性评估，发现**同类页面存在两种做法**：已重构页面高度统一，而少数页面仍是
「手写表格 + 手写弹窗 + 内联表单 + 页面级样式」的旧形态；另有若干页面在**颜色/字号**上写死具体值，
主题与暗色模式下不跟随。本计划记录评估结论、重构清单、优先级与批次排期，作为后续实施的依据。

## 二、评估口径

### 2.1 基准规范（判断依据）

| 维度 | 基准 |
|------|------|
| 列表页 | `RePlusPage`（搜索区 / 表格 / 分页 / 列设置 / 行操作收敛一体化），页面侧只提供 `api`、`auth`、`addOrEditOptions`、`listColumnsFormat`、`operationButtonsProps` |
| 弹层 | 新增/编辑用 `addDialog`（ReDialog）或 `addDrawer`（ReDrawer）；**实体编辑禁止手写 `el-dialog` 外壳** |
| 表单 | 独立 `components/XxxForm.vue` + `getPayload()`（返回 `null` 表示保持弹窗） |
| 样式 | UnoCSS 原子类 + `var(--el-*)` 变量；页面级 `<style>` 尽量为空，不写死颜色 / 字号 / 圆角 |
| i18n | 全量 `t()`，zh / en 词条对称 |
| 行操作 | ≤5 个按钮，超出用「更多」收敛；复杂实体行操作走「管理」抽屉（`ReActionPanel` 模式） |

### 2.2 合理例外（不纳入重构）

1. **可视化自绘页**：看板（`dashboard`）、大屏投屏（`analysis/screen/display.vue`）、工作台图表、聊天室（`chat`）、
   AI 助手主界面（`integration/ai`）——非列表范式，栅格 / 画布 / 气泡布局是必然形态。
2. **只读展示层**：数据集执行预览、API 应用一次性密钥明文、`ScopeSelect` 这类**控件内选择弹窗**、
   各类预览抽屉（权限预览 / 试算结果 / 调用日志 / 访问记录 / 审批日志）。
3. **表单内子表**：审批节点编辑器、路由编辑、规则编辑、动态表单字段表、填报明细表等——它们是表单控件而非列表页。
4. **设置类页面**：`settings/basic`、`settings/ldap` 走 `SettingItem` + 后端 `search-columns` 通路，字段标签由服务端下发。

## 八、执行记录

### 批次一（2026-09-24）

**`form/my`（我的填报）**：列表迁 `RePlusPage`（新增 `utils/hook.tsx` 装配）。

- 顶部保留「可填表单」卡片区（填报入口，属选择表单语义，不进表格工具栏）；
- 提交数据（`data` JSON）不在后端 `table_fields` 中，由 `listColumnsFormat` 注入一列摘要（保持 `key: value` 形态，与详情抽屉及既有 E2E 断言同口径）；
- 状态列覆写为语义色 tag（字典色优先、缺省按 DRAFT/PENDING/APPROVED/REJECTED 兜底），无状态的提交显示「无需审批」而非留空；
- 个人页语义收敛：隐藏提交人列与对应搜索字段；
- 导出沿用**框架默认工具栏按钮**（`api.exportData` + 选中行/异步开关），不再自建导出入口；
- 行操作 5 个：详情 / 编辑（草稿态显示「继续编辑」）/ 提交 / 重新提交 / 删除；框架默认「编辑」「删除」按 `code` 关闭、默认「详情」用 `hideDetail` 关闭；
- 列表容器挂 `data-testid="my-submission-table"`，行内按钮与状态 tag 保留原 testid ⇒ 既有 `dform*.e2e.ts` **零改动**通过；
- 新增词条 `dform.form_name`（表单）、`dform.created_time`（提交时间）——RePlusPage 按 `dform.<字段名>` 取列标题。

**`settings/message`（消息模板）**：编辑弹窗由手写 `el-dialog` + 内联 `el-form` 改为 `addDialog` + 新组件
`MessageTemplateForm.vue`（`getPayload` 契约、内置预览按钮与预览结果区）；列表保留页签内轻量表格
（注册表非分页资源），补齐 `template-table` / `template-edit` / `template-reset` / `template-override-tag` 定位锚点。

**E2E**：新增 `e2e/form-my.e2e.ts`（卡片填报 → 框架列表：词条表头 / 分页 / 列设置 / 搜索 → 数据行 → 详情抽屉）
与 `e2e/message-template.e2e.ts`（编辑 → 预览 → 保存标记「已自定义」→ 重置回「代码默认」）；
回归 `dform.e2e.ts` / `dform-depth.e2e.ts` / `dform-flow.e2e.ts`，双浏览器全绿。

**验证**：typecheck / strict 全仓 / eslint / prettier / stylelint / i18n（zh/en 3001 对称）/ 行数 / vitest 464 /
build + 首屏闭包 546.9KB（预算内）；E2E 新增 2 条 + 既有 dform 3 条，chromium + webkit 均通过。

**经验（框架契约）**：

- 框架按钮（行操作与工具栏）**必须提供 `show`**：无 `show` 时 `Number(undefined)=NaN`，按钮被静默过滤；
- 自定义按钮的 `code` 不要与框架默认 `update` / `delete` / `detail` / `changeHistory` / `export` / `import` 冲突（按 `code` 去重，冲突时会顶掉默认按钮）；
- 列标题走 `localeName.<字段名>` 词条（覆写 `column.label` 在框架生成阶段会被 `formatPublicLabels` 结果优先，不生效）。
