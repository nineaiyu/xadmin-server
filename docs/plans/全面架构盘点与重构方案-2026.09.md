## 〇、总体结论

**健康度：良好偏优（B+/A-）。** 工程化成熟度显著高于同类开源 RBAC 项目：

- 后端 `TODO/FIXME/XXX/HACK` **零命中**（有历史清零记录）；`NotImplementedError` 与空 `pass` 全部位于抽象基类的 no-op 钩子；中文「降级」全部为有意的优雅降级——**没有靠注释掩盖的半成品**。
- 权限 fail-closed、缓存失效信号矩阵、字段权限掩码回写守护、契约 JSON Schema + 类型生成链路，以及成体系的文档/代码门禁（file-length / cross-app-import / doc-facts / doc-paths / doc-index / tutorial-mirror / bundle-size / i18n 对称 / strict TS）均真实生效。
- 测试：后端 unit 199 + integration 94 个测试文件（全量 2600+ 用例，覆盖率门禁 85%）；前端单测 + e2e 103 个 Playwright 文件（含 smoke/visual/perf/csp 专项）。
- 差异化资产：模块化裁剪（core/standard/optional + `XADMIN_APPS`）、CLI 代码生成器 `generate_crud`、开放平台（OAuth2 双 grant + 四级授权 + PKCE/refresh 轮换）、AI 动作注册表（约 60 个动作）与 MCP 端点、字段级权限 + 脱敏规则。

**主要短板集中在五处**（详见 §3 / §7；**P0 / P1 已于 2026-09-27 全部处置，P3.4 mypy 豁免清零同批追加，逐项结论见 §十**）：

1. **两处安全实现缺口**：接口文档登录开放重定向 + 账号锁定旁路（S-1）；出站请求 SSRF（Webhook / AI base_url，S-2）。
2. **`/media/` 直链无鉴权**，与后端「下载走受鉴权端点」的口径自相矛盾（S-3）。
3. **四个热点路径的性能天花板**：审批实例列表 N+1、会话列表 N+1、AI 用量逐行扫 JSON、通知未读 count（§3.1）。
4. **前端遗留死代码**：死菜单（system/task）、占位二维码登录页、demo/book 孤儿页、上游样板页（§2）。
5. **对标缺口**：表单/报表/大屏设计器、多租户、移动端——属产品决策项而非缺陷（§6）。

**与既有计划的关系**：本报告绝大多数问题面为既有计划**未覆盖**的新发现（既有计划抽查结论见 §8），两者互补而非重复。

### 跨模块共性问题

1. **检索统一走「朴素路径」**：全局搜索 `icontains`（`system/search.py:35-39`，pg_trgm 仅 PG 生效）；知识库词频评分全表扫描（`ai/utils/ai.py:246-259`）——数据量增长是共同天花板（知识库侧已有 ADR-037 重开条件）。

4. **demo 与 loadtest 混在发布物内**：demo 代码默认关闭但当前工作区显式启用；loadtest 为根目录工程代码。
5. **无「空壳 ViewSet/缺失 serializer」证据**：所有注册路由均有实现与测试；唯一自谦标注是 `open.py:3`「开放平台雏形」，但功能面（双 grant + 四级授权 + 配额 + 审计）实为完整。

## 三、四维诊断（证据 → 成因 → 方案对比）

### 3.1 性能

| # | 问题 | 证据（快照） | 成因 | 方案（对比） |
|---|---|---|---|---|
| P-1 | AI 知识库检索全表扫描：每问加载全部块并在 Python 内分词打分 | `ai/utils/ai.py:237-262`（`AiKnowledgeChunk.objects.all()`）；ADR-037 实测 535 块 / 平均 30.3ms | 零索引、O(全库块数×块长) CPU，每问重算；无向量/全文索引（ADR-037 决策维持词频检索，登记重开条件：hit@5<75% / 块数>1000 / P95>300ms） | a) 块级 token 缓存（进程内倒排，启动构建 + 增量维护，不改检索结果、零新依赖）；b) pg_trgm/GIN 在 DB 侧裁候选；c) ADR-037 触发条件命中后按既有预研（embedding + RRF → pgvector）升级 |
| P-2 | 审批实例列表 N+1 + 载荷膨胀 | `approval/serializers/approval_instance.py:176-180` 每行调 `biz_summary`（`approval/utils/approval_flow/biz.py:104-116` 按 biz_type 查业务表）；列表默认返回全字段（`common/core/modelset/base.py:122-127` 的 `fields` 投影为前端可选，前端未传），`tasks`/`form_schema` 一并序列化 | detail 语义字段被 list 复用；`comments` 有 retrieve 守卫而 `related_object` 没有 | a) `related_object` 加 action 守卫（沿用 `get_comments` 模式）；b) 列表按 `table_fields` 投影；c) 如需列表展示则按 biz_type 批量预取。a+b 最小 |

## 四、部署与工程链盘点

### 4.1 编排与镜像

- **开发即默认栈**（`docker-compose.yml`）：内部网络 `net`、nginx 1.31.5-alpine、postgresql 17.11（PITR/WAL gzip 归档）、redis 7.4.11、db-backup（RPO 6h，local/rsync/rclone 异地副本）、server、celery-worker、celery-heavy（重队列分治）、celery-beat。PG/Redis 端口不暴露宿主，密码 `redis-server --requirepass`。
- **生产 overlay**（`docker-compose.prod.yml`）：切生产 Dockerfile（代码烘焙、非 root 1001、无源码 bind mount）、`volumes: !override`、要求 compose ≥ 2.24.4。
- **镜像**：server 多阶段（`nineaiyu/xadmin-server-base:20260924_023937` → `python:3.14.7-slim`，构建期编译 `.mo` 语言包，`EXPOSE 8896`）；`Dockerfile-base`（uv 0.12.5 + 国内镜像源）；client 多阶段（`nineaiyu/xadmin-client-base:20260926_144118` → `pnpm build` → nginx 1.31.5-alpine）；`Dockerfile-web` 为独立网关镜像（acme/socat）。
- **运行入口**：gunicorn + `uvicorn_worker.UvicornWorker`（ASGI）；`manage.py start/stop/status` 进程管理；`xadmin-server/xadmin.sh` 为 compose 管理入口（start / restart / stop / close / status / down / init_data / help）。

### 4.2 凭据链路

`config.yml` 为**唯一定义处** → `utils/compose_env.sh` 自动维护 `.env` 派生缓存 + 进程内 export → compose `${DB_PASSWORD:?}` / `${REDIS_PASSWORD:?}` 强制注入（裸 `docker compose` 也不会拿到空密码）。`config.yml` 与 `.env` 均不进 git；`config_example.yml` 只含占位符 + 轮换指引（`JWT_SIGNING_KEY` / `FIELD_ENCRYPTION_KEY` / `FIELD_ENCRYPTION_LEGACY_KEYS`）。

### 4.3 网关（xadmin-web）

CSP **强制头**（`script-src 'self'`，2026-09-18 由 report-only 切换；三处同源守护）+ 安全头统一 server 级下发 + `/static/` 一年 immutable + `index.html`/`platform-config.json` no-cache（防发版后引用已删 chunk 白屏）+ HSTS 注释化（与 Django 侧 `SECURITY_HTTPS_ENABLED` 三态口径一致）+ CSP report-uri `/api/common/api/csp-report`。**问题项**：`^~ /media/` 直链（S-3）。

### 4.4 数据与备份

PG 17.11 + PITR（WAL gzip 归档，已完成时间点回放演练，RTO < 1s）；`db-backup` 服务 RPO 6h、本地 + 异地副本（rsync/rclone）；工作区根 `xadmin-db-backups*` 为备份落盘目录（不在 git）。

### 4.5 CI 与质量门禁

`.github/workflows/`：lint.yml（ruff / mypy / 契约同步 / 前端 typecheck(strict) / eslint / i18n 对称 / bundle 预算）、test.yml（`pytest -n auto --cov-fail-under=85`）、security.yml、perf.yml、build-image.yml、build-base-image.yml、backup-drill-reminder.yml、renovate.yml。已知挂起项：renovate.yml 仅在 dev 分支，非默认分支 dispatch 404 / cron 不生效（维护者决定下次发布窗口合 main，见 `docs/plans/README.md`）。

### 4.6 契约同步链

`docs/schema/` 5 份 JSON Schema（服务端唯一真源）→ `xadmin-client/contract/schema/` 镜像 → `pnpm sync:contract` + `gen:metadata-types` 生成 `src/api/types/*.d.ts` → CI 重生成 diff 拒手改。E2E 独立端口 18896（避本机 compose nginx 8896）。

### 4.7 部署注意项

1. 工作区 `config.yml` 为本地开发态（DEBUG: true、`HTTP_BIND_HOST: 0.0.0.0`），**不得直接用于生产**；生产按 `docs/ops/deployment.md` 走 prod overlay + 环境变量。
2. S-3（/media 直链）是部署面与安全面的交叉项，建议随 P0 一并处置。
3. CSP 策略串三处同步（nginx / csp-page-server / Django），改策略需三处一起改（已有守护测试）。
