## 五、方法论沉淀（本规划期被验证有效的做法）

1. **E2E 环境固化的乘数效应**：sqlite+FakeRedis+eager+种子脚本（零外部依赖、单命令 `pnpm test:e2e`）让 E2E 成为每日回归工具，其价值远超 CI 门禁本身——阶段 3 的 4 处漂移与 eager 状态 bug 全靠真实环境暴露。
2. **契约先行**：元数据 JSON Schema + 前后端类型生成 + regen CI 门禁（T2.3）为后续重构提供了漂移雷达；ADR-003/007 同思路。
3. **"先补测试再动手"**：BaseModelSet 拆分前 22 例边界护航测试、越权矩阵先行，重构与安全整改零回归。
4. **环境教训**：本机 compose（8896）与 E2E（18896）端口隔离、`reuseExistingServer` 的误复用坑、k6 的 zsh USERNAME 魔法参数、sqlite WAL 并发——均已入内存/文档。
5. **根因修复优先**：eager `send_task` 无效这类"测试期望值与框架语义不符"的问题，先读 celery 文档确认语义再修 dispatch 层，避免在断言层打补丁。
