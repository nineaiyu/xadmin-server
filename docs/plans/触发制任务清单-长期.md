## 一、开发任务类触发项（触发即立项，先 ADR）

### TG-1 ⏸ O11-2：JSONField 慢查询逐一物化索引

- **是什么**：全项目约 88 处 `JSONField`，目前仅 `dataset/models/dform.py:106` 的 `filter_data` 有 GIN 物化索引（ADR-075 交付），其余均属受控查询。
- **触发条件**：生产出现真实慢查询，且定位到具体某个 JSONField 的查询路径。
- **触发后动作**：按命中字段逐个建 GIN / 表达式索引并配守护测试；**明确禁止**预防性全量物化。
- **依据**：NEXT-DEV-PLAN §一 O11-2。
- **复核**：2026-10-03（随 TG-2 抽样窗口）——触发条件未命中（无慢查询登记，静态计数 89 处与台账口径一致），维持 ⏸。

### TG-2 ✅ O11-3：N+1 查询抽样定位（2026-10-03 已收口，见 §六）

- **是什么**：85 处 `SerializerMethodField` 中，非 modelset 基座的定制序列化器不在框架自动 prefetch 覆盖内（框架防线见 `common/core/modelset/base.py:36-122` 自动推断）。
- **触发条件**：借 `SQLCountMiddleware` 抽样实测，抓到某端点每请求 SQL 数异常。
- **触发后动作**：对定位到的序列化器补 `select_related` / `prefetch_related` 或改取数方式；实测未见缺口前不盲改。
- **收口摘要**：实测工具沉淀 `scripts/sql_sampling.py`（双页宽斜率口径，URLconf 自动发现）；29 端点实测命中 1 处 N+1（approval-flow 列表逐行 EXISTS），已修 + 守护测试 4 例，复测归零；详见 NEXT-DEV-PLAN §五 记录十一。

### TG-3 ✅ O11-4：物理表名与 app 拆分不一致（2026-10-03 已收口，见 §六）

- **是什么**：模型已拆多 app（ai / approval / dataset…），物理表名仍冻结在 `system_*`（`ai/models/ai.py:51` 等 `db_table`），属迁移期兼容保留。
- **触发条件**：专门评估立项（典型场景：真做多库拆分 / 表归域时顺带）。
- **触发后动作**：`RENAME TABLE` 专门迁移 + 视图 / 存储过程 / 外部 SQL 兼容期 + 回填守护；**重命名成本高，非专门立项不做**。
- **依据**：NEXT-DEV-PLAN §一 O11-4。
- **收口摘要**：ADR-080——25 模型 + 3 张自动 m2m 中间表回落 Django 默认归域名（`<app>_<模型小写>`，Meta 不再持显式 db_table），各 app 单迁移 `AlterModelTable`（PG 元数据级、单事务、连带 m2m）；外部 SQL 排查无消费者（全仓无视图/存储过程/触发器/raw SQL），不设兼容视图，代码内 DDL 助手表名单源化（`ai_vector_ddl._chunk_table()`）；trgm 迁移快照经 approval/0005 `TRGM_TABLE_RENAMES` 折算对账；新增守护 `test_table_domain_alignment.py` 3 例；存量升级模拟 + 全新链重放 + 全量 pytest 通过；详见 NEXT-DEV-PLAN §五 记录十二。
