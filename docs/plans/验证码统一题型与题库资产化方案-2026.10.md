## 〇、一句话结论

图片码与交互码今天仍是两套协议、两套存储、两套观测：**图片码不经过票据、风险分级、动作绑定与 `CaptchaLog`**。
所以第一批不是「把题出得更难」，而是**把图片码变成交互码题型注册表里的一个 `image` 题型**，
让所有题型共享同一条 `challenge → verify → ticket → consume` 链路；第二批才是题库资产化
（背景图库、繁体字、图标点选）与按题型/资产度量的运营闭环。

## 一、直接回答三个问题

### 1. 图片验证码能否合并进交互验证码？

**能，且建议第一批就做。** 做法是把 `image` 实现为 `ChallengeBackend` 题型：

- 生成：复用现有 `captcha.helpers` 的算式/随机字符与 `captcha.views.render_challenge`；
- 校验：答案只进 Redis 挑战密文（不落 DB 明文），`verify` 通过后签发与交互题**同一种 ticket**；
- 消费：业务侧只认 `captcha_ticket`，不再区分 `captcha_key/captcha_code`；
- 回退：无障碍「使用图片验证码」不再是切模式，而是重新请求 `type=image` 的同一挑战；
- clean cut：项目未上线，**直接删除**旧 `CAPTCHA_MODE=image`、`GET /api/identity/auth/captcha`、
  `CaptchaStore` 与 `captcha_key/code`；旧前端/第三方无兼容义务，上线前必须迁移到 ticket。

不建议把 `image` 直接放进随机出题池：图片字符码是可 OCR 的弱题型，它的正确定位是
**无障碍回退 + 低风险兜底**，默认权重 0，只在用户显式选择或风险层判定需要时出题。

### 2. 是否需要图片库、繁体字、更复杂图案？

**需要，但目的不是「更难」，而是「更难被批量枚举 + 可运营地轮换」。** 大厂的做法可以拆成三层：

| 层 | 大厂事实 | 对我们的含义 |
|----|----------|--------------|
| 题型多样 | 极验行为验提供一点即过、滑动、图标点选、文字点选、语序点选、空间推理、九宫格等 8 种；网易易盾行为式支持智能无感知、滑动、文字/图标点选、推理拼图、语序点选、空间推理、躲避障碍、语音等 11 种 | 我们的 slide/rotate/click/wordorder/pow 只是及格线；图标点选是性价比最高的下一题型 |
| 图集热更 | 极验公开文章明确把「图集数量热更」作为图标点选防遍历的关键，并会按攻击形态切换验证形式 | 背景图、图标、字体的**版本化与轮换**比单题难度更重要；资产要有来源、许可、哈希与版本 |
| 风险分级 | 无感、滑块、点选按风险动态切换，而不是所有人做同一道题 | 我们已有 `off/shadow/enforce`，但图片码是盲区；合并后风险层才能覆盖全部流量 |

图片库与繁体字的具体取舍：

- **背景图库**：值得做。仅靠 12 组程序化渐变，滑块/旋转题的纹理熵不足，模板匹配成本低。
  建议引入 **CC0 / 自绘** 的轻量图库（WebP，640×360，单张 30~80KB，30~60 张，总量 2~5MB），
  随机裁切 + 调色 + 噪点叠加；旋转题优先选有明确地平线/天空/建筑方向的图。
- **繁体字**：可以做，但应作为**可选字符集**（`simplified` / `traditional` / `mixed` / `ascii`），
  默认简体。繁体字对 OCR 更不友好，但对不熟悉繁体的用户会抬高真人成本；`mixed` 应
  **整题统一脚本**（一道题要么全简要么全繁），不要逐字混排。字体用 OFL 的 Noto Serif TC /
  Noto Sans TC 子集，并做字形覆盖检查。
- **图标点选**：值得做。用 Apache-2.0 的 Material Symbols 图标字体做「提示条 3 个图标 →
  图中按序点选」题型，不需要二进制图片包，复用点选题的绘制/命中基座；但图标语义可被多模态
  模型识别，定位是**题型多样性 + 图集轮换**，不是绝对安全。
- **不建议现在做**：3D 旋转、九宫格 AIGC 图集、刮刮乐、短信上行验证码。成本/收益不匹配，
  且会显著增加资产与合规负担。

### 3. 企业级加强方案是什么？

三条轴，按优先级：

1. **协议轴（第一批）**：图片码并入统一票据与风险层；所有题型共享 `(scene, action)` 绑定、
   一次性 nonce、分档 TTL、`CaptchaLog` 观测。直接消灭「图片码流量在风控视野外」这个最大盲区。
2. **资产轴（第二批）**：背景图库 + 多字体 + 图标字体 + 资产清单/许可/哈希/版本 +
   每资产通过率度量 + 热轮换。让「换一套题」成为运营动作，而不是发版动作。
3. **运营轴（第三批）**：按题型/资产的通过率 SLO、挑战-校验比、放弃率、音频滥用、
   指纹-IP 扩散等指标；影子期基线 → 灰度 enforce → 异常自动降权/建议下线 → 告警与 runbook。

## 三、业界对标（2026-10 复核）

| 产品 | 题型/形态 | 可借鉴 | 不可照搬 |
|------|-----------|--------|----------|
| 极验行为验 | 一点即过、滑动、图标点选、文字点选、语序点选、空间推理、九宫格等 8 种；按风险切换；图集可热更 | 题型按风险分层；图标点选 + 图集热更；「换题型」是运营动作 | 云端行为数据与商业图集 |
| 网易易盾 | 智能无感知、滑动、文字/图标点选、推理拼图、语序点选、空间推理、障碍躲避、语音等 11 种；宣称读屏适配 | 无障碍作为产品能力；语音验证码；题型矩阵 | 云服务依赖 |
| hCaptcha | 九宫格二分类、区域点选、框选、拖拽对齐、视频帧选择 | 任务形式多样；难度按任务动态调整 | 依赖海量标注图库与 ML 管线 |
| Cloudflare Turnstile | 无感挑战 + 一次性短命 token | 无感优先；token 一次性、短 TTL | 云端判定 |
| 开源 tianai-captcha / AJ-Captcha | 滑块、旋转、滑动还原、文字/图标点选、语序、PoW | 插件化题型 + 两段式票据（我们已采用） | 资产与运营体系较弱 |

**结论**：大厂的护城河不是「某一道题更难」，而是**题型矩阵 + 风险分级 + 资产热更 + 数据闭环**。
我们能自建的是后三项中的资产与数据闭环，风险分级已有基座；不应把预算押在「把字画得更扭曲」上。

## 四、目标与非目标

**目标**

1. 图片码并入统一协议：共享票据、动作绑定、风险决策、`CaptchaLog`、失败阶梯与大盘；
2. 题库资产化：背景图库、简体/繁体/多字体、图标字体，资产有清单、许可、哈希、版本；
3. 可运营：按题型/资产的通过率、放弃率、挑战-校验比、音频使用率可视化；异常可降权/下线；
4. 可回退：上线前 clean cut 只保留统一协议，删除旧图片码模式/端点/DB 链路；回滚靠镜像版本，不靠运行时兼容层；
5. 零新增运行时云依赖：资产随包/挂载，Pillow + 字体即可，不引入 CV/ML 运行时。

**非目标**

- 不接极验/易盾/天御/reCAPTCHA/Turnstile 等云验证码；
- 不做 3D/九宫格 AIGC/刮刮乐/短信上行；
- 不做用户上传图库（供应链与版权风险），只支持随包资产或只读挂载目录；
- 不训练 ML 模型；不做「按资产自动生成难度」的黑盒；
- 不改短信/邮箱验证码链路。

## 五、目标架构

```
统一协议（唯一路径；CAPTCHA_ENABLED 为总开关）
  challenge(type = image | slide | rotate | click | wordorder | icon | pow)
        │
        ├─ 资产层：background pack / font pack / icon font（manifest + license + sha256）
        ├─ 题型层：ChallengeBackend 注册表（generate / verify / difficulty）
        ├─ 决策层：RiskEngine（所有题型，含 image）
        ├─ 票据层：HMAC ticket + (scene, action, sid, fp, aud) + nonce + 分档 TTL
        └─ 观测层：CaptchaLog(type, asset_id, input_mode, ...) → 大盘 / 告警
  已删除：CAPTCHA_MODE、旧图片码端点、CaptchaStore、captcha_key/code、ReImageVerify
```

核心变化只有一句：**`image` 从「模式」降级为「题型」，旧模式不复存在**；上线前 clean cut，
没有 `CAPTCHA_MODE`，也没有旧图片码链路可回退。

## 六、详细设计

### 6.1 图片码并入统一协议

**后端**

1. 新增 `captcha/backends/image.py`：
   - `type = "image"`；
   - `generate(difficulty)`：`get_challenge()()` → `render_challenge()` → `png_data_uri()`；
     `secret = {"answer": response.lower(), "audio_text": challenge, "asset_id": "builtin-image"}`；
   - `payload = {"background", "width", "height", "length", "audio": bool(CAPTCHA_FLITE_PATH)}`；
   - `verify(secret, answer, difficulty)`：接受 `{"code": "..."}` 或字符串，`secrets.compare_digest` 比较，
     不做轨迹校验；
   - 注册进 `captcha/backends/__init__.py`。
2. `CAPTCHA_TYPES` 增加 `"image"`；`CAPTCHA_PUZZLE_TYPES` 不加入（图片码不进随机池）；
   `CAPTCHA_TYPE_WEIGHTS` 默认 `image: 0`。
3. `flow.pick_type`：
   - 显式 `requested == "image"` 且 `CAPTCHA_IMAGE_FALLBACK_ENABLED`（或 `image` 在启用题型内）→ 允许；
   - `hard` 决策永不选 `image`；`challenge/light` 的随机池过滤 `weight=0` 的题型；
   - 若池为空，回退 `click`，避免出题失败。
4. `services.InteractiveCaptcha.challenge`：`types` 允许包含 `image`；`_answer_passed` 对
   `image` 跳过 `validate_track`；`verify` 的 `input` 允许 `keyboard`（输入验证码）。
5. 音频：新增 `GET /api/identity/auth/captcha/audio/{challenge_id}`（匿名、每 IP 限流、仅 `image` 题型），
   从 Redis 读取 `audio_text` 并复用现有 `flite/sox` 合成；返回 200/206/416 与现有音频端点同口径。
   该端点只读，不进入 `check_captcha_coverage` 的匿名写端点扫描面。
6. 旧端点删除：`GET /api/identity/auth/captcha`、`captcha-image`、`captcha-audio`、`captcha-refresh`
   与 `CaptchaAuth` / `CaptchaStore` 一并移除；旧路由 404 由 `check_captcha_legacy.py` 守护。
7. `doctor` 增加检查：旧路由仍挂载 / 旧模型仍存在 / inspect 路由存在 / 资产哈希不符 → 报错；
   强绑定、密钥、默认 enforce 的检查见姊妹篇安全硬化细则。

**前端**

1. 新增 `ReImageCaptcha`（或复用 `ReImageVerify` 的展示壳，改为接收 `challenge.background`）：
   图片 + 输入框 + 音频按钮 + 刷新；提交 `{ code }`，输入方式标记 `keyboard`。
2. `ReCaptchaBody` 增加 `image` 分支；`ReCaptchaPanel` 类型分发增加 `image`。
3. `ReCaptchaChallenge` 的「使用图片验证码」改为：
   `loadChallenge({ type: "image" })`，仍走同一 ticket 流程；删除 `fallbackImage` 切模式逻辑。
4. `CaptchaAnswer` 联合类型增加 `{ code: string }`；`CaptchaType` 增加 `"image"`、`"icon"`。
5. `capabilities.basic.captcha_image_fallback` 语义改为「`image` 题型是否可用」；
   删除 `CAPTCHA_IMAGE_FALLBACK_ENABLED` 的旧模式含义。

**Clean cut（项目未上线，无兼容层）**

| 项 | 处理 |
|----|------|
| `CAPTCHA_MODE` / `image` 模式 | 删除；统一协议是唯一路径 |
| 旧图片码端点（`auth/captcha`、`image/audio/refresh`） | 删除；旧路由 404 |
| `CaptchaStore` / `CaptchaAuth` / `captcha_key/code` | 删除；只保留 `captcha_ticket` |
| `ReImageVerify` / 旧图片表单字段 | 删除；六个消费点统一 `ReCaptchaChallenge` |
| 旧前端/第三方客户端 | 无兼容义务；上线前必须迁移到 ticket |

### 6.2 题库资产化

**资产目录与清单**

```
captcha/resources/
  backgrounds/
    manifest.json          # id / file / license / source / sha256 / category / orientation
    photo/*.webp           # 640x360，30~60 张，CC0 或自绘
  fonts/
    NotoSansSC-Captcha.ttf # 现有简体子集
    NotoSerifTC-Captcha.ttf# 新增繁体子集（OFL）
    MaterialSymbols-Captcha.ttf # 图标字体子集（Apache-2.0）
    NOTICE.md / OFL.txt / LICENSE
  icons/
    manifest.json          # codepoint / name / category / style
```

- 资产只读；支持 `CAPTCHA_ASSET_DIR` 挂载自定义目录（企业替换图库），启动时校验 manifest；
- **禁止用户上传**：避免 SSRF、恶意图片、版权与供应链问题；
- 图片统一 WebP、剥离 EXIF/GPS、无人脸；`scripts/check_captcha_assets.py` 守护
  「许可白名单 / 文件大小 / 哈希 / 重复 pHash / manifest 完整」；
- 资产 `asset_id` 只进服务端 `secret` 与 `CaptchaLog`，**不下发客户端**，避免被按资产定向训练；
- 每资产版本号 + 哈希；换图 = 换 manifest 版本，可回滚。

**生成器改造**

- `art.py`：`make_background()` 优先从图库随机取图，随机裁切/缩放/调色/叠加噪点；
  无图库时回退现有程序化渐变（升级零变化）；
- `make_orientation_scene()`：旋转题优先选 `orientation=landscape/building` 的图，
  保留地平线/太阳的语义；无合适图时回退程序化场景；
- 点选题：背景图降低局部对比度，保证字形区域对比度阈值；必要时加半透明遮罩；
- 性能：解码后的图片按进程内 `lru_cache` 缓存；单题生成 P95 目标 < 150ms；
  启动时预热少量图片，避免首屏抖动。

**字体与字符集**

- `CAPTCHA_CLICK_CHARSET` 扩展：`simplified`（默认，等同现 `chinese`）、`traditional`、
  `mixed`、`ascii`；
- `CAPTCHA_CLICK_FONT_PATHS` 支持多字体；每题随机字体，`mixed` 按题选择简/繁脚本，不逐字混排；
- 繁体子集取 Big5 常用字（约 4808 字），与简体子集分开；启动检查所选字符集是否被字体覆盖，
  缺失即 `ImproperlyConfigured`（沿用现有 fail-fast 风格）；
- 字形扰动增强：随机透视/仿射、笔画粗细（若字体支持）、局部遮挡线、轻噪声；
  以「真人首次通过率」为准，不追求视觉上更扭曲。

**图标点选题型**

- 新增 `captcha/backends/icon.py`，复用 `WordClickBackend` 的布局/命中基座；
- 提示条渲染 3 个图标，图中放 3 个目标 + 3 个干扰（同类目、同风格），按提示顺序点击；
- 图标字体用 Material Symbols 子集，随机旋转/缩放/颜色；干扰项与目标同风格，避免一眼分类；
- 默认权重 0，设置页可开启；`hard` 决策可按权重选它，但需先有通过率基线；
- 无障碍：图标题不可键盘完成，保留图片/语音回退；不把它作为唯一题型。

### 6.3 题型、难度与风险

**题型权重**

- `CAPTCHA_TYPE_WEIGHTS` 默认：`slide 30 / rotate 30 / click 30 / wordorder 10 / icon 0 / image 0 / pow 0`；
- `image` 与 `icon` 默认不进随机池，但允许显式请求（回退/预览）；
- `hard` 决策优先 `wordorder`，其次 `click/icon`，**永不** `image`；
- 同指纹短窗防重复保留；后续可加「每 N 次最多一次难题型」的配额（本期不做）。

**风险规则新增（全部可 DB 配分/开关）**

| 规则 | 判据 | 建议分 |
|------|------|--------|
| `freq_ip_fp_spread` | 同 IP 10min 内不同指纹 > 5 | +25 |
| `freq_fp_ip_spread` | 同指纹 10min 内不同 IP > 5 | +30 |
| `challenge_abandon` | 同 IP 10min 挑战/校验比 > 5 | +20 |
| `type_fixation` | 同 IP 10min 内 > 90% 请求同一题型 | +15 |
| `audio_abuse` | 同 IP 10min 音频请求 > 20 | +20 |
| `ticket_velocity` | 同 IP+action 1min 消费 ticket > 5 | +20 |
| `sec_fetch_mismatch` | 声称浏览器但缺 `Sec-Fetch-*` 或与 `Origin` 矛盾 | +10 |
| `challenge_wallclock` | 非 PoW 题 challenge→verify < 300ms | +15（基线后启用） |

- 新增规则沿用 `CaptchaRule` 表与现有评分函数，不引入表达式引擎；
- 图片回退默认要求低难度 PoW（`CAPTCHA_POW_FOR_IMAGE_FALLBACK=true`），
  防止图片码成为 OCR 农场入口；allow/light 与音频路径不受影响，读屏用户仍可完成；
- `risk_active()` 不再依赖模式，统一协议下恒运行；图片题按 `input=keyboard`
  跳过轨迹规则，但保留环境/频率/历史信号。

**处置**

- 复用现有三维度失败阶梯、冷却、蜜罐、登录锁定联动；
- 新增「题型级降权」：某题型/资产在窗口内通过率 > 98% 且样本 ≥ 100 → 大盘标红并建议降权；
  可选 `CAPTCHA_AUTO_DISABLE_ENABLED`（默认 false）自动移出随机池 24h，避免误伤时自己把题下光；
- 告警接既有通知渠道：通过率异常、挑战-校验比异常、音频滥用、同指纹 IP 扩散。

### 6.4 观测与运营

`CaptchaLog` 增字段（新迁移）：

| 字段 | 说明 |
|------|------|
| `asset_id` | 资产/图集 id（不含客户端可见信息） |
| `input_mode` | `pointer` / `keyboard` / `audio` |
| `challenge_ms` | 出题耗时（可选，服务端生成耗时） |
| `abandoned` | 由挑战/校验比聚合得出，不一定落单条日志 |

大盘新增：

- 按题型 × 难度的通过率、P50 解题时长、尝试次数分布；
- 按资产的通过率与样本量（资产健康表：active / watch / disabled）；
- 挑战-校验比、放弃率、音频使用率、图片回退率；
- TopN 拒绝原因 / IP 段 / 指纹 / UA（已有，补充 `asset_id` 维度时注意基数）；
- 影子期 `would_decision` 继续作为有效决策参与聚合。

SLO（建议初始值，按真实基线校准）：

| 指标 | 目标 |
|------|------|
| 真人首次通过率（桌面） | ≥ 85% |
| 真人首次通过率（移动） | ≥ 80% |
| 中位解题时长 | ≤ 10s |
| 放弃率 | ≤ 2% |
| 单题生成 P95 | ≤ 150ms |
| 验证接口 P95 | ≤ 300ms |

任何题型连续 3 天低于 SLO 或高于「被打穿」阈值，降权/下线并复核。

### 6.5 设置页与配置

**模式与页签**

- 总配置：删除 `CAPTCHA_MODE`，只保留总开关 `CAPTCHA_ENABLED` + 场景开关；
- 「交互式验证码」页签改名「题型与难度」：题型开关 + 权重 + 难度 + 字符集 + 字体 + 图库；
  图片题型设置复用现有「图片验证码」页签字段；
- 「图片验证码」页签保留，标注「图片题型参数（无障碍回退）」；
- 新增「题库资产」只读页签：图库/字体/图标包列表（版本、许可、来源、大小、哈希、状态），
  提供「刷新资产缓存」按钮（管理员权限），不做上传；
- 「验证数据」页签增加题型/资产健康表与 SLO 达成情况。

**新增配置键（单源 `server/conf/settings_defaults.py` + `FORWARD_KEYS`）**

| 键 | 默认 | 说明 |
|----|------|------|
| `CAPTCHA_CLICK_CHARSET` | `simplified` | 新增 `traditional` / `mixed`；`chinese` 作为 `simplified` 别名 |
| `CAPTCHA_CLICK_FONT_PATHS` | 内置两个字体 | 多字体随机 |
| `CAPTCHA_BACKGROUND_PACK` | `builtin` | 图库包 id；`procedural` = 仅程序化 |
| `CAPTCHA_ASSET_DIR` | 空 | 只读挂载目录（企业自定义图库） |
| `CAPTCHA_ICON_FONT_PATH` | 内置图标字体 | 图标题依赖 |

| `CAPTCHA_POW_FOR_IMAGE_FALLBACK` | True | 图片回退必须付低难度 PoW（防 OCR 农场）；可关 |

**权限与种子**：新增资产只读视图权限 `list:SecurityCaptchaAsset`，落 `settings/seeds/{menu,menumeta}.json`；
`sync_menu_permissions --dry-run` 缺口 0；视图 docstring 首行 ≤ 24 字。

### 6.6 契约与 clean cut

- `CAPTCHA_TYPES` 增加 `image` / `icon`；`CaptchaChallengeOut` 增加 `length` / `audio`；
  `CaptchaAnswer` 增加 `{code}`；
- `capabilities.basic` 增加 `captcha_unified: true`（中性字段，不泄露风险决策），
  `captcha_image_fallback` 改为 `image` 题型可用性；
- 新增 `GET /api/identity/auth/captcha/audio/{challenge_id}`；
- 先改 `docs/schema/` → `dump_openapi` → 前端 `pnpm sync:contract` → 契约四件套；
- **Clean cut（项目未上线）**：删除 `CAPTCHA_MODE`、旧图片码端点、`CaptchaStore`/`CaptchaAuth`、
  `captcha_key/code`；`image` 仅作为题型；旧路由 404 由 `check_captcha_legacy.py` 守护；
- server/client 同批发布；无存量库迁移表演；`CaptchaStore` 走 `DeleteModel` 迁移；
- 回退靠上一版镜像，不保留运行时旧模式；发布说明写清旧客户端必须先迁移到 ticket。

### 6.7 无障碍与合规

- 图片题型 = 视觉回退；音频端点必须真的可用（现状已内置 `flite/sox`）；
- 图标/点选/滑块不可键盘完成 → 统一提供「切换图片码」；图片码支持键盘输入 + 音频；
- `allow/light` 路径读屏可完成，成功状态 `aria-live`（已有）；
- 繁体/图标字符集按题统一，避免同一题混排造成阅读困难；
- 资产合规：只收 CC0 / OFL / Apache-2.0 / 自绘；manifest 记录来源与许可；图片剥离 EXIF；
- 隐私：`CaptchaLog` 不落原始环境包/轨迹；资产 `asset_id` 只用于内部度量。

## 七、测试与验收

**单测**

- `image` backend：生成尺寸/通道/答案不出现在 payload；`verify` 大小写/空格/类型异常；
  音频文本存在；`track` 跳过；`image` 在 `hard` 下不被选中；显式 `type=image` 可用；
- 资产：manifest schema、许可白名单、哈希、pHash 去重、字体覆盖检查、繁体/简体/mixed 选字；
- `icon` backend：目标/干扰数量、顺序校验、命中半径、难度缩放；
- 风险新规则：逐条命中/未命中/关闭三态；`challenge_abandon` / `type_fixation` 的窗口计数；
- clean cut：旧路由 404、旧字段不在 OpenAPI、`CaptchaStore` 表不存在；
  `check_captcha_legacy.py` 对旧符号复现即失败。

**集成**

- 统一链路：`challenge(image) → verify → ticket → 登录`；
- 旧链路：`GET captcha → captcha_key/code → 登录` 不变；
- 音频端点 200/206/416、限流、非 image 题型 404；
- `enforce` 下 allow 无题直过、hard 出 wordorder/click、deny 与答错同形；
- 遥测故障不影响验证结果。

**E2E**

- 扩展现有 `e2e/captcha-interactive.e2e.ts`：图片题型、回退、音频按钮、设置页资产页签；
- 新增 `e2e/captcha-assets.e2e.ts`（或并入现有）：预览图库/繁体/图标题；
- 双浏览器 + `fresh`；旧 `captcha-risk` 用例保持绿；
- a11y：图片码 + 音频 + 键盘路径；CSP 不因新资源放宽。

**攻击模拟（非 CI 阻断，发布前人工跑）**

- `curl` 直打 verify（无 env/track/sign）→ 拒；
- 模板匹配滑块（OpenCV）→ 记录成功率；
- OCR 图片码（Tesseract/PaddleOCR 之一）→ 记录成功率；
- 固定题型高频请求 → 触发 `type_fixation` / 冷却；
- 批量囤 challenge 不 verify → 触发 `challenge_abandon`。

**门禁**：后端全量 pytest、ruff、mypy、`check_*`、`makemigrations --check`、`load_init_json --check`、
`sync_menu_permissions --dry-run`、`check_captcha_assets`（新增，先在 `docs/ci-gates.md` 登记）；
前端 typecheck/lint/test:run/24 项 `check:*`；E2E `fresh` 双浏览器；真实容器重启验证。

## 九、风险与取舍

1. **「更难」不等于「更安全」**：图片库/繁体字会抬高 OCR 成本，但多模态模型同样在进化；
   真正的可持续项是协议、算力、资产轮换与数据闭环。不要用真人通过率换虚假的安全感。
2. **图片码的定位**：合并后它仍是弱题型。默认权重 0、只在回退/显式请求时出题；
   高风险场景不选图片题；必要时加低难度 PoW。
3. **繁体字的公平性**：默认简体；繁体按语言/租户配置；`mixed` 整题统一脚本；
   上线前用目标用户样本测首次通过率。
4. **资产体积与性能**：图库 2~5MB + 字体 2~3MB；用 WebP + 子集 + 进程缓存；
   在低配容器上测出题 P95 与内存增量。
5. **供应链与合规**：只收许可明确的资产；manifest + 哈希 + 来源；禁止用户上传；
   `check_captcha_assets` 进 CI；图片剥离 EXIF，避免人脸/隐私素材。
6. **clean cut 风险（本方案最大风险）**：旧图片码链路在上线前删除，旧前端/第三方客户端
   没有运行时回退路径。防线：上线门禁的旧路由 404 / 旧字段不在 OpenAPI / E2E 全链路、
   发布前兼容演练、回滚靠镜像版本；旧客户端必须先迁移到 ticket 才能上线。
7. **自动降权的自伤风险**：自动下线题型可能被攻击者用来「把题打没」；默认只告警，
   自动降权需显式开启并限制单次/每日次数。

**明确不做**：3D 旋转、九宫格 AIGC、刮刮乐、短信上行、云端验证码、用户上传图库、ML 训练管线。

## 十、已拍板事项（2026-10-27）

| 议题 | 结论 | 实施含义 |
|------|------|----------|
| 图片码定位 | **作为统一协议的题型、默认权重 0** | 图片码走统一 ticket/风险/日志；不进随机池，只做回退/显式请求 |
| 繁体字策略 | **可选字符集、默认简体** | `simplified` 默认；`traditional` / `mixed` 可配；`mixed` 整题统一脚本；新增 Noto Serif TC 子集 |
| 图库资产形态 | **随包 CC0 + 只读挂载** | 资产 manifest + 许可/哈希/版本；不做用户上传；保留程序化兜底 |
| 默认模式 | **clean cut：只保留统一协议，删除 `CAPTCHA_MODE` 与旧 `image` 模式** | C1 一次完成删除；server/client 同批；回滚靠镜像；旧客户端上线前必须迁移 ticket |

**实施注意**

1. **项目未上线，不做兼容层**：旧 `image` 模式、旧端点、`CaptchaStore`、`captcha_key/code`
   在 C1 删除；旧路由 404、旧字段不在 OpenAPI；`check_captcha_legacy.py` 防复活。
2. `CAPTCHA_IMAGE_FALLBACK_ENABLED` 默认 True、`CAPTCHA_POW_FOR_IMAGE_FALLBACK` 默认 True：
   无障碍回退保留，但图片码请求必须付低难度 PoW，配合 `fallback_abuse` 规则防 OCR 农场。
3. 默认 `CAPTCHA_RISK_MODE=enforce`；上线前必须完成影子/合成流量基线，首周盯盘；
   未完成基线不得上线。
4. 强绑定（sid + fp + audience）、verify 常签、决策优先级、失败同形、默认 enforce 的
   详细口径见 [安全硬化实施细则](验证码上线前安全硬化实施细则-2026.10.md)。
