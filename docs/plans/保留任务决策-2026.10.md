# 保留任务决策（2026.10）

> 本文回答一个具体问题：审查/长期台账里**明确保留**的项，哪些值得继续开发、哪些维持现状、
> 哪些只差目标环境验证。结论按「项目当前事实 + 已有 ADR / 守护 + 真实触发条件」给出，
> 不把「看起来可以统一」当成开发理由。
>
> 关联：`DEV-TASKS.md`（唯一待办入口）、`长期任务方案-2026.10.md`（R3 逐页授权）、
> `触发制任务清单-长期.md`（触发条件）、`../CURRENT-STATUS`（审查包状态入口）。

## 一、结论速览

| 保留项 | 结论 | 根源判断 | 触发 / 下一步 |
|---|---|---|---|
| `system` 物理拆子 app | **不开发** | 见 [ADR-045](../adr/ADR-045-modular-trimmable-architecture.md)：软裁剪已交付，物理拆 app 会同时动表、迁移、种子、模块路由与影响面键；当前文件/服务层拆分已解决可读性 | 出现「跨团队独立发版」或「按 app 安装/卸载」的真实诉求时重评 |
| 前端运行时远程组件（Module Federation） | **不开发** | 构建期 `src/extensions/**/routes.ts` 已覆盖二开页面注入；运行时加载要新增 CSP、鉴权、版本契约三套边界，收益未成立 | 出现多团队独立发版或第三方运行时插件诉求时立项 |
| 动态表单敏感字段按角色白名单 | **维持统一掩码** | 2026-10-22 产品口径已确认「非超管统一掩码」；角色白名单会引入第二套字段策略与审计面，当前无合规诉求 | 合规要求「按角色差异化查看/导出」时，先补策略与审计设计 |
| `defineListPage` / PageShell 剩余页面 | **按需开发** | 页面壳迁移是机械改造，收益在一致性；一次性大范围改页面壳的回归成本高于收益 | 跟随页面功能改动分批迁移，不单独立项 |
| R3 逐页授权口径（43 处写能力） | **需产品确认，默认不开放** | 只读/取用类已由 `test_builtin_role_readonly_coverage.py` 守护且全绿；剩余以导入导出/批删/强退/模拟登录等写操作为主，批量授权会把只读演示角色变成写角色 | 产品给出「要开放的页面 + 能力」清单后，按页补 `seeds/grants.json` + 三层守护 |
| 四个最小二开示例 | **不新增代码** | `docs/guide/plugin-development.md` 已覆盖 action / input_type / 通知渠道 / 审批 biz 四类 5 分钟扩展；`examples/plugins/xadmin-demo-plugin` 是可运行样本 | 出现「示例不够用」的具体反馈时补单例 |
| 目标 Linux 干净机安装/升级实测 | **已执行（2026-10-23）** | 安装器只支持 Linux；已在 CentOS 7 目标机完成 5.0.2 全新安装与幂等升级，健康/迁移/权限/属主全绿；4.2.5→5.x 目标机复跑受旧镜像缺口阻塞 | 补齐 4.2.5 的 web/postgres/redis 镜像后复跑旧库升级（或沿用本机隔离栈演练） |

## 二、逐项依据

### 2.1 `system` 物理拆子 app

- ADR-045 的结论是「评估不立项」，不是「没时间做」；`system` 的模型/视图/种子/模块路由/AI 声明
  与 `common` 契约缝耦合，物理拆分的收益主要是目录观感，风险是迁移链与存量库升级。
- 已完成的替代动作：`system/utils/platform` 按域迁 `system/services/monitor`、
  `devtools/services/codegen`、`ops/legacy`；`identity` / `file` / `audit` / `task` 四域已独立成 app。
- 结论：**不开发**。若未来出现「按 app 独立发版 / 安装」诉求，先重走 ADR，不直接拆表。

### 2.2 前端运行时远程组件

- 当前扩展点是构建期约定：`src/extensions/**/routes.ts` 纳入全屏路由收集，菜单组件解析、
  路由预取、菜单视图清单同时支持 `extensions/` 片段；不引入远程组件。
- 运行时加载需要同时解决：CSP（远程脚本源）、鉴权（远程组件拿什么身份）、版本契约
  （宿主与插件 API 兼容）、失败降级；这些边界没有真实需求时投入产出比低。
- 结论：**不开发**。需要「二开页面免改宿主源码」时，先用 `pnpm gen:module` + 构建期 extensions。

### 2.3 动态表单敏感字段按角色白名单

- 2026-10-22 已确认口径：schema `sensitive` 对非超管在列表/详情/导出统一掩码；超管可见。
- 角色白名单会让「同一字段对不同角色可见」成为第二套策略面，需要额外审计与回归；
  当前没有客户合规诉求，统一掩码是更安全的 fail-closed 口径。
- 结论：**维持统一掩码**。若未来要做，先设计「策略存储 / 超管豁免 / 导出审计」三件事，再动序列化器。

### 2.4 `defineListPage` / PageShell 剩余页面

- 已迁移 15 个 RePlusPage 列表页；自定义壳页（credential/directory/monitor/my-scope/export 等）
  不适用工厂，强行迁移会降低体验。
- 页面壳/统计卡/弹层/只读表的统一已完成主要公共件；剩余页面是低风险机械迁移。
- 结论：**按需开发**，跟随页面功能改动分批做；不单独立项，不做一次性全量替换。

### 2.5 R3 逐页授权口径

- 当前内置角色：只读/取用类守护全绿；剩余 82（管理员）/ 86（演示模式）条未授权项以写操作为主。
- 批量补 grants 会把「只读演示角色」变成可写角色，破坏演示模式的安全边界；
  `test_builtin_role_readonly_coverage.py` 已覆盖只读类漂移。
- 结论：**默认不开放写权限**。产品按页面给出「要开放的能力」后，逐页补 `seeds/grants.json`
  并补三层守护；没有清单就不动授权。

### 2.6 四个最小二开示例

- `docs/guide/plugin-development.md` §4.2 已给出「自定义 action + 权限点、自定义 input_type、
  通知渠道、审批 biz sync」四类 5 分钟扩展；`examples/plugins/xadmin-demo-plugin` 是可运行样本。
- 再新增四个目录级示例会与文档/示例插件重复，维护成本高于收益。
- 结论：**不新增代码**；有具体二开反馈时按场景补单例。

## 三、目标 Linux 安装/升级验证清单（发布门禁）

> **执行结果（2026-10-23）**：`192.168.0.111`（CentOS 7）完成 5.0.2 全新安装与 `upgrade v5.0.2` 幂等升级，均通过；
> 证据见审查包 `xadmin审查-20261021/附录/04-目标Linux安装升级实测-20261023.md`。4.2.5→5.0.2 目标机复跑
> 受阿里云仓旧镜像（web/postgres/redis）缺失阻塞，补齐镜像后按本节复跑。

> 安装器只支持 Linux x86_64（`xadmin.sh` 在 Darwin 直接退出）；本机隔离 compose 演练不能替代。
> 执行前确认目标机为干净系统，准备好离线包/镜像源与配置模板。

### 3.1 全新安装

```bash
# 目标机：Linux x86_64，Kernel > 4.0，Docker + compose 可用
tar -xzf xadmin-installer-<version>.tar.gz && cd xadmin-installer
./xadmin.sh install
./xadmin.sh status
```

验收：

- 容器健康：`server / celery-worker / celery-heavy / celery-beat / postgresql / redis / nginx` 均 healthy；
- 初始化：迁移完成、`load_init_json` 0 error、`doctor` 10 通过 / 0 失败；
- 登录：管理员账号可登录，菜单/权限点渲染正常；
- 数据目录属主：`${VOLUME_DIR}/server/data` 属主与镜像 `USER 1001` 匹配；
- 记录：安装版本、镜像 digest、配置文件校验和。

### 3.2 存量升级（4.2.5 / 5.0.x → 当前版本）

```bash
# 升级前备份（安装器会按开关自动备份，仍建议手工留一份）
./xadmin.sh backup_db
./xadmin.sh upgrade v<version>     # 文档命令带 v；安装器内部会归一化
```

验收：

- `upgrade_check` = `up-to-date`（迁移数、游离表、缺表缺列均为 0）；
- `docker ps` 健康四项为 true；`load_init_json --check` 0 error；
- `sync_menu_permissions --dry-run` 缺口 0；
- 登录、审批、表单、开放平台各抽 1 个真实页面；
- 记录：备份路径、升级耗时、体检输出、回滚路径。

## 四、产品口径（2026-10-23 已确认）

1. **R3 逐页授权**：**维持默认不开放**。只读/取用类保持现有守护；43 处写能力不批量授权，
   等具体页面有业务诉求时由产品给出「页面 + 能力」清单，再逐页补 `seeds/grants.json` + 三层守护。
2. **动态表单敏感字段**：**维持非超管统一掩码**。列表/详情/导出同一口径，不引入按角色白名单；
   若未来出现合规要求，先设计策略存储、超管豁免与导出审计，再动序列化器。

以上两项已确认，代码侧不做批量授权或第二套字段策略。
