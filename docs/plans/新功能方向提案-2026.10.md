## 一、外部对标盘点（三个梯队）

| 梯队 | 代表 | 与本项目的关系 |
|------|------|----------------|
| 元数据驱动低代码 | **amis**（百度，JSON 配置即开发）、Appsmith / ToolJet / Budibase（可视化拖拽内部工具） | amis 与本项目同构度最高（JSON 协议渲染表格/表单/图表）；本项目 RePlusPage 协议面（search-fields/columns + input_type 词表 35+ 项 + tabs + 受控 lookup）是其**子集形态的超集**，且多出权限 / 审计 / 审批 / 裁剪等企业面 |
| 代码优先 CRUD 元框架 | **refine** / react-admin（React 生态） | 主张「代码所有权 + hooks 抽象」——对应本项目的 `defineListPage` DSL + 契约注入二开体系（18 册已验证缝面纪律） |
| Vue admin 模板 | **Vben v5**（monorepo / 多 UI 库 / shadcn 化方案）、Soybean（主题颜值）、vue-pure-admin（本项目前端基座） | 纯模板与「模板 + 元数据后端」不是同一物种——本项目相对三者的差异化恰在**协议驱动 + 模块可裁剪 + 开放平台** |

**2026 趋势要点**（来源见文末）：① AI-native（agentic / 预测式 UI、嵌入 admin 的 LLM
工作流）替代静态仪表盘成为分化主线（AI-native vs "AI-washed"）；② 配置式 Pro 组件
（ProTable/ProForm 形态）成为中后台标配，Vue 生态仍在补齐——本项目已到位；③ shadcn
「组件即代码」、低饱和 / 圆角 / 暗色渗透进 admin 设计（Vben 已提供 shadcn 方案）；
④ monorepo / 类型安全 / 依赖升级窗口化（本项目已常态化）。

**对标结论**：不缺「有没有」——九大内置能力覆盖中后台主航道；差距集中在三处
**「深一度」**：AI 从「助手」走向「主动」（趋势①）、数据从「展示」走向「联动探索」
（amis/Metabase 形态）、二开从「能用」走向「顺滑」（refine 的 DX 标准）。

## 二、候选方向（按建议优先级排序，均给出现成基座）

> 「基座」= 审查已确认存在的可复用资产；「量级」= 人日级粗估（S≤5 / M≤20 / L>20）。

### P1 · 仪表盘卡片联动与下钻（S~M，纯增量零红线）

- **现状基座**：ChartCard 刷新信号原位重拉（05 册 5.1）、数据集 `execute/aggregate`
  端点、kiosk 模式路由元数据均已就绪；仪表盘编辑态拆分（T4）同文件顺手做。
- **提案**：卡片点击 → 下钻抽屉（复用数据集预览表格）或按卡片维度值反向过滤同盘其他
  卡片（联动刷新走既有 refreshToken 机制）。
- **对标**：amis chart 联动、Metabase click-through、Grafana drilldown 是分析类产品的
  标配交互；本项目数据面已齐，缺的只是这一层交互编排。
- **依赖 / 风险**：无新端点；联动需定义卡片间过滤协议（建议先单向下钻，联动二期）。

### P2 · AI 主动摘要与预警播报（S，AI 域第二阶段第一刀）

- **现状基座**：AI 助手观测面齐备（usage/metrics/observability 端点，06 册 6.1）、
  welcome 首页卡片体系 + LCP 已优化至 244ms（DEV-TASKS #13）、通知渠道注册表现成。
- **提案**：welcome 新增「AI 日报卡」——定时聚合（审批待办 / 审计异常 / 监控阈值 / AI
  用量）生成自然语言摘要，异常项可点击直达对应页面；复用 `ai_declarations` 的只读动作
  白名单，不让 AI 触发写操作。
- **对标**：趋势①「预测式 UI / 嵌入式 copilot」的最小可信切片；与既有 AI 助手（用户
  主动问）互补为「系统主动说」，但**不引入自主动作**（守住受限动作边界）。
- **依赖**：AI 供应商成本少量上升（摘要生成），建议先做成开关默认关。

### P3 · 全局数据搜索（M，重启停用面）

- **现状基座**：`system/search_indexes.py` 与 `search.py` 基座已在（02 册 2.1 域），顶栏
  菜单搜索（SearchModal + 命令面板）体验成熟；菜单树里 `/system/search` 为 `is_active=false`
  的停用目录（12 册 12.2）——**数据搜索是当年规划过、基座在、入口停用的状态**。
- **提案**：顶栏搜索升级为「菜单 + 数据」双面：按模型注册白名单（复用 modellabelfield
  注册表），命中详情直跳；权限经既有菜单权限点收敛（数据权限自动叠加）。
- **对标**：现代 admin 的 ⌘K 全局搜索（Vben / Soybean 均已内置跨实体搜索）已是用户
  预期；本项目菜单面领先、数据面缺位。
- **依赖**：需要先回答索引策略（PG trgm 已有先例——identity 用户搜索在用）。

### P4 · 代码生成器双入口合流 + AI 字段草案（M，先做 T11）

- **现状基座**：CLI（`_generate_crud` 14 模块）与 GUI（`/system/codegen`）双入口并存、
  模板同源性无守护（15 册 15.2）；生成物已含种子回灌 / i18n / AI 声明。
- **提案**：① 先执行 T11（确认/统一模板源，GUI 改为 CLI 渲染层的 GUI 壳）；② 再加
  「自然语言 → 字段草案」：AI 从描述生成 field_plan JSON（生成器的中间表示已有），人
  审后进 GUI 流程——**AI 产物过人审，不直写代码**。
- **对标**：refine 的 AI 生成（refine.dev 对比页主打卖点）、Appsmith AI；本项目生成器
  中间表示（field_plan）恰好是 AI 的理想接缝。

### P5 · MCP 工具治理（M，开放平台补全）

- **现状基座**：MCP 客户端 + tools/list 运行期渲染（06 册 6.4）、AI 受限动作白名单
  （`ai_declarations` + permission_meta）、操作日志。
- **提案**：MCP 服务器级「工具白名单 / 调用配额 / 审计报表」——出站调用走
  `outbound.pinned_request` 既有出口，审计面复用 OperationLog。
- **对标**：2026 年 MCP 生态爆发后的治理诉求（企业接入三方工具的合规面）；早做一步
  即是二开卖点。

### P6 · 全局密度 / 紧凑模式偏好（S，设计体系小步）

- **现状基座**：EP `ComponentSize` 已贯穿 RePlusPage（`tableBarData.size`）、设置面板
  偏好体系（configure preferences）成熟。注意与既有「内容区紧凑模式」（`SettingGeneral.vue`，
  内容区留白密度）和页面缩放偏好不同层——本项指表格/表单**组件级 `size` 全局注入**，非内容区 padding。
- **提案**：全局密度偏好（默认 / 紧凑）注入所有表格与表单 size——一行偏好 + 常量收口。
- **对标**：Soybean 主题系统、Vben 偏好中心的标配项；同为候选池「适老 / 可读性」的
  前置能力（字号方案被否决后的替代路径）。

### P7 · 通知订阅增强：阈值订阅、@提及与 webhook 渠道（S×3）

- **现状基座**：监控阈值告警（monitor.py thresholds）、审批讨论（InstanceDiscussion）、
  通知渠道注册表 + 模板注册表（07 册）；渠道注册表现有 6 渠道（email / site_msg / sms /
  dingtalk / wecom / feishu），**无 webhook 通知渠道**——开放平台的 webhook 是出站事件
  订阅而非通知渠道（2026-10-25 核实），渠道密钥管理面已齐备。
- **提案**：① 监控阈值 / 审批事件 → 订阅化（用户自选渠道，复用 UserMsgSubscription）；
  ② 审批讨论 @提及（解析 + 站内信 + 红点角标复用 approvalBadge）；
  ③ 新增 webhook 通知渠道（走 `register_channel` 注册制 + 出站既有出口，S~M）。
- **对标**：内部协作产品的基础预期；三件均为既有模型的增量接线。

### P8 · 仪表盘 / 大屏快照导出（S~M，报表链路补全）

- **现状基座**：图表渲染 echarts 6（`getDataURL` 可直接出位图）、导出链路已统一
  （task 域导出服务 MIME 单源 + 下载中心 + 进度/取消协议）、定时报表 xlsx + 邮件/IM
  送达已在（`dataset/analysis_tasks.py`）；但**画布快照导出为零**——后端无 HTML 渲染面
  （无 playwright / weasyprint），前端无图表位图合成逻辑（2026-10-25 核实）。
- **提案**：纯前端先行——仪表盘 / 大屏逐卡 `getDataURL` 合成长图（PNG）+ 标题 /
  时间戳 / 水印叠加，落既有下载中心；PDF 路线二期再议（浏览器打印或服务端渲染另评，
  避免为快照引入无头浏览器常驻）。
- **对标**：Grafana 面板分享/导出、[Metabase 仪表盘订阅与 PDF 附件](https://www.metabase.com/docs/latest/dashboards/subscriptions)、
  [JumpServer 报表导出面](https://www.jumpserver.org/features.html)是分析类产品的标配能力。
- **依赖 / 风险**：零新端点、零新依赖；与前端专项 D-2（看板 WS 数据推送）不重叠
  （一个改数据面、一个改出口面）；大屏自由画布含视频/富文本等非图表窗格，首版可只覆盖
  图表窗格并在导出物上明示降级说明。

   「后端定义 → 前端免写」，拖拽编辑器引入第二套 UI 事实源）；
2. **独立前端运行期插件**（远程组件加载）：CSP `script-src 'self'` 与模块裁剪白名单
   双重否决（此前已决策，web 仓 default.conf 注释可证）；
3. **BPMN 引擎替换**、**在线建表 DDL**、**多租户**：沿用红线，重开条件见 DEV-TASKS §三。
