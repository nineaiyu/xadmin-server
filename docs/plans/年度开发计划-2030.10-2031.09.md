## 一、年度定位

第四年度以「演练驱动自愈修复」收口（3 个运行期缺陷：Redis 韧性 / DB 池自愈 / 探测缓存）。
本年度延续**持续运营**，并显式化两个抓手：

1. **SLO 目标值校准执行**（T6）——数据积累成熟（2029-12 起采集），Q1–Q2 落地并回填 metrics；
2. **陈年挂起项清账**（T5/T3）——推送合 main 后（用户动作）执行视觉基线入库 / Renovate 验收 /
   CSP 页面层切强制，终结长期悬挂项。

一切新增以真实触发为前提；不设功能军备目标。

## 六、验证方式（门禁矩阵）

| 层级 | 每窗口出口门禁 |
|------|---------------|
| 后端 | `ruff check/format` + `pytest -n auto` 全量 + 覆盖率 ≥78% + 新增守护测试 |
| 前端 | typecheck + typecheck:strict + eslint + prettier + stylelint + vitest + check:contract + **check:bundle-size（基线 522 KB）** |
| E2E | 新功能主链路双浏览器 + `test:e2e:fresh`（改后端必跑）+ 视觉回归（基线入库后常态） |
| 数据/部署 | 新权限点重灌幂等；迁移全新库重建（测试库持续覆盖）；升级路径按 installer 预检/回滚口径 |
| 性能/稳定 | k6 场景集基线对比；SLO 看板（校准后按新阈值） |
| 治理 | 新功能 100% 带测试；先 ADR 后动手；候选池先对账再排期 |

## 附录 A：明确不做（红线延续）

- 多租户（[ADR-031](../adr/ADR-031-multi-tenant-evaluation.md) 重开条件未命中）；
- 业务模块军备（商城 / CRM / WMS 等）；
- 重依赖（类 Excel 报表设计器、vxe-table、schema-form 等）；
- 适老主题、全面移动端适配（维持既有结论）。

## 附录 B：本计划与第四年度的衔接

- T1/T2 承接第四年度依赖复核结论（ADR-004/014 复审记录）；
- T6 承接 2029-12 数据源交付（任务指标跨进程聚合）与指标端点启用；
- T5/T3 承接 release-checklist §1/§3 挂起项（同属"待外部动作"类）；
- 演练承接第四年度 3 轮（累计 6 轮场景覆盖），继续新场景轮换。
