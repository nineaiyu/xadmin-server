# 前端框架一致性调查与收敛方案（2026.10）

- 状态：**调查完成，方案待启动**（门禁脚本未写、页面迁移未做）
- 日期：2026-10-18（调查）／2026-10-17（弹窗全屏按钮修复，见 §七）
- 触发：用户反馈两类现象——「有些页面右上角没有全屏按钮」「有些添加/编辑页面没走框架自带的字段渲染」
- 关联：[后台页面UI一致性重构计划-2026.09.md](archive/后台页面UI一致性重构计划-2026.09.md)（2026-09 弹层/列表页收敛，本文是其表单维度的续篇）、
  [metadata-protocol.md](../architecture/metadata-protocol.md)（元数据协议权威口径）、
  [ADR-064](../adr/ADR-064-dform-designer-upgrade.md)（动态表单 schema 协议，与本文议题平行）

## 一、结论速览

两个反馈**都不是框架缺失，而是「调用口径分裂」**：

1. **弹窗全屏按钮**：`ReDialog` 组件自带该按钮，但历史上是 opt-in（每个调用点手传
   `fullscreenIcon: true`），73 处调用只有 11 处传了——常规增删改表单全都没有。2026-10-17
   已在组件层改为**默认渲染**（§七）， bolted 显式 `fullscreenIcon: false` 关闭。
2. **表单字段渲染**：框架的元数据渲染链路完整存在且有活样板（user / ai 档案 / 设置面板零手写
   字段），但 **5 个页面显式关闭框架默认表单按钮改用手写 `*Form.vue`**，而后端 ViewSet
   100% 下发了这些表单的元数据——属于明确的「没走框架」。
3. **根因是契约竞争**：2026-09 的 UI 一致性计划把「表单 = `XxxForm.vue` + `getPayload()`」
   定为统一契约，该契约与「元数据驱动表单」并行且**没有任何文档说明何时用哪条路**，新人照旧
   契约写，就会持续产出「有元数据却手写」的页面。收敛必须「先补门禁与文档判定、再逐个迁移」。

## 二、调查范围与口径

| 维度 | 口径 |
|------|------|
| 仓库 | `xadmin-client`（Vue 3 + Element Plus + 自研 `Re*` 组件库） |
| 「没走框架」判定 | 页面 hook 显式 `auth.create = false; auth.update = false`（关闭框架默认表单）且有同目录手写 `*Form.vue`，且后端 ViewSet 继承 `BaseModelSet`（自动下发 search-fields / search-columns） |
| 合理手写判定 | 无对应模型元数据（登录/审批动作/内存草稿）、schema 协议不同源（dform 设计器）、形态特例（树形主编辑界面、画布 inspector） |
| 统计来源 | 全部数字来自 `grep -rc` / `find` 实测，见各节 |

## 三、框架能力盘点（不是没有，是没用上）

### 3.1 弹层全屏按钮（三套机制，勿混为一谈）

| 机制 | 位置 | 语义 | 默认 |
|------|------|------|------|
| 顶栏浏览器全屏 | `src/layout/components/lay-sidebar/components/SidebarFullScreen.vue` | Fullscreen API，整个浏览器进全屏 | 开（widget 目录 `lay-navbar/widgets/catalog.ts:66`） |
| **弹窗右上角全屏** | `src/components/ReDialog/index.vue` | 切换 `el-dialog` 的 `fullscreen` | **2026-10-17 前 opt-in；现已默认开** |
| 表格卡片全屏 | `src/components/RePureTableBar/src/bar.tsx` | CSS 级 `fixed inset-0` 铺满 | 开（`tableBar` prop） |

「顶栏浏览器全屏」缺失的四类根因（均非缺陷，属预期）：

1. **菜单外/独立页不套 Layout 外壳**：登录、OAuth 回调、邀请激活、账号设置
   （`src/router/modules/remaining.ts:30-110`）+ 模块自声明全屏页（glob 收集的
   `views/**/routes.ts`：大屏投屏、报表/大屏设计器）——`src/layout/index.vue:386` 的
   `LayHeader v-if="!fullContent"` 整块不渲染；
2. **布局切 `full-content` 或关「显示顶栏」**：`layoutModes.ts:89` / `configure.headerHidden`；
3. **账号/站点偏好关闭该 widget**：`widgetPositions.fullscreen = "none"` 或 `NavbarFullscreen: false`
   （设置面板 → 布局 → 顶栏组件；站点种子默认开，`settings/seeds/systemconfig.json:69`）；
4. **「内容最大化」态**：`hiddenSideBar` 为 true 时顶栏不渲染，还原入口只有页签栏按钮，
   而该按钮默认关（`TagsShowMaximize: false`）——**这是唯一建议动的体验缺口**（§六 A3）。

### 3.2 表单字段渲染链路（完整存在）

链路：后端 `BaseModelSet`（`packages/xadmin-common/common/core/modelset/viewsets.py:26`，
自动带 `SearchFieldsAction`/`SearchColumnsAction`）→ 前端 `fieldTypeRegistry.ts`（32 个封闭
`input_type` 词表，与后端 `input_types.py::DECLARED_INPUT_TYPES` 锁步）→ `registry.ts`
投影出表单/搜索/详情三张渲染器表（表单通道 24 个渲染器）→ `columns.tsx:126`
`getFormRenderer(input_type)` 装配 `PlusForm` 列 → `AddOrEdit.vue` 渲染。

**活样板（零手写字段）**：

| 样板 | 用法 |
|------|------|
| `system/user` | `useUserFormOptions.ts:28-107`：在元数据列上微调 dept 级联 / invite 开关 / password 条件隐藏，字段本体来自后端 |
| `integration/ai` 档案 | `AiProfileFields.vue` 直连 `useBaseColumns` → `PlusForm`，不依赖 RePlusPage 默认壳 |
| `settings` 面板 | `SettingItem.vue:59,76-84`：`useBaseColumns(props.localeName)` → `PlusForm`，支持按渠道拆页签 |

**元数据协议能力边界**（决定哪些字段能迁、哪些不能）：`search-columns` 21 键含
`choices`（超 200 条截断）/ `lookups` / `suggest_url` / `multiple` / `tabs_index` 等；
**协议无 linkage、无 mask、无嵌套子表能力**——联动只在 dform schema（ADR-064），脱敏在
序列化输出侧，嵌套子表（如审批规则 levels）元数据无法表达。

## 六、解决方案（三步：门禁 → 迁移 → 文档定界）

### A. 弹窗全屏按钮（已做完，见 §七）

剩余一项体验缺口：**「内容最大化」态的还原入口**。页签栏最大化按钮默认关
（`TagsShowMaximize: false`，`systemconfig.json:90`），用户进入最大化后顶栏消失、还原入口
不可见。建议将其默认打开，或在最大化态给一个常驻还原按钮。改默认值需同步前端
`public/platform-config.json` 与后端 `settings/seeds/systemconfig.json` 两侧（平台参数四步
成组登记，见 `xadmin-client/AGENTS.md` §四）。

### B. 表单字段渲染：先门禁、再逐个迁移

**第一步：门禁（成本最低，防扩散）**。新增 `scripts/check-handwritten-forms.mjs`（对齐现有
34 个 check 脚本形态，接入 CI）：

1. **白名单制**：新增 `*.vue` 若同时含 `el-form-item` 且所在目录存在 RePlusPage 同模块页，
   即报错；显式豁免走文件头标记（如 `<!-- @form-exempt: reason -->`）；
2. **豁免清单随代码走**——把 §五一次性登记进去并附理由（先例：RePlusPage 的
   `renderers-pairing.spec.ts` 成对清单思路）；
3. 与 `check-file-length.mjs` 组合：手写表单文件普遍长（`PaneInspector.vue` 33 处
   `el-form-item`、`FormFieldDialog.vue` 28 处），可顺带限制单文件 `el-form-item` 数量。

**第二步：逐个迁移（按 §四 P0→P3）**。两种现成模式直接照抄：

- 标准模型 CRUD → hook 里去掉 `auth.create/update = false`，用 `addOrEditOptions.columns.<key>`
  定制（样板：`useUserFormOptions.ts`）；
- 自建壳弹窗 → 照抄 `AiProfileFields.vue`（`useBaseColumns` → `PlusForm`）；
- 需要自定义控件 → `registerFormRenderer`（`registry.ts:27-32`），不要退回手写整个表单。

**第三步：双端一致性守护**。现有 `metadata-vocabulary.spec.ts` 只保证「词表 ⇄ 渲染器」不
漂移。建议新增「页面 ⇄ 后端元数据」断言：对每个显式关闭 `auth.create`/`auth.update` 的
RePlusPage 页面，检查同目录是否存在 `*Form.vue` 并要求其带豁免标记或登记在迁移计划里——
把「明知故犯」与「无意疏漏」区分开。

### C. 文档定界（根因治理）

写一份「表单选型判定」文档（或并入 `metadata-protocol.md` / `component-handbook.md`），
明确三条路的胜负条件：

| 形态 | 选型 |
|------|------|
| 标准模型 CRUD（后端 BaseModelSet + serializer 字段可被 21 键元数据表达） | **元数据表单**（`addOrEditOptions` 微调） |
| 有模型但含元数据表达不了的结构（嵌套子表 / 三元组 / 逗号分隔数组） | **混合**：基础字段走元数据，复杂字段 `registerFormRenderer` 或保留手写 |
| 无模型元数据 / schema 协议不同源 / 形态特例 | **手写 `XxxForm.vue`**（2026-09 契约继续有效） |

不写这份文档，契约竞争会持续产出同类页面——这是本次调查最根本的结论。

## 七、已落地：弹窗全屏按钮默认渲染（2026-10-17）

**问题**：用户以「新建岗位只有关闭按钮、没有全屏按钮」定位到 `ReDialog` 的全屏按钮是 opt-in
（`index.vue` 旧条件 `v-if="options?.fullscreenIcon || options?.headerRenderer"`，且
`store.ts` 的 `addDialog` 不做组件级默认值合并），73 处调用仅 11 处传参且集中在通知详情与
头像上传。

**改动**（3 文件，工作区待提交）：

| 文件 | 改动 |
|------|------|
| `src/components/ReDialog/index.vue` | 新增 `showFullscreenHeader(options)`：`headerRenderer` 优先走自绘头部，否则**默认渲染**「标题 + 全屏切换」头部，仅显式 `fullscreenIcon: false` 关闭；全屏按钮本体（uid 隔离、静态 `fullscreen` 常驻时不渲染可切换按钮）逻辑不变 |
| `src/components/ReDialog/type.ts` | `fullscreenIcon` 注释改为默认渲染口径，并写明 `headerRenderer` / `fullscreen: true` 两个例外 |
| `src/components/ReDialog/__tests__/reDialog.spec.ts` | 补 3 条用例：默认渲染且可逆、`fullscreenIcon: false` 走 EP 默认头部（标题+关闭按钮结构不回退）、`headerRenderer` 优先 |

**教训（过程记录）**：第一版把模板里 `headerRenderer` 的渲染整段删掉的写法是**回退性 bug**
（自定义头部路径被掐断），由新补的第三条用例当场抓住。`v-if="showFullscreenHeader"` +
`v-if="headerRenderer"` / `v-else` 的分支结构才是正解——**改默认值不能顺手删既有分支**。

**验证**：`vitest` ReDialog 18 例全过；前端全量 `test:run` 2282 passed；`typecheck` /
`lint`（eslint --max-warnings 0 + prettier + stylelint）通过；`check:{template-root,
contract-usage,i18n,menu-permissions,as-unknown,module-cycles,success-code,
platform-config}` 全过；`check-file-length` 存量基线未增长。尚未跑 E2E（无对话弹窗相关
用例，`grep dialog-fullscreen-toggle e2e/` 零命中；视觉基线无 dialog 快照）——若后续接入
E2E，注意全屏按钮现为默认元素，选择器 `[data-testid="dialog-fullscreen-toggle"]` 会大量命中。

### 附带发现（未修，需另立任务）

`ReDialog` 的 `v-bind="options"` 会把 `headerRenderer` 函数属性序列化到 DOM 上
（表现为 `.el-dialog` 节点上的 `headerrenderer="() => h(...)"` 属性字符串），导致**自定义
`#header` 插槽实际从未被 EP 消费**——即该渲染路径当前是死的，与 `_uid`/`getData`/`setData`
的既有处理（挂为不可枚举）不一致。当前无调用方传 `headerRenderer`，故无实害；修复方向是
把 `headerRenderer`（以及其它函数/对象型 options 字段）同样挂为不可枚举或从 `v-bind`
白名单中剔除。**修前先补一个会失败的用例**（挂在真实 DOM 上即为失败）。
