# ADR-065：知识库向量检索（embedding + RRF 混合，ADR-037 出口落地）

- 日期：2026-09-27
- 状态：**已交付**（backend pytest 全量 EXIT=0 + SDK 单测 20 例 + 向量纯函数 12 例 + 构建与混合检索集成 12 例 + 评测守护（36 问 hit@5 ≥ 75%）/ client typecheck + vitest 646 + 各 lint 门禁 + E2E 双浏览器「知识库向量：档案 → 构建 → 状态」2 例 / 迁移 `ai.0002_knowledge_embeddings`）
- 背景：[ADR-037](ADR-037-ai-retrieval-evaluation.md) 评估结论是「暂不引入向量，登记出口」，出口之一是**分块数 > 1000**。本批次实测语料已从 535 块增长到 **1178 块**（评测测试输出 `chunks = 1178`，越过阈值），且 P2.5 的决策点已由使用方确认推进，故按 ADR-037 的预研路线落地：**OpenAI 兼容 embedding API + Python 侧余弦 + RRF 混合**，不动部署（pgvector 留到语料超 1 万块另立 ADR）。

## 决策

### D1 启用条件 = 独立的 `purpose=embedding` 激活档案（无档案零变化）

- `AiProfile.Purpose` 新增 `embedding`（每个用途至多一个激活行，沿用既有用途级唯一约束）；
- **该用途不做回落**：`embedding_profile()` 只认 `purpose=embedding`，不回落 chat/structured（chat 模型打 `/embeddings` 会被供应商拒绝，或维度/语义完全不同）；
- 未配置 embedding 档案 → 向量链路整体不启用，检索行为与历史实现逐行等价（守护测试对比全扫路径）；**停用档案即回退词频**（无需改代码，运维可即时止损）；
- 复用档案的 `base_url` / `api_key`（AES 值级加密）/ `timeout` / `max_retries`：同一网关同时提供 chat 与 embeddings 端点时，只多一条档案。

### D2 向量落库到分块，陈旧判定显式而非隐式重算

`AiKnowledgeChunk` 新增 `embedding`（float32 小端二进制）/ `embedding_model` / `embedding_hash` / `embedding_dim`：

- 二进制而非 JSON：体积约为文本的 1/5 且省去检索期的解析（535+ 块量级的内存占用可忽略）；
- **陈旧 = `embedding_hash != content_hash` 或 `embedding_model != 当前档案模型`**：陈旧向量**不参与向量通道**（词频通道兜底该块），绝不静默用旧正文的向量回答当前问题；
- **分块重建保留向量**：`rebuild_chunks` 按 `content_hash` 复用未变块的既有向量（重建会换主键，不保留则每次仓库同步/重传都会让向量全量失效，重算即 API 成本）；
- 停用文档 → 分块移除（既有语义）→ 向量随之消失；重新启用后需再次构建（增量构建只补缺失块）。

### D3 构建独立触发、幂等、失败语义明确

- 触发方式：知识库页「构建向量」按钮（权限点 `buildEmbeddings:AiKnowledge`）与 `manage.py build_ai_embeddings`（`--force` / `--dry-run` / `--document` / `--batch-size`，与页面同源）；
- **幂等**：只补「未向量化 / 模型变更 / 正文变更」的块；`force=true` 全量重算（模型切换本就会让全部块陈旧，多数场景无需 force）；
- 失败语义：批间失败即停止（供应商多半整体不可用），已成功批次保留，返回 `ok=false` + 已嵌入条数 → 页面给 1001 可读提示（不静默丢语义）；
- 用量：构建记入 AI 账本（`feature=embedding`，**creator 为空**）——构建是管理端批处理，不占用任何个人配额，但成本可见（用量页按链路分布）；
- 未加入 sync 自动链路（仓库同步仍只做登记与分块）：向量构建的成本与耗时显式可控，同步/重传后由状态提示驱动补建。

### D4 检索 = RRF 融合，词频是基线、向量是补充

`ai/utils/ai_embeddings.py::rrf_fuse`（k=60）融合两侧排名，**词频权重 1.0 / 向量权重 0.5**：

- 词频是质量基线（ADR-037 实测 hit@5 97.2%），权重差异使「单通道向量命中」始终排在词频命中之后：弱 embedding 模型不会把基线命中挤出 top-k；词频无命中或命中稀疏时（改写式提问、同义表述）向量通道补足；
- 同分按「最佳名次 → 向量名次 → pk」稳定排序（纯 RRF 同分无法判优劣，该口径可复现）；
- 词频候选仍走既有阈值过滤（`SCORE_THRESHOLD=2`），向量候选取余弦前 50；
- **异常一律回退词频**：未配置档案 / 查询向量化失败 / 索引超容量（> 20000 块）/ 维度不一致 → 走词频原路径；问答可用性不被向量可用性绑定；
- 性能：向量索引与分词索引同款增量缓存（签名 = `content_hash:dim:model`，仅变化块回读二进制）；查询向量带 128 条短缓存（评测集连跑/重复提问省一次远端调用）。

### D5 契约不变 + 评测守护

- `retrieve(question, top_k)` 返回结构不变（`[{"chunk", "score"}]`，score 语义为融合分）→ 消费方（`_prepare_rag` / 评测 / 未来调用方）零改动；
- CI 守护：36 问评测集在**假 embedding（哈希袋向量，与词频同源）**下 hit@5 ≥ 75%——验证融合链路不破坏召回；真实模型的 hit@5 需在配置了档案的环境执行 `manage.py build_ai_embeddings` 后复跑 `pytest tests/integration/ai/test_ai_retrieval_eval.py`（打印值可作对照基线，口径见 ADR-037）；
- E2E：桩 LLM 新增 `POST /v1/embeddings`（确定性假向量），用例覆盖「档案 → 构建 → 状态（fresh/dim/stale）」，双浏览器通过。

## 验证

- SDK：`EmbeddingClient` 20 例（请求体与顺序重排、空输入短路、未配置/拒绝/非法 JSON/条数不符/非法向量、网络与 5xx/429 重试、4xx 不重试、批次上限）；
- 纯函数：编解码往返（含 memoryview）/ 非法长度 / 余弦（正交、反向、零向量、长度不符）/ RRF（单通道、双通道叠加、权重差、top-k 截断与稳定序）12 例；
- 集成：未配置档案时与全扫路径等价、构建写库与幂等、force 重算、dry-run 不写库、语义召回进入结果且双通道共识居首、查询向量化失败回退词频、单批失败上报部分进度、维度不一致失败、陈旧向量与模型切换被排除、分块重建保留未变块向量 12 例；
- 评测对照（本地实测）：纯词频 hit@5 = 35/36 = 97.2%；混合 + 假向量（噪声通道的最坏情形）= 29/36 = 80.6%，仍高于门禁 75%——说明权重口径下融合不会把基线拉垮。

## 边界

- **CI 无法验证真实嵌入质量**：真实模型的 hit@5 与 P95 需在配置环境复测（ADR-037 的「评测先行」原则保留）；弱模型可能稀释基线（假向量对照 97.2% → 80.6%），故启用前应评测、启用后可随时停用档案回退；
- 不做 pgvector / 向量索引（语料 > 1 万块另立 ADR；当前 1178 块 Python 侧余弦在毫秒级）；
- 不做重排（rerank / cross-encoder）、不做查询改写与多向量融合（HyDE 等）；
- 分块口径沿用 `##` 边界 + 1200 字符滑窗（语义切分不在本批范围）；
- 向量只覆盖知识库分块（不索引业务数据），检索面 fail-closed 语义不变；embedding 内容会发送到配置的供应商（数据出境/隐私评估由使用方按供应商口径确认）。
