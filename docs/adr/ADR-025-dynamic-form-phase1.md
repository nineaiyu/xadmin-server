# ADR-025：动态表单一期（采集登记）

- 状态：已接受
- 日期：2026-09-13
- 关联：年度开发计划 2026.10-2027.09 §四 W10（G5）；ADR-015（重依赖红线）；
  jeecg 在线表单设计器（对标对象，本 ADR 为其收敛版）

## 背景

采集登记类需求（无模型建表）缺乏支撑：每类登记都要开发模型 + 迁移 + 页面。
动态表单让管理员用「收敛控件集」自助定义表单，用户填报，数据以通用 JSON 存储。

## 决策

### 1. 表单定义 = 收敛控件集 JSON Schema

`DynamicForm`：`name`(唯一) / `description` / `schema`(JSON) / `is_active`。

- **控件集收敛为 8 种**：`input / textarea / number / select / radio /
  checkbox / date / switch`——覆盖采集登记高频场景；不做富文本/级联/子表单
  （登记候选池，随需求评审）；
- 字段定义 `{key, label, type, required, options, min, max, max_length,
  placeholder}`；key 必须 `^[a-z][a-z0-9_]{0,31}$` 且表单内唯一（JSON 存储键
  与查询稳定性的底线）；select/radio/checkbox 必须给 options（≤50 项）；
- **写入侧与提交侧双侧校验**同一套规则（system/utils/dform.py）：未知控件
  类型/key 不合法/超上限（单表单 ≤50 字段）一律拒绝——定义是数据质量的源头；
- schema 变更后**存量提交不回填**（新字段读旧数据为空），列表页标注——
  登记边界，避免隐性数据迁移。

### 2. 提交 = 通用 JSON 存储 + 按 schema 校验 + creator 隔离

- `DynamicFormSubmission`：`form`(FK PROTECT) / `data`(JSON) / `creator` /
  `created_time`；未在 schema 中的键、required 缺失、选项外取值、数值越界、
  超长文本一律拒绝；
- **可见性一期按 creator 隔离**：普通用户只见本人提交（可改/删本人），超管
  见全部——采集登记的典型口径，避免引入共享语义的复杂度（共享提交登记
  候选池）；
- 表单停用（is_active=False）后不可再提交，存量提交可查。

### 3. 页面：自定义动态列表（RePlusPage 动态列登记二期评估）

- 「表单管理」页（管理员）：列表 + 设计器弹窗（字段增删/排序/逐字段配置）
  + 字段预览；「表单填报」页（用户）：可填表单卡片 + 动态表单弹窗 + 本人
  提交列表（列按 schema 动态生成）；
- RePlusPage 的 search-columns 契约按模型字段生成，动态 JSON 列要接入需要
  动态序列化器协议改造——**一期用自定义动态表格（列由 schema 驱动，体验
  等价）**，RePlusPage 动态列协议改造登记二期评估；
- 前端动态渲染复用 Element Plus 表单控件，零新依赖（不引 form-create/
  schema-form 类库——ADR-015 红线）。

### 4. 明示不做（一期边界）

表单公开分享链接、附件上传控件、提交审批流挂接（G5b/2027-07 窗口）、
提交数据导出（复用 G8 报表管线评估）、条件显隐逻辑、多语言表单。

## 测试与验收

- 单元：schema 校验矩阵（key 格式/重复/控件类型/options/字段数上限）、
  提交校验矩阵（required/选项外/数值越界/超长/未知键）、停用表单拒提交；
- 集成：设计器 CRUD 越权（匿名/无菜单权限）、提交 creator 隔离（他人不可见
  不可改）、超管全量、列表动态列按 schema 返回；
- 门禁：pytest / ruff / i18n po；前端 typecheck / eslint / locale-keys；
  E2E 主链路（建表单 → 填报 → 列表可见）+ 全量回归。

## 复审记录（2026-09-13，二期窗口）

- **二期（G5b）已交付**：提交审批挂接（表单开关 + 412 一次性令牌协议 + 前端设计器/填报标记），
  决策与边界见 [ADR-026](ADR-026-dynamic-form-approval.md)；
- **「RePlusPage 动态列协议改造」评估结论：不立项**。一期自定义动态表格已覆盖
  「列表 + 弹窗填报 + 本人提交管理」的全部体验诉求；协议改造要动 `search-columns` 契约
  （前端类型 + 契约镜像 + 双端门禁）与字段权限口径，收益面窄而维护面大；
- **重开条件**：出现「动态表单数据要接入导入导出 / 行级数据权限过滤 / 与普通模型列表同款搜索」
  的真实需求时，再按契约先行原则评估。
