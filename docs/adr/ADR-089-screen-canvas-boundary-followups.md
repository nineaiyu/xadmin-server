# ADR-089：大屏画布边界收回与触发登记（动画时序 / 批量对齐网格）

- 日期：2026-10-11
- 状态：**已交付**（第一批两项收回 + 其余条目触发登记；一期见 ADR-086、二期 ADR-087、三期 ADR-088）
- 背景：

一 ~ 三期交付后，三份 ADR 的「边界（不做）」清单里还挂着一批条目：有的是**成本低、语义无歧义**
（动画时长 / 延迟 / 循环、多元素批量对齐网格），有的是**成本高或涉及外部依赖**（旋转后的视觉几何
命中、富文本扩展、模板治理、视频 / 地图 / 自定义 HTML 窗格），还有一条是**跨设备**能力
（服务端剪贴板）。它们混在「不做」与「等条件」两类里，容易被读成「还有没做完的活」。

本 ADR 做两件事：**把无歧义的两项直接收回**（改动随本 ADR 交付），**把其余条目登记为触发制**
（写清触发条件与第一动作，条件未到不投入）。

## 决策

### D1 入场动画的时序与循环（收回 ADR-088 边界第 2 条的一半）

- 窗格新增三个可选字段，一律**只在配了动画（`animation != none`）时才有意义**，且**非默认不下发**
  （旧载荷字节不变；`none` 时静默忽略，不因「配了时长却没动画」报错）：
  - `animation_duration`：100~5000ms，缺省 320（组件 CSS 基线）；
  - `animation_delay`：0~5000ms，缺省 0；
  - `animation_loop`：布尔，缺省 false（开 = 无限循环，用于「呼吸」类强调）。
- 校验在服务端（`dataset/utils/screen_layout.py`，越界即拒），前端同口径夹取
  （`utils/paneEffects.ts`：`clampAnimationMs` / `paneAnimationStyle`）；
- 时序**只在展示态写内联样式**（投屏 + 设计器预览），编辑态不写（避免影响编辑判断，也让
  DOM/断言干净）；
- 仍然不做：**逐元素自定义关键帧**（只保留 7 种内置动画）、按窗格配不同动画曲线的可视化编辑器。

### D2 多元素批量对齐网格（收回 ADR-088 边界第 5 条）

- 多选面板新增「对齐网格」：把选区每个窗格的 `x / y / w / h` **四舍五入到当前步长倍数**
  （步长取工具栏「吸附网格」的选择，尺寸不小于最小 16px，结果夹回画幅）；一次操作**一个撤销点**，
  已全在网格上则不产生变更（不记空撤销点）；
- 与手势吸附的分工：手势吸附**参考线优先、网格兜底**（一期手感不变）；本动作是显式命令，
  **直接落网格**（不受参考线影响）；
- 为什么连尺寸一起取整（而不是只挪位置）：尺寸不齐时「对齐网格」只解决了一半问题——相邻窗格
  之间仍会出现半格缝隙；取整尺寸是幂等的，再点一次结果不变。

### D3 触发登记（条件未到不投入；命中后按「第一动作」起手）

| 条目 | 出处 | 触发条件 | 第一动作 |
|------|------|----------|----------|
| 视频 / 地图 / 自定义 HTML 窗格 | ADR-086 §边界（ADR-062 扩展口径） | 产品给出具体类型 | 服务端 `SCREEN_PANE_TYPES` 白名单 + 前端 `PANE_DEFAULTS` + 属性面板三处同步（自定义 HTML 须先定「只允许 iframe 地址」还是「原样 HTML」——后者有 XSS 面，需安全评审） |
| 跨设备剪贴板（服务端存储） | ADR-087 §备选表 | 跨设备 / 跨浏览器复制粘贴诉求出现 | 新增按用户单槽模型 + `screen-clipboard` 端点 + 权限点；前端剪贴板双写（本地 + 服务端），粘贴优先本地 |
| 旋转后的视觉几何命中（框选 / 吸附 / 对齐按旋转盒） | ADR-088 §边界 | 出现「旋转后选不中 / 对不齐」的真实反馈 | 先定唯一口径（旋转后「看起来对齐」与「数学对齐」不允许并存），再改造 `freeSelect` / `freeSnap` / `freeAlign` 的几何入口 |
| 富文本扩展（链接 / 图片 / 列表 / 表格 + 所见即所得工具条） | ADR-088 §边界 | 出现「要排版级富文本」的真实诉求 | 先定安全口径（外链 / 外链图片 / 允许的标签集）+ 是否引第三方编辑器（bundle 预算另评） |
| 模板治理（版本管理 / 目录分组 / 审核流） | ADR-088 §边界 | 模板数量增长到「找不到 / 改坏要回滚」 | 先做目录分组 + 版本历史与回滚；审核流视组织流程再议 |
| 多租户 / 跨租户共享 | 工作区红线（[DEV-TASKS.md](../plans/DEV-TASKS.md)） | SaaS 商业化诉求 | **维持不做**：重走 ADR（数据隔离读 / 写 / 巡检三面已有） |

## 备选方案与取舍

| 方案 | 结论 |
|------|------|
| 动画时长按「秒」输入（1.5s） | **拒绝**：与服务端毫秒字段两套单位必然漂移；统一 ms + 输入步进 50 |
| 时长允许超长（>5s） | **拒绝**：投屏轮播下超长入场动画等于画面「半残」，上限 5000ms |
| 循环动画默认开 | **拒绝**：会改变既有投屏观感；缺省关，显式开启 |
| 对齐网格只取整位置（不取整尺寸） | **拒绝**：相邻窗格仍会留半格缝隙，且用户得再手改尺寸；取整尺寸幂等 |
| 对齐网格改成「等距重排」（顺带把窗格摊成等距） | **拒绝**：与「分布」功能语义重叠，且用户没要求重排，隐式改动过大 |

## 兼容性与回退

- 三个新字段全部可选且非默认不下发：旧载荷（无键）升级后字节不变，前端旧版本读新载荷也只忽略未知键；
- 「对齐网格」是新增动作入口，隐藏入口即可回退；动画时序缺省时与三期行为逐像素一致；
- 服务端校验新增两条错误文案（时长 / 延迟越界），zh/en 语言包已同步。

## 落地记录（2026-10-11）

两项收回当日交付，其余条目按 D3 登记为触发制（不投入、不预备）。

- **后端**：`_normalize_pane_body` 增时序校验与落库口径（`SCREEN_ANIMATION_DURATION_DEFAULT = 320`
  / `SCREEN_ANIMATION_DELAY_DEFAULT = 0` / `SCREEN_MIN_ANIMATION_MS = 0` / `SCREEN_MAX_ANIMATION_MS = 5000`），
  `none` 时静默忽略；两条新错误文案进 zh/en 语言包；
- **前端纯函数**：`paneEffects.ts` 增 `clampAnimationMs` 与 `paneAnimationStyle`（缺省不写内联样式，
  保持 CSS 基线单一来源）；`freeAlign.ts` 增 `snapBoxesToGrid`（返回 `pk → 新盒模型`，已在网格的
  窗格不进结果）；
- **组合层与 UI**：`createFreeEditor.alignToGrid()`（复用 `applyBoxes` 的「无变化不记撤销点」口径）；
  `PaneInspector` 增时长 / 延迟 / 循环三项（仅配了动画时出现）；多选面板增「对齐网格」；`ScreenPane`
  把时序并入展示态内联样式（编辑态不写）；
- **踩坑**：`paneBody` 的默认值口径必须与服务端逐字一致（320 / 0 / false），否则会出现「前端以为
  是默认值不下发、服务端按非默认落库」的静默分叉；本 ADR 用两侧常量同名同值的注释互指来兜住。
