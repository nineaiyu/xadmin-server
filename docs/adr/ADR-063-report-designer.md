# ADR-063：报表设计器（P2.2 批次二）

- 日期：2026-09-27
- 状态：**已交付**（backend pytest 全量 EXIT=0 + 22 例设计单测 + 11 例 API 集成 + 6 例投递渲染集成 / client typecheck + vitest 634 + eslint/prettier/stylelint/i18n + build 与体积门禁 / E2E 双浏览器「报表设计器 + 大屏设计器 + 数据分析主链路 + 远程控制」8 例通过 / 本地 compose 已迁移与部署）
- 背景：定时报表（`Report`）此前只有「固定口径」——`mode=rows` 导出数据集全部列、`mode=aggregate` 导出单张分组表，用户既不能挑选明细列，也不能在报表里组合多个图表。P2.2 批次一的画布设计器解决了大屏投屏形态，批次二补的是**报表本身的设计能力**（数据集列 → 明细表 + 聚合组件 + 模板），并让「立即运行」与「定时投递」共用同一份设计。

## 决策

### D1 设计挂在 `Report.design`，空值即存量口径

`Report.design`（JSONField，默认 `{}`）承载设计：`{columns, table_limit, components}`。

- **空 design = 完全存量行为**：明细全列 + 单 sheet，xlsx 附件与邮件正文一字未变（存量报表、既有集成测试与 E2E 零影响）；
- 清空设计（`design: {}`）即回到存量口径，设计器「删掉全部组件 + 列全选」也是同一效果；
- 调度字段（frequency/send_time/cron/recipients/notify_channels）与设计解耦：设计只管「报表长什么样」，调度只管「什么时候发给谁」。

### D2 表格即「明细本体」，不做成组件

设计里的图表组件只有 4 类（`number` / `bar` / `line` / `pie`），**表格不是组件**而是 `columns` + `table_limit`：

- 明细表是报表的必然产物（xlsx 首 sheet + 邮件附件的行数口径都指向它），做成可增删的组件会引出「0 个表格组件时导出什么」这类空洞状态；
- `columns` 同时是**导出口径**（`design_export_columns`）：投递时按它裁剪 xlsx 列，与投递侧「字段权限裁剪」叠加（先按设计列裁剪，再按浏览者字段白名单裁剪）。

### D3 校验与渲染同源，服务端仍是唯一事实源

- `dataset/utils/report_design.py` 负责归一化 + 校验：列必须命中数据集 `columns`（保序去重）、行数上限 10~500、组件 ≤ 12 且 id 唯一、图表类必须给 `group_by`、`sum`/`avg` 必须给数值列 `value_field`（数值列由 `numeric_columns_of` 判定）、`span ∈ {12, 6}`、未声明键丢弃；
- 序列化器在对象级 `validate()` 里调用（需要合并后的 dataset），**非法设计 400 且不落库**；
- 读侧函数一律宽容（`design_export_columns` / `design_table_limit` / `design_components`）：数据集列后续被删改名、字段权限收紧都不阻断投递，逐项静默跳过。

### D4 投递渲染：组件各落一张独立 sheet，单组件失败 fail-soft

- 明细（首 sheet）：`mode=aggregate` 沿用存量单表；`mode=rows` 按设计列裁剪并截断到 `table_limit`；
- 每个聚合组件 → 一张独立 sheet（`{序号}-{标题}`，非法字符替换、31 字符内），表头「名称 / 值」；
- **单个组件失败（字段被删、字段权限收紧）只写一行「图表数据不可用」并记日志**：投递可用性优先于单个图表，不让一份报表因一张图整体失败；
- 邮件正文追加一行组件清单（`Designed charts: …`）——正文仍是纯文本，图表数据在附件 sheet 内（HTML 邮件模板另行立项）。

### D5 前端复用一期图表卡，设计器只做「列 + 组件 + 属性」

- 组件字段与看板卡片同源（`dataset + chart_type + group_by/metric/date_trunc/value_field`），因此 `componentToCard()` 一次映射即可复用 `ChartCard`（主题、懒加载、错误重试、导出内核零重复实现）；
- 设计器为独立隐藏路由 `/analysis/report/designer?pk=`（与大屏设计器同族），列表行入口「设计报表」（`partialUpdate:DataReport`）；
- 三栏：左（模板 + 明细列勾选 + 行数上限 + 组件库）/ 中（明细表实时预览 + 组件网格）/ 右（选中组件属性）；
- **模板** = 一套现成的「列 + 组件」骨架（明细表 / 分组统计 / 趋势看板），套用即写入设计、之后可自由改；趋势模板优先用数据集 `config.date_field` 做按天折线，无日期字段或无数值列时自动退化（不产出必然被服务端拒绝的设计）；
- 明细表预览复用数据集执行接口（服务端已按字段权限裁剪输出列），面板里选了但无权限的列静默跳过——与投递侧列裁剪口径一致。

## 验证

- 后端：设计归一化 22 例（列过滤/上限/组件类型/指标与数值列/时间粒度/重复 id/数量上限/读侧宽容）+ API 11 例（写入、清空回存量、未声明键被丢、五类非法 400、非法更新不落库、列表与详情）+ 投递渲染 6 例（存量单表、列裁剪保序、行数截断、组件 sheet、aggregate 模式并存、单组件失败 fail-soft）；
- 顺手修复：`ws.append([_("Name"), ...])` 传 gettext_lazy 代理给 openpyxl 会抛 `Cannot convert '名称' to Excel`（存量 aggregate 分支潜伏缺陷，实现与测试双侧改为显式 `str()`）；
- 前端：设计纯函数 14 例（列口径/卡片映射/收敛/模板）；
- E2E（双浏览器）：API 建数据集与报表 → 设计器套用分组统计模板（2 组件 + 列收窄）→ 加指标卡并改标题 → 保存 → 读接口校验 design 落库 → 刷新数据；同批回归大屏设计器与数据分析主链路。

## 边界

- 不做报表内的自由布局（组件按 12 列栅格顺序流式排布，无拖拽定位）、不做组件级样式（配色/图例）配置；
- 不做 HTML 邮件正文（正文仍为纯文本 + 组件清单）与报表内嵌图片（图表以 xlsx sheet 数据形式投递）；
- 不做报表订阅的收件人分组、审批式发布；数据集级别的过滤/排序沿用数据集自身配置，设计器不覆盖。
