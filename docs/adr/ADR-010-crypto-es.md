# ADR-010：前端加密库停留 crypto-es（crypto-js 弃用处置决策）

- 状态：已接受
- 日期：2026-09-08（决策）/ 2026-09-11（登记 ADR）
- 关联：技术债台账 TD-28；N3 五期 F5「依赖与供应链」复查项

## 背景

`crypto-js` 自 2023-10 起停止维护（npm 弃用标记，无 CVE），且参与登录链路
（密码 AES 加密传输）。审计产物（`pnpm audit`）对弃用库无告警，但停维护库
参与安全链路本身是需要显式决策的风险，不能靠「没有 CVE」默认放行。

## 决策

1. **替换为社区维护的 fork `crypto-es`（^3.1.3）**——已于 2026-09-08 完成：
   - API 兼容（AES + OpenSSL `Salted__` 格式），`src/utils/aes.ts` 单点替换；
   - 线上协议 `AESCipherV2` 不变，登录/注册/重置全链路回归通过（TD-28）。
2. **协议版本化（`v2:` 前缀 WebCrypto PBKDF2+AES-GCM）列为可选增强**，不在本期实施：
   涉及 8 个调用点 async 化 + 5 条链路回归，收益是纵深防御而非修复缺陷；
   待 N4 窗口与其它传输层加固一起评审。
3. 供应链纪律：`pnpm audit` / `pip-audit` 高危清零维持门禁；弃用（deprecated）
   直接依赖升级时必须复核维护度（renovate 配置已禁 unstable）。

## 后果

- 正面：安全链路回到有维护的库；协议不变，无迁移成本。
- 负面：`crypto-es` 为单维护者 fork，若停更需重新评估（登记于供应链复查清单）。
- 中性：WebCrypto 双格式过渡保留为可选增强，不构成债务。
