# ADR-056：数据权限配置页重构与生效范围归一

- 状态：**已实施（2026-09-24）**
- 日期：2026-09-24
- 关联：[ADR-020](ADR-020-dataset-dashboard-phase1.md)（数据集行级数据权限 fail-closed）、[ADR-012](ADR-012-approval-flow-engine.md)（审批流与数据权限）、
  `docs/architecture/data-permission.md`（现状口径）、`common/core/data_scope/`（规则编译器）

## 一、背景

数据权限的读取侧（`common/core/filter.py::get_filter_queryset` + `common/core/data_scope/`）已经过一轮重构：
四段管线（validate → resolve → compile → combine）、三值布尔代数、写读双侧 fail-closed、用户/部门试算与
授权来源诊断均已就位。**配置侧**仍停留在旧形态：

1. 新增/编辑是「弹窗里嵌一张规则表格，规则再开一个子弹窗」，规则编辑是线性堆叠的表单（属性名级联 +
   预设按钮 + 匹配 + 排除 + 类型 + 值），层级深、字段语义弱，看不到规则的可读含义；
2. 生效范围（菜单绑定）在界面上以级联多选呈现，**选「页面菜单」的授权在运行时永不命中**——菜单上下文
   （`request.user.menu`）恒为请求命中的接口权限点菜单，页面/目录菜单 pk 不会出现在比对中；配置端与运行时
   口径不一致，且列表看不到「这条授权绑了哪些接口、分配给了谁」；
3. 规则类型的值控件形态（文本/时间/选人/选部门…）在前端硬编码映射，新增规则类型要前后端两处改；
4. 四类取值方式（`value.text`/`value.json`/`value.date`/`value.dept.ids`）在 choices 接口里被标为 disabled，
   能力实际不可用；
5. 「同一用户命中多条授权时如何合并」这一优先级语义只存在于后端实现与文档，配置界面没有任何提示。

## 二、决策

| # | 决策 | 要点 |
|---|------|------|
| 1 | 新增/编辑改为**右侧抽屉**，规则行内编辑 | 复用 RePlusPage 的 `props.mode: "drawer"`；规则列表 → 行内展开编辑卡片，取消「弹窗套弹窗」 |
| 2 | 规则列表展示**可读摘要** | 「包含 创建人 目标用户本人」这类自然语言摘要（前端纯函数 `ruleSummary`），方向/字段/匹配/取值一次可读 |
| 3 | 值控件形态**后端下发** | `rule_meta.RULE_TYPE_META`（input / value_required / default_match / group）+ choices 接口下发（含 `matches` 匹配符文案）；前端只保留兜底映射，新增规则类型只改后端 |
| 4 | 生效范围**归一为接口权限点** | 保存时把页面/目录菜单展开为其下全部接口权限点（`serializers/permission.py::expand_menu_scope`）；展开为空则拒绝保存，避免范围被意外放大成「通用」 |
| 5 | 列表带出**规则数 / 接口数 / 分配对象数** | 列表 action 注解计数（`Count(..., distinct=True)`）零额外查询；序列化器 `rule_count/menu_count/user_count/dept_count` |
| 6 | 「全部数据」等四类取值方式**放开** | choices 不再下发 disabled；值控件按 input 形态渲染（相对时间改为「过去/未来 N 分钟/小时/天」的可读输入） |
| 7 | **不引入显式优先级排序**，改为在界面显式说明 | 合并语义维持「授权池内并集取最宽」，见 §三；引入优先级排序或「按序取首个命中」等于改变运行时语义，会影响既有部署，登记为评估出口 |
| 8 | 巡检命令补一类 `[WARN]` | 存量数据里绑定了页面/目录菜单的授权，运行时不会命中，提示重新保存以归一 |
| 9 | 「全部数据」不做字段坍缩 | 过滤对象用**应用 / 模型 / 字段级联**（与旧版一致），取值方式切到「全部数据」时该控件与匹配条件**保留为只读**（路径锁到 `* / *`）并给出提示，不整块隐藏——隐藏会被读成「配置丢了」 |

## 三、语义口径（配置端与运行时同源）

| 概念 | 口径 |
|------|------|
| 规则配置 | 一条规则 = 过滤对象（应用 / 模型 / 字段级联，落到 `表.字段`；`*` 表示跨模型通用字段）+ 取值方式（type）+ 匹配条件（match）+ 取值（value）+ 方向（包含/排除） |
| 匹配逻辑 | match 白名单 = 字段 class lookups ∪ 框架自定义（`m2m`/`m2m_all`/`ip_in`/`all`）；取值方式为「运行期注入」或「指定对象」时由读取侧固定 match（in/exact），写入侧与编译侧共用同一集合 |
| 生效范围 | 授权可绑定若干**接口权限点**（页面/目录在保存时展开）；未绑定时对所有接口生效；绑定时仅对 `request.user.menu` 命中的接口生效（导入导出回退到 list/create 权限点） |
| 分配对象 | 授权通过 `UserInfo.rules` / `DeptInfo.rules` 分配给用户或部门（部门含其下级成员，仅启用部门） |
| 优先级 | 单个授权内多规则按该授权的且/或模式组合（且模式下「全部数据」是单位元被忽略，或模式下支配整组）；**多个授权之间为并集（取最宽结果）**——授权只用于放宽范围，不能用授权收紧其他授权；无任何适用授权即空集（fail-closed）；超管豁免 |

## 四、影响与边界

- **行为变化**：此前「绑定页面菜单」的授权不生效，归一后重新保存即按该页面下全部接口生效；这是修复而非语义改变
  （存量数据由巡检 `[WARN]` 提示，不自动改写存储）。
- 归一后的存储是接口权限点集合，页面级授权在列表上以「N 个接口」展示；勾选页面 = 勾选其下全部接口。
- 仍不支持「针对某接口收紧可见范围」：授权是放宽语义，配置页只提供说明与试算诊断，不改变合并方式。
- `table="*"` 的规则按既有口径跳过字段存在性与 match 合法性校验（跨模型通用字段无法静态校验），
  写入侧仍做类型/取值形态校验，读侧 bad case fail-closed 并告警。
- 值控件元数据由后端下发，前端兜底映射保留以兼容旧后端；新增规则类型时前端零改动（除非引入新的控件形态）。

## 五、验证

- 后端：`tests/unit/system/test_data_permission_scope.py`（类型元数据覆盖、页面展开、空展开拒绝、注解计数、
  字段形态元数据、choices/lookups 下发）；全量 pytest 与 ruff。
- 前端：`ruleValue.spec.ts` / `ruleSummary.spec.ts` / `menuScope.spec.ts`（值归一、摘要、范围展开与统计）；
  typecheck / strict / eslint / prettier / stylelint / i18n 门禁。
- E2E：`e2e/data-permission.e2e.ts`（抽屉内行内配置规则 → 摘要 → 试算 → 保存 → 列表生效范围 → 编辑回显，双浏览器）；
  `e2e/preview.e2e.ts` 的配置页试算用例同步改为抽屉口径。
