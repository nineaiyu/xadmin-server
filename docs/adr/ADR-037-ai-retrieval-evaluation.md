# ADR-037：AI 检索升级评估（评测驱动；结论：暂不引入向量，维护开条件）

- 状态：已接受（结论：**不引入向量检索**，词频重叠检索维持；登记评估出口）
- 日期：2026-09-14
- 关联：下一年度规划建议 §四.A1（W1–W2）；[ADR-023](ADR-023-ai-assistant-phase1.md)（AI 一期：词频检索 + 向量升级候选池）；
  [ADR-033](ADR-033-knowledge-base-management.md)（知识库文档管理）；
  `system/utils/ai.py::retrieve`；`tests/data/ai_retrieval_eval.json`、
  `tests/integration/system/test_ai_retrieval_eval.py`

## 背景

AI 一期采用零依赖「词频重叠评分」检索（CJK 二元组 + ASCII 词 + 标题加成，`retrieve` 全量扫描
`AiKnowledgeChunk`），向量嵌入升级登记为候选池。A1 的启动口径是**评测驱动**：

1. 先建**检索评测集**（20–30 问 + 期望出处，入 CI）；
2. 实测 hit@5；
3. **门控**：hit@5 < 75% **或**分块数 > 500 才升级；
4. 选型顺序：OpenAI 兼容 embedding API + Python 侧余弦（<1 万块够用、**不动部署**）→ 语料超 1 万块再评估
   pgvector（部署变更，需 ADR）。

## 评测方法（已入 CI）

| 项 | 口径 |
|----|------|
| 语料 | 仓库文档（`_iter_doc_files`：`docs/**.md` + 根 README/CONTRIBUTING），与生产知识库同源；69 个 md / 1.1 MB |
| 评测集 | `tests/data/ai_retrieval_eval.json`：**36 问**（覆盖 ADR/架构/运维/规划四类，含 6 条改写式「难题」）+ 期望出处 |
| 判定 | `retrieve(question, top_k=5)` 的 top-5 中出现任一期望出处即 hit；聚合 hit@5 |
| 门禁 | hit@5 ≥ 75%（低于阈值按规划升级向量）；另有「期望出处必须存在于当前语料」的守护用例（防文档改名导致评测静默失真）与单次检索耗时护栏 |
| 运行 | `pytest tests/integration/system/test_ai_retrieval_eval.py`（随全量套件入 CI，无需外部服务） |

## 实测结果（2026-09-14）

| 指标 | 实测 | 门控线 | 判定 |
|------|------|--------|------|
| **hit@5** | **35/36 = 97.2%** | < 75% 才升级 | 远高于阈值，质量充分 |
| 分块数 | 535 | > 500 才升级 | 略超（+7%），见下 |
| 单次检索耗时 | 平均 30.3ms / 最差 31.6ms（36 问实测） | — | 全量扫描成本在预算内 |
| 唯一未命中 | `hard-field-hidden`（「看不到某一列」→ 命中 `permission.md`/`data-permission.md` 等语义近邻，非期望的 `field-permission.md`） | — | 语义近邻命中，非事实性错误 |

## 决策：暂不引入向量检索

理由（数据支撑）：

1. **质量不缺**：hit@5 97.2% 远超 75% 门控；唯一 miss 落在语义近邻文档上，引入 embedding 的边际收益
   无法用现有数据证明；
2. **规模未到**：535 块仅比触发线高 7%，且 500 线的原始含义是约束「Python 侧全量扫描/余弦」的成本；
   实测 30ms/次的检索成本与语料规模都在预算内；
3. **复杂度与风险**（对应规划 R3）：embedding 会引入新的外部依赖（API 成本、网络可用性、数据出境/隐私评审）
   与召回链路双实现（词频 + 向量 RRF），而当前权限口径（fail-closed）虽不受影响，维护面仍显著增加；
4. **部署零变更是可保持的优势**：维持现状即维持「不新增部署面」的边界。

## 评估出口（任一满足即重新评估）

1. hit@5 跌破 75%（CI 门禁会直接失败，触发评估）；
2. 分块数 **> 1000**（本轮 535；知识库大幅扩容后重估）；
3. 检索耗时 P95 **> 300ms**（评测脚本记录的 avg/worst 出现数量级退化）；
4. 出现明确的「语义检索」需求（如同义改写命中率成为产品指标），或接入方可提供 embedding 服务。

## 若将来升级（预研要点）

- 选型：OpenAI 兼容 embedding API（复用档案 `base_url`/`api_key`，新增 embedding 模型配置项）+ Python 侧余弦；
  **语料超 1 万块**再评估 pgvector（部署变更，须另立 ADR）；
- 混合检索：词频 + 向量 **RRF** 融合，保持 `retrieve` 返回结构不变（消费方零改动）；
- 权限口径：检索面仍为知识库分块（不含业务数据），fail-closed 语义不变；
- 评测先行：先在现有 36 问评测集上跑出 embedding 的 hit@5 再决策落地，避免「无数据替换」。
