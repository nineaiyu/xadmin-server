# ADR-100：第二轮审查保留项处置决策（iframe / 限流 / IM 出站 / 颜色基线 / 报表脱敏投递）

- 状态：**已接受**
- 日期：2026-10-30
- 关联：[permission.md](../architecture/permission.md)、[缓存策略](../architecture/cache.md)、
  [ADR-099](ADR-099-http-only-refresh-token.md)

## 一、背景

第二轮全栈 / 前端审查在正式 P0/P1/P2 之外，登记了若干候选池与设计取舍项。
它们不是未修复的缺陷，而是「当前实现有明确信任边界或治理机制」的决策点。
本 ADR 集中记录统一处置，避免后续窗口重复立项，也避免把「保留」误读为遗漏。

涉及项：

1. SafeFrame iframe sandbox 同源组合（池-F5 / SEC-FE-02）；
2. 限流缓存故障 fail-open（池-B4）；
3. IM SDK 以裸 `requests` 访问硬编码官方域名（池-B8 / INT-C-01）；
4. 颜色字面量与验证码族贴线组件基线（池-F6 / 池-F7 / 池-07 / 池-08）；
5. 报表「脱敏后投递」开关（E-1，随 DS-P0-01 根治产生）。

## 二、决策

| # | 项 | 决策 | 理由与边界 |
|---|----|------|-----------|
| 1 | iframe sandbox | **维持** `allow-scripts allow-same-origin` 组合；仅当 `frameSrc` 来源升级为低权可配时收紧 | 当前 `frameSrc` 由超管菜单配置，属可信源；同源+脚本可自移除 sandbox 是信任边界内的已知属性。低权可配时改为按源白名单，并对同源内部页去掉 `allow-same-origin` 或改服务端代理 |
| 2 | 限流 fail-open | **维持** 缓存故障时放行（fail-open） | 限流是加固而非鉴权；缓存/Redis 故障时 fail-closed 会把全站登录/导出/AI 一起拒绝，可用性代价高于限流失效。口径已写入加固面文档，监控按回源率观察 |
| 3 | IM SDK 出站 | **维持** 直连各家官方硬编码域名；不引入 `pinned_request` | 域名固定、无用户可控 URL，无 SSRF 面；引入 DNS pinning 会破坏代理/测试桩与三家 SDK 的差异。若未来支持自定义网关/代理，必须迁移到 `pinned_request` 并补出口守卫测试 |
| 4 | 颜色字面量 / 贴线组件 | **维持** 基线只减不增；不做一次性清理/拆分 | 16 文件 94 处均为图表、色板、二维码白底、EP 兜底等运行期无法消费 CSS 变量的场景，已逐条登记；`check:color-literals` 已扩展拦截 Tailwind 调色板类，新增业务代码不得进入基线。贴线组件改动前先拆分，不预防性重写 |
| 5 | 报表脱敏投递 | **暂不作为产品功能实现**；当前按报表创建者角色套用 DataMaskRule | 数据集/报表取数链已套用与列表同源的掩码；超管按既有豁免口径可创建原文报表。若合规要求「报表外发一律脱敏」，再增加 `mask_delivery` 开关，默认对非超管脱敏、超管显式选择；该字段涉及模型/迁移/前端表单，单独立项 |

## 三、触发条件（命中后重评本 ADR 对应行）

- iframe：菜单/大屏开放低权角色配置 `frameSrc`，或出现同源 iframe 安全事件。
- 限流：缓存故障窗口出现可观测的滥用/暴力破解，或限流从「加固」升级为「鉴权前置」。
- IM SDK：支持自定义网关/代理/私有化端点，或三家 SDK 统一到自研 HTTP 客户端。
- 颜色/组件基线：某文件因业务改动触碰基线内颜色，或贴线组件新增功能导致超 500 行。
- 报表投递：合规要求外发文件不得含原文，或出现报表收件人越权投诉。

## 四、后果

- 保留项有明确的责任边界与重开条件，不再作为「待办债」反复出现在审查清单；
- 安全侧仍保留两层兜底：副作用 GET AST 门禁（Cookie 通道）与 XSS 净化/CSP 防线；
- 任何一项触发时按「先修订本 ADR / 独立立项」处理，不在普通业务改动中顺手改。
