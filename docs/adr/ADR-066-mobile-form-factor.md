# ADR-066：移动端形态评估与响应式守护（P2.6）

- 日期：2026-09-27
- 状态：**已交付**（mobile E2E 1 例 chromium（webkit 按设计跳过）+ 相关回归 34 例双浏览器（user-panel / split-pane / table-column-align）+ 6 个核心页 iPhone 13 视口实测截图核验；client typecheck / eslint / prettier / stylelint / vitest / i18n / 行数门禁全绿）
- 背景：§7 P2.6 登记为「移动端/APP：无——视目标用户群」。本批以**实测**（iPhone 13 视口 390×664、UA 命中移动判定）核验现有响应式能力，并据此决定路线：维持「响应式优先」，还是投独立 APP / uni-app。

## 实测结论（证据）

移动形态由 `@pureadmin/utils` 的 `deviceDetection()` 触发，**判定依据是 UA**（`midp` / `ucweb` / `android` / `iphone os` / `windows ce` / `rv:1.2.3.4` / `windows mobile`）。命中后：

| 面 | 实测结果 |
|---|---|
| 布局壳 | 侧栏变抽屉：`.app-mask` 遮罩 + `mobile.openSidebar`，汉堡开合正常（截图核验） |
| 页面分支 | 用户管理改成「部门树在上、用户列表在下」堆叠；账户设置左侧导航收成汉堡弹层；弹窗按 `fullscreen: deviceDetection()` 全屏化 |
| 表格与搜索 | 表格在容器内横向滚动，**6 个核心页页面级横向溢出 = 0**（`documentElement.scrollWidth == innerWidth`） |
| 核心页 | 登录 / 首页 / 用户管理 / 账户设置 / 我的填报 / 聊天室 / 仪表盘 / 消息中心 均可读可操作（截图核验） |
| **缺陷 1 处** | 用户管理堆叠布局里，部门树沿用桌面铺满口径（`minHeight: calc(100vh - 141px)` + 滚动区 `calc(90vh - 108px)`）→ 390×664 下**树占满视口、用户列表被推到整屏之外**（只有滚动到底才能看到） |

缺陷修复：`UserTree` 新增 `compact` 形态（堆叠=高度自适应 + 滚动区 `min(32vh, 260px)`），用户管理移动分支传 `compact`。实测用户列表工具栏从整屏之外（table top 588）回到首屏（534，视口 664），且树内容仍可滚动查看。

## 决策

### D1 维持「响应式优先」，不投独立 APP / uni-app

现有 UA 分支 + 响应式已覆盖核心页的可读可操作；独立端的成本面（工程链与发版、登录与推送通道、包体积、与二开能力的长期同步）远大于当前收益。

**重开条件（任一命中即重新评估移动端形态）**：

1. 目标用户群以移动端为主，且业务需要原生能力（推送、离线、扫码、相机、定位）；
2. 需要应用商店 / 企业内部分发（应用市场合规、签名与灰度发布）；
3. 移动端访问占比连续两个季度 > 40% 且移动形态反馈集中在交互层。

### D2 移动形态入 CI 守护（`e2e/mobile.e2e.ts`，仅 chromium）

三条守护：核心页**零页面级横向溢出**（6 页）、侧栏抽屉**开合坐标**（关：`x < 0`；开：`x ≥ 0`；遮罩收起）、用户管理**堆叠布局不遮挡列表**（树高 < 视口一半、表格进入首屏）。移动判定与浏览器无关（UA + CSS），故只跑 chromium 控成本。

### D3 已登记边界：`deviceDetection()` 是 UA 判定

**窄窗口桌面浏览器**与 **iPad（桌面 UA）** 不会进入移动形态，会看到桌面双栏/宽表格布局。若需覆盖「窄视口」，需把判定升级为「UA ∨ 视口宽度 ≤ 阈值」，并同步布局 store 的 `device` 语义（`src/store/modules/app.ts`）与所有 `deviceDetection()` 调用点——跨布局改动，登记为后续项；触发条件＝出现窄窗口/iPad 使用反馈。

### D4 不做项

不下沉 PWA（离线缓存与安装引导）、不做移动端专属导航结构（底部 tabbar）、不做手势交互（左右滑返回）、不做表单设计器/大屏设计器/报表设计器的移动端专项设计——这些页在移动端按「水平滚动 + 全屏弹窗」降级使用。

## 验证

- `e2e/mobile.e2e.ts`（iPhone 13 视口）：1 例通过（chromium），webkit 按设计 skip；
- 回归：`user-panel`（3 例）+ `split-pane`（8 例）+ `table-column-align`（12 例）× 双浏览器 = 34 例通过——确认 `UserTree` 的 `compact` 形态未影响桌面分栏路径；
- 手工核验：6 个核心页 + 登录页截图（390×664）逐页确认布局、抽屉与表格滚动。

## 边界

- 未做**真机测试**（浏览器模拟视口 + UA 模拟）；真机差异（iOS 安全区、软键盘顶起、Safari 视口高度抖动）未覆盖；
- 未覆盖全部页面（重点核验核心页；桌面专用设计器按降级使用口径接受）；
- 移动端交互未做可用性度量（点击目标尺寸、滚动性能），如需按 WCAG 移动口径审计另立专项。
